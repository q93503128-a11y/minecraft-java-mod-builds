# Augmentation Survival — Augment Canon Correction

Date: 2026-10-27
Status: **CURRENT CANON CORRECTION**

이 문서는 `AUGMENTS.md`의 2026-10-25 버전에 남은 **Section 9 `아직 미확정 / 보류`를 교정**한다.

## 1. 승인 규칙 교정

사용자가 이미 반복해서 정한 규칙은 다음과 같다.

- 신규 증강 후보는 사용자가 명시적으로 `폐기`, `보류`, `나중에`, `빼기` 등으로 제외하지 않은 한 **통과/확정**으로 취급한다.
- 별도의 `확정` 문장을 다시 받지 못했다는 이유만으로 보류시키지 않는다.
- 따라서 과거 제안 이력의 `별도 확정 지시가 없어 보류 유지`, `이번 수정에서는 확정하지 않고 보류 유지` 같은 기록은 사용자의 실제 승인 규칙과 충돌한 **정리 오류**다.
- `AUGMENTS.md` Section 8의 명시적 `폐기 / 대체 완료`만 폐기 정본으로 유지한다.
- 과거 Section 9 항목은 아래와 같이 모두 **확정 후보군**으로 복구한다. 각 항목의 등급/최대 레벨/수치/상호작용은 `AUGMENT_PROPOSAL_HISTORY.md`와 이후 사용자 수정 지시 중 가장 최신 값을 따른다.
- **설계상 확정과 runtime 구현 완료는 구분한다.** 구현되지 않은 증강을 실제 코어 뽑기 풀에 먼저 노출하지 않는다. 후보 풀 진입은 해당 증강의 gameplay runtime과 필요한 서버 검증이 완료된 뒤 진행한다.

## 3. `동료 구조` 의미 교정

과거 문서의 `동료`를 길들인 동물/지배 몹으로 적은 것은 사용자가 의도한 의미와 달랐다.

### 정본

- 이름: `동료 구조`
- 등급: 영웅
- 최대 Lv: 1
- **플레이어 전용 멀티플레이 증강**이다. 길들인 동물/지배 몹용 증강이 아니다.
- 서버에 실제 플레이어가 **2명 이상 접속 중일 때만 코어 후보 풀에 등장**할 수 있다.
- 보유자가 치명적인 피해를 받고 기존 상위 사망 방지 효과가 모두 실패하면 즉시 사망하지 않고 **10초간 쓰러짐(Downed)** 상태가 된다.
- 쓰러진 플레이어는 이동, 공격, 채굴, 설치, 아이템 사용, 액티브 사용을 할 수 없다.
- 다른 살아 있는 플레이어가 가까이에서 **2초 연속 구조 상호작용**을 완료하면 최대체력의 **30%**로 일어난다.
- 구조 성공 후 해당 플레이어에게 **300초 재사용 대기시간**을 적용한다.
- 서버 접속 인원이 1명뿐일 때는 이 증강이 치명타를 쓰러짐으로 바꾸지 않는다. 구조할 사람이 없는 상태에서 플레이어를 10초간 묶어 두지 않는다.
- 쓰러짐 판정, 구조 대상, 거리, 시간, 부활 체력, 쿨다운은 모두 서버 권한이다.
- `소생 (액티브)`은 길들인/지배 영구 동료의 실제 사망 후 복구 능력으로 유지하며 `동료 구조`와 역할이 다르다.
- 연출은 단순 HUD 팝업으로 대체하지 않는다. 실제 쓰러짐 자세/행동불가 상태와 구조 진행이 월드에서 읽혀야 한다.

### 사망 방지 우선순위

기존 사망 방지 계약을 보존한다. `동료 구조`는 다른 사망 방지 수단을 빼앗지 않는 **마지막 멀티 구조 안전망**으로 처리한다.

예: `한 번 버티기` / 바닐라 손 토템 / `비상 토템` / `재림` 등 실제로 먼저 성공한 사망 방지가 있으면 Downed로 들어가지 않는다.

## 4. `비행` 정본 교정 — Superman-style powered flight

과거 `Survival Creative식 자유 비행` 설계는 폐기한다. **증강 자체는 유지하되 비행 방식만 교정**한다.

- 이름: `비행`
- 등급: 신화
- 최대 Lv: 1
- 별도 자원 소모, 지속시간, 재사용 대기시간은 두지 않는 기존 방향을 유지한다.
- 전용 configurable key로 비행 상태를 켜고 끈다.
- Creative flight처럼 입력을 놓는 즉시 공중에서 정지하는 방식이 아니다.
- 기본 감각은 **슈퍼히어로/Superman식 추진 비행**이다.

### 이동 상태

1. **TAKEOFF**
   - 지상 발동 시 짧은 상승 추진과 함께 비행 자세로 전환한다.
   - 단순 `mayfly=true` 전환이 아니라 실제 발진 순간을 보여준다.

2. **HOVER**
   - 정밀 위치 조정용 저속 상태.
   - 시선/입력에 따라 부드럽게 움직이고, 입력을 놓으면 짧은 감속 후 정지한다.
   - 건축용 Creative flight처럼 딱딱한 즉시 정지는 피한다.

3. **CRUISE**
   - 전진 입력 시 **시선 방향으로 가속**한다.
   - 상승/하강도 카메라 pitch를 따라 자연스럽게 연결한다.
   - 방향 전환 시 몸이 선회 방향으로 기울고 속도 벡터가 즉시 90도 꺾이지 않는다.

4. **BOOST**
   - 질주 입력을 유지하면 고속 추진으로 전환한다.
   - 속도는 순간 점프가 아니라 짧게 램프업한다.
   - 고속일수록 선회 반경이 커지고 감속에도 시간이 필요하다.

### 1차 튜닝 기준

실제 플레이테스트 전의 시작값이며 고정값이 아니다.

- Hover 목표 속도: 약 `0.35~0.45 block/tick`
- Cruise 목표 속도: 약 `1.0~1.4 block/tick`
- Boost 상한: 약 `2.0~2.4 block/tick`
- 서버가 최종 속도/충돌/위치를 결정한다.
- 고속 비행으로 벽을 통과하거나 충돌 검사를 생략하지 않는다.
- 지나치게 높은 속도로 chunk loading과 멀티플레이 안정성을 망가뜨리지 않는다.

### 연출 계약

- Player Animation Library를 사용해 최소한 `takeoff`, `hover`, `cruise`, `boost`, `brake/landing` 상태가 서로 다른 자세를 가진다.
- Cruise/Boost에서는 몸통을 전방으로 눕히고 팔/다리를 추진 비행에 맞춰 정렬해 **실제로 날아가는 실루엣**을 만든다.
- 속도에 따라 FOV를 점진적으로 넓히되 과도한 멀미 유발은 피한다.
- Boost 진입 시 짧은 풍압/저역 충격음을 사용하고, 고속 유지 중에는 지속적인 바람 소리를 사용한다.
- 고속에서만 절제된 후류/공기 흐름 VFX를 사용한다. 항상 파티클을 뿌리는 방식은 피한다.
- 카메라 흔들림은 Boost 진입/고속 구간에만 약하게 사용하고 옵션으로 끌 수 있게 한다.
- A/D 선회 시 3인칭 모델의 bank/lean을 적용한다.
- 착지/비행 종료 시 즉시 뚝 떨어뜨리지 않고 짧게 감속·자세 복귀를 거친다.
- 공통 HUD 배너를 비행감의 핵심 피드백으로 사용하지 않는다. 상태는 움직임, 애니메이션, 음향, 카메라, VFX로 읽혀야 한다.

### 외부 사례 참고 경계

- `Viltrumite Flight`: HOVER / CRUISE / SONIC에 가까운 단계 구분, 고속 비행 애니메이션·사운드·카메라 피드백을 **reference**로 삼는다.
- `Dynamic Flight Control`: 시선 기반 3D 이동, 관성/감속의 조작감을 **reference**로 삼는다.
- 외부 모드의 코드/자산을 허가 없이 복사하거나 번들하지 않는다. 필요한 동작은 우리 서버 권한 구조와 현재 Player Animation Library 위에서 직접 구현한다.

- CANON APPROVED: YES — 위 Section 2 전체
- `동료 구조` 의미 교정: CANON APPROVED

- 기존 147-entry runtime catalog: 이 문서 작성 시점의 실제 구현 기준선이며 별도로 유지
- 새로 복구된 항목들의 runtime 구현: 항목별로 아직 검증 필요
- PLAYTESTED: NO
- MULTIPLAYER TESTED: NO
