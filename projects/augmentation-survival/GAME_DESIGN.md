# Augmentation Survival — Game Design Canon

> 작업명 기준 문서. 정식 명칭은 미정이다.

## 1. 한 줄 정의

Minecraft 장기 서바이벌을 그대로 살리면서, 여러 경로로 증강 코어를 모으고 증강을 계속 쌓아 전투·채광·이동·탐험·생존·생산 전반에서 플레이어가 과감하게 강해지는 파워 판타지 모드.

## 2. 핵심 디자인 원칙

### 2.1 증강은 이 게임의 주인공이다

증강은 보조 옵션이 아니라 플레이 방식 자체를 바꾸는 중심 성장 시스템이다.

- 단순 `공격력 +5%`만 반복하지 않는다.
- 낮은 등급도 충분히 쓸 만해야 한다.
- 높은 등급일수록 더 큰 규칙 변화와 강한 체감을 허용한다.
- 강해지는 재미를 과하게 억제하지 않는다. 이 프로젝트는 의도적으로 강한 파워 판타지를 지향한다.

### 2.2 전투 전용 모드로 만들지 않는다

Minecraft는 장기 서바이벌 게임이므로 증강 역시 여러 플레이 축을 강화해야 한다.

현재 고려하는 축:

- 전투
- 채광 / 자원 수집
- 이동
- 탐험
- 생존
- 농사 / 목축
- 낚시
- 건축 및 작업 편의

각 축의 실제 증강 목록은 별도 콘텐츠 설계 단계에서 확정한다.

### 2.3 장기 월드에 맞는 랜덤성

한 판이 짧은 로그라이크와 달리 Minecraft 월드는 수십~수백 시간 이어질 수 있다.

따라서 랜덤성은 다음 역할만 맡는다.

- 어떤 증강 후보를 만날지에 대한 기대감
- 예상하지 못한 조합 발견
- 같은 월드에서도 선택 순서가 달라지는 변화

반대로 다음은 피한다.

- 이미 완성한 증강이 반복해서 꽝으로 등장
- 특정 핵심 증강을 끝없이 못 얻는 구조
- 초반 운 하나가 장기 월드 전체를 망치는 구조

## 3. 증강 등급

현재 등급 체계:

1. 일반
2. 고급
3. 희귀
4. 영웅
5. 전설
6. 신화

등급별 실제 증강 수와 성능 차이는 아직 고정하지 않는다.

중요 원칙:

- 일반 증강도 실제로 쓸 만해야 한다.
- 상위 등급이 하위 등급의 단순 수치 상위호환만 되지 않게 한다.
- 고등급 증강을 엔더 드래곤 처치 이후에만 열지 않는다.
- 엔더 드래곤은 고등급 증강을 시험하고 활용할 대상이지, 신화 증강을 처음 허용하는 절대 관문이 아니다.

## 4. 증강 코어와 뽑기

### 4.1 등급별 코어

각 등급마다 대응하는 증강 코어가 존재한다.

예:

- 일반 증강 코어
- 고급 증강 코어
- 희귀 증강 코어
- 영웅 증강 코어
- 전설 증강 코어
- 신화 증강 코어

### 4.2 기본 뽑기 규칙

1. 플레이어가 증강 장치에 원하는 등급의 코어를 넣는다.
2. 그 코어와 같은 등급의 유효한 증강 후보 3개를 제시한다.
3. 플레이어가 1개를 선택한다.
4. 선택이 확정되면 코어를 소비하고 증강을 획득한다.

상위 등급 코어에서 하위 등급 증강이 섞여 나오는 구조는 현재 사용하지 않는다.

### 4.3 중복과 레벨

증강마다 `최대 레벨`을 개별적으로 가진다.

- 1회 획득형: 최대 레벨 1
- 레벨형: 최대 레벨 2, 3, 5 등 필요에 따라 지정

규칙:

- 이미 최대 레벨인 증강은 후보 풀에서 제거한다.
- 아직 레벨을 올릴 수 있는 증강은 다시 등장할 수 있다.
- 특정 등급의 모든 증강이 최대 레벨이면 해당 등급 코어로 더 이상 뽑을 수 없다.
- 이 경우 코어를 소비하지 않는다.

따라서 중복은 `꽝`이 아니라 의도된 레벨 성장에만 사용한다.

## 5. 제작

### 5.1 일반 증강 코어

현재 확정 레시피:

```text
R A R
A C A
R A R
```

- `R` = 레드스톤 가루
- `A` = 자수정 조각
- `C` = 구리 주괴
- 결과 = 일반 증강 코어 x1

한 번 제작할 때 하나만 나온다. 일반 증강 자체가 의미 있는 성장 선택이어야 하므로 대량 산출 레시피로 두지 않는다.

### 5.2 기본 증강 장치

증강 시스템은 너무 늦게 열리지 않아야 한다. 기본 장치는 철 시대 안에서 제작 가능하게 한다.

현재 확정 레시피:

```text
I C I
C F C
I C I
```

- `I` = 철 주괴
- `C` = 구리 주괴
- `F` = 화로
- 결과 = 증강 장치 x1

기본 증강 장치에는 레드스톤이나 자수정 조각을 요구하지 않는다. 초반 접근성을 막지 않기 위함이다.

기본 기능:

- 등급별 증강 코어 투입
- 같은 등급 증강 3개 제시
- 1개 선택 및 획득

### 5.3 강화 증강 장치

코어 합성은 기본 장치보다 한 단계 뒤에 열어도 된다.

현재 확정 레시피:

```text
I D I
G A G
I D I
```

- `I` = 철 주괴
- `D` = 다이아몬드
- `G` = 금 주괴
- `A` = 기본 증강 장치
- 결과 = 강화 증강 장치 x1

현재 재료 수:

- 철 주괴 4
- 다이아몬드 2
- 금 주괴 2
- 기본 증강 장치 1

강화 증강 장치는 기본 뽑기 기능을 유지하면서 코어 합성 기능을 추가한다.

## 6. 코어 합성

강화 증강 장치에서 다음 변환을 지원한다.

```text
일반 코어 x3 -> 고급 코어 x1
고급 코어 x3 -> 희귀 코어 x1
희귀 코어 x3 -> 영웅 코어 x1
영웅 코어 x3 -> 전설 코어 x1
전설 코어 x3 -> 신화 코어 x1
```

현재 원칙:

- 별도 촉매는 요구하지 않는다.
- 역분해는 현재 계획하지 않는다.
- 반복 클릭을 강요하지 않도록 다량 일괄 합성 UX를 지원하는 방향을 우선한다.
- 3:1 비율 자체의 최종 밸런스는 플레이테스트 단계에서 조정 가능하다.

## 7. 코어 획득 설계

### 7.1 가장 중요한 규칙: 장소는 등급 하나를 의미하지 않는다

`폐광 = 고급`, `고대 도시 = 전설`처럼 한 장소가 한 등급만 고정 지급하는 구조를 사용하지 않는다.

대신 각 콘텐츠는 `등급 분포`를 가진다.

예시:

- 폐광 상자: 일반~희귀 코어가 모두 등장 가능
- 더 위험한 구조물: 고급~영웅 또는 희귀~전설처럼 상위 쪽으로 분포 이동
- 최고난도 콘텐츠: 전설이 주력이고 신화도 낮은 확률로 등장 가능

정확한 확률은 아직 정하지 않는다.

### 7.2 낮은 등급도 여러 획득처를 가진다

코어는 제작만으로 얻지 않는다.

획득 경로 후보:

- 바닐라 구조물 상자
- 바닐라 몹 / 특수 몹 드랍
- 탐험 보상
- 특정 바이옴의 월드 콘텐츠
- 외부 모드 구조물 상자
- 외부 모드 몹 / 보스 드랍
- 외부 모드 바이옴에 배치한 별도 코어 관련 콘텐츠
- 코어 합성

### 7.3 고등급 접근 시점

증강이 이 모드의 핵심이므로 높은 등급을 지나치게 그림의 떡으로 만들지 않는다.

현재 진행 감각:

- 초반부터 일반뿐 아니라 고급, 운이 좋거나 위험을 감수하면 희귀도 볼 수 있다.
- 중반에는 희귀와 영웅을 실제로 노릴 수 있어야 한다.
- 전설과 신화도 엔더 드래곤 이후 전용으로 잠그지 않는다.
- 코어 합성을 적극적으로 사용한 플레이어는 직접 드랍보다 빠르게 상위 등급에 접근할 수 있다.

등급별 정확한 바닐라 획득처 표는 다음 설계 패스에서 확정한다.

## 8. 바닐라 loot와 연동

기존 Minecraft 콘텐츠를 버리지 않고 증강 성장 루프에 연결한다.

예:

- 폐광
- 던전
- 난파선
- 사막 피라미드
- 정글 사원
- 폐허 포탈
- 네더 요새
- 보루 잔해
- 우드랜드 맨션
- 고대 도시
- 레이드 / 보스 / 특수 몹

원칙:

- 기존 loot를 통째로 갈아엎지 않는다.
- 가능한 경우 기존 loot에 코어를 추가한다.
- 동일 장소에서 여러 등급이 나올 수 있게 한다.
- 위험도와 희소도가 높아질수록 분포가 상위 등급 쪽으로 이동한다.

## 9. 외부 모드와 공식 소형 모드팩

### 9.1 방향

이 프로젝트는 단독 모드로도 동작할 수 있어야 하지만, 외부 바이옴·구조물·몹·전투·QoL·성능 모드를 엄선한 공식 소형 모드팩 구성을 적극 검토한다.

목표는 `유명 모드 많이 넣기`가 아니다.

외부 모드는 다음 역할을 해야 한다.

- 증강으로 탐험할 공간 확장
- 증강으로 상대할 몹과 보스 확장
- 비전투 증강을 활용할 생존·탐험 콘텐츠 확장
- 전투/애니메이션/편의/성능의 품질 보완

### 9.2 외부 구조물 연동

외부 구조물의 loot table 또는 보상 시스템에 증강 코어를 섞을 수 있게 호환 레이어를 설계한다.

예:

- 외부 소형 던전: 일반~희귀
- 외부 중형 던전: 고급~영웅
- 외부 고난도 던전: 희귀~전설, 매우 낮은 확률의 신화

이는 예시이며 실제 모드와 구조물 난이도를 조사한 뒤 분포를 정한다.

### 9.3 외부 몹 연동

외부 모드의 몹, 엘리트, 미니보스, 보스에도 증강 코어 드랍을 추가할 수 있게 한다.

- 일반 몹은 낮은 등급 중심
- 강한 적일수록 상위 분포
- 보스라고 무조건 한 등급만 고정하지 않는다.

외부 모드가 표준 loot table이 아니라 자체 보상 코드를 사용하면 전용 호환 구현을 별도로 검토한다.

### 9.4 외부 바이옴 연동

바이옴 자체에 단순 확률 드랍을 붙이는 것보다, 해당 바이옴의 콘텐츠를 통해 코어를 얻도록 한다.

예:

- 바이옴 전용 몹
- 바이옴 전용 구조물
- 코어 관련 광맥/자원
- 특수 저장고 또는 탐험 보상

외부 바이옴을 추가했다는 이유만으로 별도 시스템을 남발하지 않는다. 그 바이옴에서 증강을 활용하거나 획득하는 이유가 있어야 한다.

### 9.5 호환성 구조 원칙

- 외부 모드가 없어도 본체는 정상 동작한다.
- 외부 모드 설치 시 해당 compat만 활성화한다.
- 외부 모드 원본 파일을 직접 수정하는 방식을 기본으로 하지 않는다.
- 라이선스와 재배포 조건을 확인한 뒤 모드팩 포함 여부를 결정한다.
- 외부 모드가 증강보다 더 강한 별도 성장 시스템을 제공해 핵심 루프를 무력화하면 포함을 재검토한다.

## 10. 로더 선택

현재 Fabric 또는 NeoForge로 고정하지 않는다.

소스 bootstrap 전에 다음을 비교한다.

- 목표 Minecraft 버전 지원 상태
- 사용하려는 바이옴/구조물/몹/전투 모드의 실제 지원 여부
- loot / worldgen / entity / UI / networking 구현 편의
- 멀티플레이 구조
- 성능 및 유지보수성
- 모드팩 사용자 설치 편의

외부 모드 조합을 먼저 후보화한 뒤 가장 적합한 로더를 고른다.

## 11. 아직 확정하지 않은 것

다음은 현재 정본에서 의도적으로 미확정이다.

- 정식 게임명
- mod id / namespace
- Minecraft 버전 / Java / loader / loader version
- 증강별 실제 목록
- 등급별 증강 개수
- 증강별 최대 레벨
- 증강 수치 밸런스
- 코어 드랍 확률
- 구조물별 정확한 코어 분포
- 몹별 드랍 규칙
- 공식 모드팩 외부 모드 목록
- 엔더 드래곤, 위더 등 개별 보스의 확정 코어 보상
- 최종 UI 디자인

## 12. 다음 기획 순서

1. 바닐라 구조물·몹·활동별 코어 등급 분포 초안 작성
2. 외부 바이옴·구조물·몹 모드 후보 조사
3. 외부 모드 후보를 기준으로 Fabric / NeoForge 생태계 비교
4. 로더와 목표 Minecraft 버전 확정
5. 대표 일반~신화 증강 세트 설계
6. 뽑기/획득/저장 불변조건 정의
7. M0 source bootstrap 및 최소 플레이 가능한 vertical slice 구현
