# Augmentation Survival — Augment Roster Canon

Date: 2026-10-23

이 문서는 개별 증강의 현재 정본이다. 이후 증강 후보를 제안하거나 구현할 때 이 파일을 먼저 확인해 의미 중복을 피한다.

## 1. 공통 규칙

- 증강 총 보유 개수 제한은 없다.
- 증강마다 최대 레벨을 개별 지정한다. Lv.1 고유형, Lv.3/Lv.5 성장형 등으로 통일하지 않는다.
- 최대 레벨에 도달한 증강은 같은 등급의 뽑기 후보 풀에서 제거한다.
- 배타 관계는 전역 규칙으로 두지 않고, 실제 충돌하거나 함께 허용하면 게임성이 무너지는 조합에만 개별 적용한다.
- 내부 설계상 전투/채광/농사/이동/생존/탐험/낚시/건축 등으로 분류할 수 있지만, 플레이어에게 카테고리를 표시하지 않는다.
- 인게임 카드에는 등급을 표시하고, 효과는 가능한 한 정확한 수치를 보여준다.
- `다음` 후보를 제안할 때는 확정/폐기/보류뿐 아니라 과거에 한 번이라도 제안된 후보와 의미가 겹치지 않는 신규 효과만 제안한다.
- 과거 후보를 다시 다룰 때는 사용자가 직접 재검토를 요청했을 때만 꺼낸다.
- **증강끼리는 기본적으로 연계를 허용한다.** 같은 행동을 강화하는 증강들은 가능한 한 함께 작동해야 하며, 강한 조합 자체를 이유로 임의 차단하지 않는다.
- 단, 자동 생성된 2차 행동이 다시 같은 범위/연쇄 생성 효과를 재귀적으로 발동해 무한 또는 기하급수적으로 커지는 경우만 재귀 발동을 차단한다.
- 자동 채굴/자동 수확 같은 2차 행동도 가능한 한 드롭, Fortune, 자원 보너스, 제련 변환, 내구도 절약 등 호환 가능한 수치형 증강의 효과를 이어받는다. 각 기능별 예외는 명시적으로 기록한다.
- 전용 능력 키는 Minecraft Controls에서 재지정 가능한 key mapping으로 등록한다. 공식 모드팩 전체 키맵을 구현 시 확인해 WASD, 점프, 웅크리기, 질주, 인벤토리, 공격/사용, 드롭, 손 바꾸기, 핫바 숫자키 등 **핵심 조작 키와는 겹치지 않게** 기본키를 선택한다. 필요하면 비중요 바닐라/모드 키는 사용할 수 있으나 사용자가 언제든 재지정할 수 있어야 한다.

## 2. 카드 / 표시 UI 원칙

- 일반: 등급색 변화만
- 고급: 등급색 변화만
- 희귀: 등급색 변화만
- 영웅: 등급색 + 약한 네온 발광
- 전설: 네온 발광 + 카드 뒤쪽 후광
- 신화: 붉은색 중심 + 강한 오오라. 전설보다 명확히 강한 존재감을 주되 화면 전체를 가리는 과한 연출은 피한다.

표시형 증강 공통 표현:
- 이름표, 큰 아이콘, 화면 중앙 안내를 난립시키지 않고 **얇은 외곽선 표시**를 기본으로 한다.
- 광석은 청록 계열, 자연 생성 전리품은 금색 계열, 적대적 개체는 붉은 계열을 기본 구분색으로 사용한다.
- 여러 표시형 증강을 동시에 보유해도 대상 종류가 색으로 즉시 구분되게 한다.
- 표시 범위 밖 대상은 보이지 않으며, 표시 자체는 실제 월드 상태·광원·AI·어그로를 변경하지 않는다.

## 3. 방어 계산 원칙

기본 순서:
1. 원래 피해
2. Minecraft 갑옷 방어력 / 방어 강도
3. 보호 계열 인챈트
4. 증강의 일반 피해 감소
5. 조건부 / 속성별 증강 피해 감소
6. 최종 체력 피해

증강 피해 감소끼리는 단순 합산하지 않고 곱연산한다. 예: 상시 피해 10% 감소와 조건부 피해 20% 감소가 동시에 적용되면 `0.9 * 0.8 = 0.72`, 즉 총 28% 감소다.

## 4. 멀티플레이 / 서버 권한 원칙

- 피해, 드롭, 채굴, 낚시, 경험치, 인벤토리, 증강 획득/레벨, 기계 처리 등 중요한 결과는 서버가 최종 결정한다.
- 플레이어가 직접 수행한 행동은 그 행동을 수행한 플레이어의 증강 레벨만 적용한다. 다른 플레이어의 개인 증강을 합산하지 않는다.
- 공유 블록/기계에 영향을 주는 증강은 `누가 마지막으로 만졌는가` 같은 불안정한 판정을 사용하지 않는다. 각 증강마다 소유/범위/스냅샷 규칙을 명시한다.
- 주변 플레이어를 기준으로 작동하는 기계/오라형 효과가 여러 명에게서 겹칠 경우 기본값은 가장 높은 유효 레벨 하나만 적용하며 합산하지 않는다.
- 자동화(호퍼 등)는 특정 플레이어의 행동으로 간주하지 않는다.
- 멀티플레이 구조는 위 원칙으로 설계하지만 실제 멀티플레이 실테스트는 아직 하지 않았다. `MULTIPLAYER TESTED: NO`.

`연료 절약` 멀티 규칙:
- 연료를 누가 넣었는지로 판정하지 않는다.
- 화로/훈연기/용광로가 새 연료 1개를 실제로 소모해 연소를 시작하는 순간, 서버가 주변 8블록 안 플레이어 중 `연료 절약` 레벨이 가장 높은 한 명을 찾는다.
- 그 연료 1개의 연소시간에 해당 레벨 보너스를 스냅샷한다. 이후 플레이어가 멀어져도 이미 시작한 연료의 연소시간은 바뀌지 않는다.
- 주변에 해당 증강 보유자가 없으면 바닐라 연소시간을 사용한다. 호퍼 연료도 같은 규칙을 쓴다.

## 12. 이름 원칙

증강 이름은 짧고 기능이나 이미지가 바로 떠오르게 짓는다.

피한다:
- 과한 추상명사
- 의미 없이 거창한 판타지 조어
- `영겁`, `초월`, `운명의`, `심연의 파동`처럼 효과와 연결되지 않는 AI식 이름

고등급이라도 이름의 과장보다 실제 효과와 연출로 강함을 보여준다.
