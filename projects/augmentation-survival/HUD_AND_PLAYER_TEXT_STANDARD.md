# Augmentation Survival — HUD / Player-facing Text Standard

Date: 2026-10-31
Status: canonical direction

## 1. 플레이어-facing 텍스트와 개발 정본은 분리한다

설계 문서에는 계산 순서, 호환 예외, 서버 권한, 재귀 차단, 외부 모드 대응 같은 구현 정보를 남길 수 있다.

하지만 실제 게임 카드/툴팁에는 다음을 넣지 않는다.

- `ROOT`, `DERIVED`, special damage 같은 내부 분류명
- Better Combat / 특정 외부 모드 호환 처리 설명
- "이 피해는 천벌에는 적용되지 않는다"처럼 다른 증강의 내부 예외를 장황하게 나열하는 문장
- P0/P1, TODO, debug, prototype, alpha, temporary
- 개발 로그, 구현 메모, 기술적 제한 설명
- AI가 만든 문서처럼 보이는 과도한 주석/예외 나열

인게임 설명은 Arena / ARAM: Mayhem 류 카드처럼 다음만 빠르게 전달한다.

1. 무엇을 하면 발동하는가
2. 플레이에 어떤 변화가 생기는가
3. 지속시간/재사용 대기시간/범위처럼 선택에 꼭 필요한 핵심 정보

내부 예외는 해당 효과의 계산 계약에만 둔다.

예:

- 내부 정본: `천벌`은 일반 공격 피해증폭을 받지 않는 최대체력 비율 특수 피해.
- 인게임: `주변 모든 적에게 강력한 번개를 내립니다.`

### 수동 작성 원칙

모든 증강의 플레이어-facing 설명은 **사람이 직접 작성한 문장**만 사용한다.

현재 정본은 다음 6개 등급별 리소스다.

- `src/main/resources/data/augmentation_survival/augmentation/presentations/common.json`
- `src/main/resources/data/augmentation_survival/augmentation/presentations/uncommon.json`
- `src/main/resources/data/augmentation_survival/augmentation/presentations/rare.json`
- `src/main/resources/data/augmentation_survival/augmentation/presentations/epic.json`
- `src/main/resources/data/augmentation_survival/augmentation/presentations/legendary.json`
- `src/main/resources/data/augmentation_survival/augmentation/presentations/mythic.json`

금지:

- 스탯/튜닝/기획 데이터에서 문장을 자동 생성하는 기능
- 구현명을 사람이 읽는 문장으로 자동 치환하는 요약기
- 수동 설명이 없을 때 기계적인 기본 문구를 대신 보여주는 fallback
- 기존 상세 문장을 잘라서 summary를 자동 생성하는 처리
- 런타임 Mixin으로 별도의 카드 문구를 덮어써서 정본이 둘로 갈리는 구조

증강 하나라도 수동 설명이 빠지면 게임 초기화에서 오류로 처리한다. 효과가 변경되면 구현과 함께 해당 수동 원고를 직접 수정한다.

`summary`와 `detail`도 각각 독립적으로 작성한다. 단순 수치형 증강이라도 기본 카드에는 효과의 의미를 먼저 쓰고, 레벨별 숫자는 상세정보로 넘긴다. 효과가 정말 한 줄로 완결되는 경우가 아니라면 두 필드를 그대로 복사하지 않는다.

### 기본 카드 문장

기본 카드는 플레이어가 1~2초 안에 선택 방향을 파악하는 용도다.

- 가능하면 한 문장.
- `행동/조건 → 결과`가 바로 읽혀야 한다.
- 레벨별 숫자 열거보다 플레이 방식의 변화를 먼저 말한다.
- 다른 증강과의 조합을 설명문이 전부 떠먹이지 않는다. 효과 규칙 자체를 명확하게 적어 플레이어가 조합을 발견하게 한다.
- 고등급일수록 문장을 길게 만들지 않는다. 강함은 효과와 연출이 보여준다.

### Shift 상세정보

증강 카드, 보유 증강 목록, 증강 정보 화면에서 마우스를 올렸을 때 기본 상태는 짧은 플레이어-facing 설명만 보여준다.

**Shift를 누른 채 마우스를 올리면 상세정보를 확장한다.**

상세정보에는 플레이 판단에 유용한 수치를 넣는다.

- 레벨별 정확한 수치
- 피해/회복/보호막 계수
- 최대 중첩과 중첩당 수치
- 범위, 지속시간, 재사용 대기시간
- 발동 횟수/필요 적중 횟수
- 최대 대상 수
- 현재 레벨에서 실제 적용되는 값
- 다음 레벨에서 바뀌는 값

예:

기본 표시:
`메아리 타격 — 근접 공격 적중 시 메아리가 함께 공격해 추가 피해를 입힙니다.`

Shift 상세:
`메아리 피해: 원래 공격의 20% / 40% / 60%`
`기본 공격 적중 효과: 1회 추가 발동`

`계수`라는 표현은 플레이어가 수치를 이해하기 위한 게임 용어로 사용할 수 있다. 단, 구현용 이벤트명/호환 예외/재귀 차단 문구까지 상세정보에 노출하지 않는다.

기본 툴팁 하단에는 과도하게 눈에 띄지 않는 `Shift: 상세 정보` 안내를 둘 수 있다.

## 2. 체력 표시 — 하트 대신 게이지 중심

증강으로 최대체력/흡수/보호막이 크게 늘어날 수 있으므로 바닐라 하트 여러 줄을 핵심 체력 UI로 사용하지 않는다.

기본 체력 정보는 숫자 + 게이지 방식으로 표시한다.

### 빨간 체력바

- 플레이어의 실제 현재 HP / 최대 HP를 표시한다.
- `강건함`, `사냥 기록`, `거대화`처럼 최대체력을 바꾸는 효과는 모두 이 실제 최대 HP에 반영한다.
- 바닥 트랙을 채우는 액체 같은 붉은 게이지로 표현한다.
- 피해 시 즉시 감소하되 짧은 잔상/후행 표시를 사용할 수 있다.

### 노란 추가 체력

- 흡수 체력/증강이 만든 임시 추가 체력 계층을 노란색으로 표시한다.
- 별도 두 번째 바를 만들지 않고 빨간 체력바와 같은 줄 안에서 겹치는 형태로 표현한다.
- 실제 HP와 혼동되지 않게 노란 액체층/광택 차이를 둔다.
- `넘치는 회복` 등으로 생긴 흡수 체력이 대표 대상이다.

### 파란 보호막

- `보호막`처럼 별도 shield pool로 관리되는 값은 파란색으로 표시한다.
- 빨간/노란 체력바에 덮어쓰지 않고 그 바로 위에 얇은 별도 바를 둔다.
- 현재 보호막 / 최대 보호막을 별도로 읽을 수 있다.
- 보호막이 0이면 자연스럽게 사라져 HUD 공간을 불필요하게 차지하지 않는다.

### 공통 시각 표현

- 빨강/노랑/파랑 모두 딱딱한 평면 사각형보다 **흐르는 액체가 차 있는 느낌**을 사용한다.
- 미세한 파동/표면 움직임은 허용하지만 플레이 중 숫자 가독성을 해치지 않는다.
- 과도한 glow, gradient, 입자 난사는 피한다.
- UI 요소가 화면마다 다른 간격/높이로 흔들리지 않도록 동일한 HUD 기준선을 사용한다.
- 최대체력이 매우 커져도 바 자체 폭을 끝없이 늘리지 않고 숫자와 비율로 표현한다.

## 3. 체력 계층 표시 순서

시각적으로는 위에서 아래 순서:

1. 파란 보호막 바
2. 빨간 실제 HP 바 + 같은 줄에 노란 흡수/추가 체력 표현

피해 계산 자체의 우선순위는 `AUGMENT_INTERACTION_CONTRACT_2026-10-24.md`를 따른다.

## 4. 월드 위협 단계 HUD

현재 월드의 위협 단계는 플레이어가 항상 인지할 수 있어야 한다.

- 기본 위치는 화면 **우측 상단의 작은 상태 영역**으로 한다.
- boss bar, minimap, 외부 모드 HUD가 존재하면 안전 여백을 확보해 겹치지 않게 오프셋한다.
- 기본 표시는 작은 아이콘 + `위협 0~8` 정도로 짧게 유지한다.
- 내부 power score 숫자는 일반 HUD에 노출하지 않는다.
- 단계가 상승할 때만 짧은 전환 연출/사운드로 알려주고 평상시에는 시선을 빼앗지 않는다.
- 위협 단계 상세 화면에서는 현재 일반 적의 대표 체력/피해 배율을 확인할 수 있게 할 수 있다.
- 개발용 `power score`, 내부 스케일 그룹 이름, namespace 같은 정보는 플레이어 HUD에 표시하지 않는다.

위협 단계는 지역별 값이 아니라 **세이브 전체에서 하나의 공통 값**을 사용한다. 정확한 산정/상승 규칙은 `ENEMY_POWER_SCALING_DESIGN.md`를 따른다.

## 5. 액티브 증강과 권능 해방 UI 분리

일반 증강 액티브는 기존대로 증강 스킬 모드 + 숫자키 `1~0`의 **10칸 빠른 사용 슬롯**을 사용한다.

`권능 탈취`는 이 10칸을 사용하지 않으며 권능을 골라 장착하는 슬롯도 두지 않는다.

### 권능 해방 조작

- `권능 탈취` 전용 **권능 키 1개**만 둔다.
- 보스를 처음 처치해 권능 패키지를 탈취하면 별도 선택 없이 영구 누적된다.
- 권능 키를 누르면 지금까지 탈취한 모든 보스 권능이 한 번의 권능 해방으로 발동한다.
- 권능 수가 늘어도 추가 단축키나 액티브 슬롯을 요구하지 않는다.
- 권능 해방 전체가 하나의 120초 재사용 대기시간을 사용한다.
- 일반 액티브 10칸과 권능 해방은 서로 슬롯/쿨다운을 공유하지 않는다.

### HUD

- 별도 권능 선택 패널을 상시 띄우지 않는다.
- `권능 탈취` 보유 시 작은 전용 아이콘과 전체 쿨다운만 표시한다.
- 아이콘 옆 또는 Shift 상세정보에서 현재 탈취한 우두머리 수를 확인할 수 있게 한다.
- 사용 가능 상태에서는 아이콘이 짧게 강조될 수 있으나 지속적인 강한 glow는 피한다.
- 권능 해방 시에는 일반 액티브 HUD를 밀어내지 않고 별도의 짧은 시전 피드백만 제공한다.

## 6. 인게임 카드 문체

- 짧은 이름 + 기본 설명 1문장을 우선한다.
- 기본 설명은 효과의 의미와 플레이 변화를 먼저 전달한다.
- 레벨별 수치표, 범위, 지속시간, 재사용 대기시간, 최대 대상 수는 Shift 상세에 둔다.
- 현재 선택 판단에 반드시 필요한 숫자만 기본 설명에 남긴다.
- "서버가 판정한다", "호환 목록", "내부 계산상" 같은 문장을 쓰지 않는다.
- 다른 증강과의 상호작용은 플레이어가 규칙을 오해할 정도로 중요한 경우만 짧게 언급한다.
- 고등급 효과는 거창한 문구보다 실제 효과와 연출로 위력을 보여준다.

예시:

`유리 대포`
- 기본: `최대 체력을 희생해 전투 피해를 크게 높입니다.`
- 상세: `Lv.1 / 2 / 3에서 최대 체력이 원래의 60% / 80% / 100%가 되고, 일반 전투에서 주는 피해가 60% / 80% / 100% 증가합니다.`

`거대화`
- 기본: `20초 동안 거대화하여 체력과 근접 전투 능력이 크게 증가합니다.`
- 상세: 크기·체력·사거리·피해·넉백의 정확한 수치를 표시한다.

`권능 탈취`
- 기본: `쓰러뜨린 보스의 권능을 빼앗아 한꺼번에 해방합니다.`
- 상세: 획득 조건, 권능 키, 전체 재사용 대기시간을 표시한다.

이 문서는 실제 구현 시 UI/카드/툴팁 작성의 기준으로 사용한다.
