# Augmentation Survival — UI 구조 리뉴얼 결정 및 검증 게이트 (2026-11-05)

상태: 디자인 방향 확정 / 전체 화면 구현·게임 내 시각 검수 전.

## 게임 정체성
Minecraft 장기 서바이벌에서 149종 증강을 계속 얻고 축적하는 파워 판타지.
단일 전투 로그라이크도, 일반 마법 도감도, 디지털 SF 터미널도 아니다.
현재 2026-11-04 실제 플레이 스크린샷을 기준으로 판단한다.

## 실패한 방향
- 검은 큰 캔버스 위에 비슷한 얇은 테두리 직사각형 반복
- 이미지 생성 도구가 만든 청록 네온·과장된 후광·불필요한 패널·가상의 능력 수치/화폐
- 현실 Minecraft의 GUI scale과 화면 크기를 고려하지 않은 포스터형 시안
- 카드 위에 AI풍 장식만 추가하면서 정보 구조와 조작은 유지하는 겉치장
- 구현되지 않은 XP 막대/에너지 소모/쿨타임/레벨을 시안 또는 실제 UI에 발명

## 채택 방향: 기계적 유물 + 공명 + 기능별 화면 차별화
- 공통 문법은 Minecraft와 맞는 재질(석재·구리/금속·자수정·장치 슬롯)과 절제된 게임 내 픽셀 아이콘.
- 전체 검정 배경과 사이버펑크 청록 네온은 기본 정체성이 아니다. 밝은 제작면과 석재/금속/유리/자수정도 적극 활용.
- 직사각형을 금지하지 않는다. 다만 화면마다 다른 공간 구성을 사용.
- 실제 3:1 합성·코어 등급·후보 3개·보유 수준·슬롯 10개·서버 권한은 보존.
- 보유 증강을 장비처럼 슬롯 제한하지 말 것. 149종 소유는 무제한이며 편성 10칸은 액티브 단축키임.
- 플레이어 facing 문구는 canonical presentations/와 HUD_AND_PLAYER_TEXT_STANDARD.md 사용.
- 수치와 기능은 코드/카탈로그 정본 검증. 없는 시스템 발명 금지.

## 화면별 구현
1. 증강 제작 안내서: 3×3 재료와 결과가 곧바로 읽히는 작은 실물 제작서. 현재 가로 UI의 넓은 빈 공간 제거.
2. 코어 등급 동조: 여섯 등급이 동일 패널 반복처럼 보이지 않게, 상징적인 중앙 동조 장치와 코어 소켓을 시각 중심으로 사용. 선택 가능/없음과 보유량은 즉시 판독.
3. 3후보 선택: 중앙에서 분리된 공명 결과 3개. 아이콘/짧은 효과/레벨/부분 재추첨을 명료히. 원본 카드 클릭 판정 및 후보 서버 트랜잭션 유지.
4. 보유 증강: 도감/관리 화면. 빠른 검색·페이지·등급 필터/획득 상태, 목록 + 상세. 149종에서도 탐색 가능.
5. 코어 합성: 하위 코어 ×3 → 장치 공정 → 상위 코어 ×1. 합성 횟수와 보유량을 실제 서버 상태로 표시; 단일/최대 합성 모두 보존. 근거 없는 소모 자원 추가 금지.
6. 전투 증강 편성: 상단 실제 10 슬롯 유지. 아래 액티브 목록 및 상세는 호버 팝업에 가리지 않고 빠르게 읽히도록. 스킬 모드 키는 별도 키매핑·플레이어 설정 존중.
7. 공간 연결: 왼쪽 검색 가능한 위치/등록 목록, 오른쪽 목적지/공유/기본 이동 관리. 빈 목록도 가이드 제공.
8. 권능 탈취: 수집한 지원 보스별 권능을 Shift+J로 조회, J 발동 유지; 권능 세트는 기존 서버 저장에서만 읽기. 별도의 개인별 24개 슬롯을 만드는 것이 아님.
9. 지배 관리: `Shift+지배 슬롯` 관리 화면과 서버 UUID 로스터/원격 해제가 소스에 구현됨. 실제 인게임 UI는 불필요하게 넓고 빈 공간이 많아 리뉴얼 대상. 기존 등록·해제·오프라인/언로드 동료 관리 계약을 유지하고, 특수 몹의 전투 AI 문제는 UI와 별개로 검증한다.

## 등급 FX
일반/고급/희귀: 보유 코어/선택 부분의 명확한 등급색.
영웅: 약한 발광.
전설: 아이콘 뒤 실제 시인성 높은 후광.
신화: 붉은 중심광, 독립 회전 문양/오오라와 소량의 입자. 
*후광을 단순 카드 테두리 겹침으로 대신하지 말고, 실제 이미지·회전 텍스처·마스킹 등으로 구체화.*
저해상도에서 광량·모션 줄이고 텍스트/마우스 판정과 충돌 금지.
일반 상태는 안정적으로, 호버/선택/획득/합성의 의미 있는 순간만 0.1~0.4초 내외 반응 애니메이션.
진행 중 반복 파티클 남발 금지.

## 수용 기준
- 실제 Minecraft 26.2 클라이언트에서 normal/compact GUI scale, 낮은 해상도, 최대 내용, 빈 내용, 2개 선택·재추첨을 검수.
- 시각 검수 스크린샷 없으면 UI VISUAL REVIEW: NO.
- 기존 기능 소실/서버 트랜잭션 변경 금지. UI만 바꾸는 단계에서 대규모 gameplay 리팩터링 금지.
- 모든 화면을 한 번에 새 창으로 바꾸기보다 관련 흐름 하나씩 구현·시각 검수 후 다음으로 진행.
- 기술 부채 UI rescue Mixin을 그냥 지우지 않는다. 실제 렌더 경로와 click geometry를 동시 교체하고 검증.

## 2026-11-05 추가 실기기 플레이 화면 4장: UI 결함 인계 (사용자 제공)

이미지 원본은 ChatGPT 대화에 첨부돼 있으며 **이 문서만으로 Codex가 실제 PNG를 볼 수 있는 것은 아님**. Codex 작업 시 사용자 원본 캡처 4장을 첨부하거나 GitHub에 별도 저장해야 함. 사용자 제공 순서:
1. 지배 관리 — 점유 0/10, 아무 동료도 없을 때.
2. 공간 연결 — 위치 0개, 빈 목록 및 모든 필드/관리 버튼 노출.
3. 지배 관리 — 가디언 1/10, 오른쪽 상세와 해제 버튼.
4. 탈취한 권능 — 0/26, 위더 선택, 1/13 페이지.

### 즉시 수정해야 하는 문제
- **권능 탈취:** 화면 크기 대비 목록이 한 페이지 2종에 불과해서 26종을 **13페이지** 탐색해야 함. 중앙·하단은 과도하게 비어 있고, 상세가 2줄이면 남는 공간의 정보 가치가 매우 낮음. 무엇보다 footer의 J 조작문과 재사용 대기시간/해방 상태/닫기 문구가 위아래 줄에서 겹쳐 **가독성을 파괴함**. 실제 Minecraft GUI scale에서 재현. 수정 완료 기준: 목록 6–10개가 한눈에 읽히거나 필터·스크롤 제공, 서버 확인된 획득·활성화 상태와 효과를 한 화면에서 식별, 우측 토글 hitbox 명시, 긴 효과 설명과 footer 물리적으로 분리, 26종을 페이지 13번 넘겨보지 않아도 됨.
- **지배 관리:** 0명일 때 왼쪽에 한 줄만 떠 있고 우측은 큰 빈 회색 직사각형. 가디언 1명도 왼쪽 대부분이 빈 공간. 현재 `DominationManagementScreen.layout()`는 **최대 620×330의 고정 크기, 목록 폭 약 50%, 상세 폭 약 50%, 최대 9행**을 지정해서 실제 항목 수와 무관하게 거대한 영역이 생성됨. 0명은 짧은 온보딩/간결한 빈 상태, 1명은 동료 한 줄+간결한 상세/해제, 다수는 밀도 높은 목록/검색/스크롤로 상황별 밀도 조정. 진단용 `minecraft:guardian` / `minecraft:overworld`를 그대로 보여주기보다 '가디언' / '오버월드'처럼 번역·축약된 플레이어 문구 사용. 저장된 UUID/차원/로드 여부는 서버 데이터로 유지.
- **공간 연결:** 검색·등록 이름·상세 이름·공유 대상용 **검은 EditBox 여러 개가 라벨 없이 노출**되고, 위치가 0개인데도 빈 슬롯 행 6개와 이동/즐겨찾기/기본 지정/이름 변경/삭제/공유/회수 등 불필요한 조작이 전부 노출됨. 검색/등록, 빈 상태, 위치 선택 후 관리라는 순서를 명확히 나누고 첫 진입 시 '위치 등록' 핵심 행동만 강조. 기존 안전한 서버 권한·기본 이동·공유·회수·삭제 동작은 보존.
- 화면별 색·폰트/패딩/헤더·footer 규칙이 서로 달라 하나의 게임 제품으로 보기 어려움. 앞서 정한 **기계적 유물+공명** 아트 방향과 실제 Minecraft용 배치 규칙에 맞춘다. UI에 가상의 재화·스탯/개발 문구 추가 금지.
- 실제 UI 코드: `client/screen/AuthorityCollectionScreen.java`, `client/screen/DominationManagementScreen.java`, `client/screen/SpatialLinkScreen.java`. `AuthorityCollectionScreen.layout()`은 높이에서 행 수를 계산하고 컴팩트 모드에서는 상단 목록/아래 상세 2영역을 강제로 나눠 작은 창에서 목록 2행만 생성됨. footer는 `layout.h()-31`에서 두 줄을 그리는데 실제 설명/레이아웃과 충돌하는지 시각 검수 필요.

### UI와 독립적인 실제 플레이 버그 (UI 패스에서 임의로 수치 조절하거나 미봉하지 말 것)
- 지배한 슬라임이 적에게 접근만 하고 공격하지 않음.
- 지배한 가디언의 공격 방식이 비정상적으로 바뀜. 원래 빔 공격의 충전/발사 흐름부터 확인.
- 서버 `augment/companion/CompanionAugmentService.java`의 `tickDominatedCompanions → refreshCombatTarget → applyCombatTarget`은 대부분의 몹에 매 틱 `setTarget`과 `getNavigation().moveTo(target,1.15)` 공통 경로를 사용. 슬라임은 특수 MoveControl/공격 Goal, 가디언은 충전형 beam goal을 사용하기 때문에 종별 AI에 경로 간섭 가능성이 큼. **원인 가설이며 미테스트**. 고정 틱 피해 지급, 종별 무조건 공격력 추가, 원본 공격 제거는 금지.
- 슬라임·마그마 큐브·가디언·엘더 가디언·블레이즈·가스트·셜커·위치·워든 등 특수 AI 몹을 대상으로 공격 방법별 검증 매트릭스 작성. 원본 공격과 피격 판정은 보존하고 지배 소유·대상 선택·아군 보호만 연결. 워든은 별도 기존 anger/brain 처리와 충돌시키지 않기.
- 위 버그는 UI 작업과 별개의 서버 전투 코드 수정을 요구. 각각 독립 재현 테스트를 추가하고 실제 플레이로 검수할 것.

### 실행 순서
1. 전투 기능은 유지하면서 UI 3종을 실제 플레이 캡처 기준으로 개선. **권능 탈취 footer 텍스트 겹침은 최우선**.
2. 0개/1개/많은 항목, 작은 GUI scale/고해상도/좁은 창, 길고 여러 줄인 권능 효과, 선택/토글/해제/등록/공유/검색 동작을 마우스 클릭 좌표와 함께 검증.
3. 슬라임·가디언 공격 문제는 별도 엔티티 AI 경로 분석·재현 테스트 후 수정. UI 작업 때문에 지배/권능 기록을 초기화하거나 서버 구조를 변경하지 않음.
