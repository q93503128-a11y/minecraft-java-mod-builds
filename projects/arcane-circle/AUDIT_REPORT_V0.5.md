# Arcane Circle v0.5 전체 감사 보고서

검사 대상은 `0.4.0-alpha.1` 전체 소스와 리소스이며, 저장·입력·네트워크·시전·융합·UI·지팡이·생존 획득·멀티플레이 안전성을 분리해 점검했다.

## 확인하고 수정한 주요 결함

| 영역 | 기존 문제 | v0.5 조치 |
|---|---|---|
| 쿨타임 | 정적 메모리 맵이라 재접속·재시작으로 초기화 가능 | 플레이어별 주문 쿨타임을 월드 SavedData에 저장 |
| 융합 대기열 | 로그아웃·사망·차원 이동 뒤 남을 수 있음 | 모든 수명주기 이벤트에서 세션 제거, 10초 자동 만료 |
| 융합 입력 | 잘못된 두 번째·세 번째 재료가 회로를 망침 | 완성 가능한 후보가 없으면 새 재료만 거부 |
| 시전 실패 | 대상 검증 전 마법진·소리가 먼저 출력됨 | 대상·공간을 먼저 검증한 뒤 연출·효과·소모 처리 |
| 조준 | 벽 뒤 대상과 가까운 비적합 대상을 잡을 수 있음 | 시야 검사, 시선 투영 거리와 횡오차 기반 우선순위 |
| 아군 피해 | 범위 주문이 팀원·길들인 동물을 공격 가능 | 팀 아군과 소유 길들임 개체 제외, 불사조 성역은 치유 |
| 전이 | 액체·불안정 바닥·월드 경계 검사 부족 | 경계, 발·머리 공간, 액체, 바닥 윗면 지지 검사 |
| 저장 마이그레이션 | 알 수 없거나 미습득 주문 슬롯이 남을 수 있음 | 유효 주문과 학습 여부를 검사해 안전한 기본 슬롯으로 복구 |
| 초기 지급 | 제거된 엔티티 태그 API 의존 및 중복 위험 | 마법사 프로필의 선택적 저장 필드로 정확히 한 번 지급 |
| 숫자키 | 주문키가 바닐라 핫바도 동시에 이동 | 클라이언트 Post tick에서 주문 처리 뒤 기존 선택 슬롯 복원 |
| UI | 작은 화면에서 HUD·인벤토리·마력핵 패널 겹침 | 폭·높이에 따라 측면/상단/압축 레이아웃 자동 전환 |
| 마도서 | 탭 전환 때 선택 슬롯 초기화, 잠긴 주문 무반응 | 슬롯·스크롤·창 위치 유지, 잠금 이유 즉시 표시 |
| 지팡이 | 창작 탭 외 획득 불가, 바닐라 막대 모델 공유 | 최초 견습봉 지급, 8개 생존 제작식, 9개 고유 픽셀아트 |
| 지팡이 효과 | 공간·바람·방벽 등 일부 보정이 실효성이 낮음 | 이동 거리, 결빙, 보호막, 회복, 범위에 실제 반영 |

## 구현 확장

- 2~3개 재료를 다중집합으로 비교하는 융합식 검색
- 부분 재료 상태에서 남은 완성 후보 수와 삼중 확장 가능 여부 계산
- 주문 학파별 룬과 실제 시전 마법진 문법 분리
- 마도서 `지팡이` 탭과 제작 재료 안내
- 영구 쿨타임의 서버 권위 동기화와 클라이언트 보간 표시
- 9개 지팡이 전용 32×32 PNG와 휴대형 모델

## 자동 검사 범위

`tools/test_magic_contract.py`는 다음 계약을 검사한다.

- 구버전 저장과 호환되는 선택 필드
- 영구 쿨타임과 최초 지급 플래그
- 융합 후보 계산, 만료, 세션 정리
- 시전 검증과 연출 순서
- 아군·길들인 동물 보호
- 숫자키와 메뉴 입력 정리
- 작은 화면 HUD·인벤토리·마도서 레이아웃 코드
- 10개 융합식과 9개 지팡이 등록
- 8개 생존 제작식의 결과 ID
- 9개 PNG의 서명, 32×32 크기, 해시 중복 여부
- 아이템 정의→전용 모델→전용 텍스처 연결

`tools/verify_jar.py`는 완성 JAR에서 같은 리소스와 클래스가 실제 포함됐는지 다시 검사하고 SHA-256을 생성한다.

## 남는 수동 검사

정적 검사와 Java 빌드는 화면의 실제 체감까지 보장하지 않는다. 배포 JAR에서는 다음을 직접 확인한다.

- 창 크기와 GUI 배율별 글자 잘림
- 숫자키 사용 뒤 핫바 선택 복원 체감
- X를 놓는 순간의 융합 응답성
- 각 마법진의 입자 밀도와 전투 가시성
- 지팡이 손 모델의 크기와 위치
- 멀티플레이에서 팀·소유 동물 판정
