## 2. Canon consumed

`Hart's Momentum`:

```text
after moving at sprint speed for >= 1.25 s
next melee basic within 2.0 s
lunge up to 1.5 blocks toward the valid target
+35% poise/stagger damage
internal cooldown 5.0 s
```

The lunge may not pass through solid collision or extend the actual hitbox beyond validated visible
attack reach.

Runtime tick equivalents:

```text
1.25 s = 25 ticks
2.0 s  = 40 ticks
5.0 s  = 100 ticks
+35% poise = 1.35x
```

## 3. Server-owned qualification state

`R01RegalhartMythicEffectState` owns transient qualification/cooldown state.

The server observes an equipped Hartcrown player each tick. A movement tick counts only while the
player is actually sprinting and has non-zero horizontal server movement. Twenty-five continuous
qualifying ticks arm one 40-tick opportunity.

If the player stops moving/sprinting before qualification, the segment resets. If the 40-tick
opportunity expires unused, that same uninterrupted sprint segment does not repeatedly recreate a
fresh window; movement must break before a new 25-tick qualification begins. A successful
consumption starts the 100-tick cooldown.

This choice prevents continuous sprint from degenerating into a permanently armed state while
keeping the exact authored 1.25 s / 2.0 s / 5.0 s numbers intact.

## 4. Melee authority ordering

Hart's Momentum is integrated into `PlayerAttackAuthorityMixin` only after all of the following
have already accepted the melee hit:

1. Better Combat reports an active melee candidate;
2. project action-lock rules permit the basic;
3. target is a project-owned combat actor with a valid authority target;
4. project combat build and target snapshot exist;
5. canonical melee damage authorization succeeds;
6. authoritative attack cadence accepts the swing/target;
7. project physical HP damage application succeeds.

Only then can Hart's Momentum consume its opportunity.

Therefore the 1.5-block movement cannot manufacture a target that Better Combat/project reach had
not already accepted. It changes player position as authored feedback and applies the poise bonus to
the accepted attack; it does not extend hit reach.

## 5. Collision-safe lunge

The runtime computes a horizontal vector toward the already-valid target and requests at most
1.5 blocks of movement.

Movement uses:

```java
player.move(MoverType.SELF, movement)
```

This reuses the same Minecraft collision-resolved movement primitive already used by project dodge
and Quickstep movement instead of teleporting through blocks. The runtime records actual horizontal
distance moved, which may be less than 1.5 blocks when collision constrains the request.

No new hitbox is generated by the lunge.

## 6. Poise integration

The consuming melee basic receives:

```text
final project poise damage
= ordinary basic poise damage
× existing Warrior Momentum multiplier when applicable
× 1.35 Hart's Momentum multiplier
```

HP damage is not increased.

Existing personal elite/boss poise-break handling, including Rootquake where equipped/eligible,
continues after the final poise application.

## 7. Lifecycle / presentation boundary

Transient Hart's Momentum state is cleared on:

- respawn;
- disconnect.

This pass deliberately does not:

- create/materialize Hartcrown Spear as a physical reward;
- invent a zero-value placeholder item;
- select or copy an unaccepted external spear asset;
- add generic particle placeholder presentation;
- flip `R01ExternalActorCatalog.productionSpawnReady(REGALHART)`.

Hartcrown physical delivery still needs accepted item presentation/materialization. Regalhart live
spawn also still waits on its independent attack/camera/weak-point/presentation gates.
