# 2. Stylized Magic Construct — direct final visual rejected after preview

Public product sources reviewed:

- Fab: `https://www.fab.com/listings/b86c16b7-fa0f-449f-9dfd-2ca4ef725982`
- Unity Asset Store: `https://assetstore-fallback.unity.com/packages/3d/characters/creatures/stylized-magic-construct-318325`
- public product screenshots mirrored from the Unity listing

The screenshots show a coherent stylized fantasy construct family with:

- slim humanoid torso proportions;
- pointed/hovering lower-leg silhouette;
- long claw-like arms;
- narrow helmet/head mass;
- bright magical body/emissive areas framed by metallic armor plates;
- multiple color variants.

These are good production assets. They are simply the wrong **direct** finale identity.

## Why direct adoption fails

The visible read is closer to:

```text
elite magical construct / arcane soldier / caster enemy
```

than:

```text
continent-scale ancient-system guardian / final crisis form
```

Specific problems:

- body mass is too slim/humanlike for the heavy systemic-guardian role;
- the preview does not expose a sufficiently dominant central core/control structure;
- there are not enough obvious large segmented functional zones for the already-authored Partition/Reconfiguration mechanics;
- five similar construct variants read more naturally as a creature/enemy family than one singular launch-finale entity;
- scaling the model up would enlarge the same silhouette rather than solve its identity.

Therefore:

```text
DIRECT FINAL MODEL: REJECTED
PURCHASE FOR FINAL-BOSS PURPOSE: NOT RECOMMENDED AT CURRENT EVIDENCE
RIG / CAST / ATTACK MOTION REFERENCE: RETAINED
EDITABLE/COMPOSITE BASE: only reconsider if actual source inspection later proves a major silhouette transformation is both legal and visually coherent
```

This is a quality rejection, not a claim that the donor asset is low quality.

# 4. Earth Guardian — animation grammar reference, not final visual

Source:

`https://www.fab.com/listings/c694958c-e4c0-43f3-b080-54c12cf20b65`

Current product metadata states:

- realistic detailed Earth Guardian golem;
- Epic skeleton;
- 25 animations;
- 5 attacks;
- **4 Barrier animations**;
- walk/run/jump;
- knockback/turn;
- spawn/death;
- FBX plus converted glTF/GLB/USDZ;
- public page says generated-with-AI = No.

## Why the animation set matters

The four Barrier animations are unusually relevant to the already-authored finale mechanic:

```text
Partition Window
```

They demonstrate the correct presentation principle:

> a defense/partition state should have a dedicated body animation/state change, not merely a shield particle suddenly appearing.

Potential reference mapping:

```text
barrier close / protected posture
→ network partition intact
barrier strain / transition
→ links overloaded
barrier open / vulnerable posture
→ Partition Window
barrier recover
→ partition restored
```

## Why the direct model still does not solve R12

It is explicitly a conventional Earth/stone golem identity. R03 already uses a Rock Golem role and R12 needs a more systemic/constructed visual thesis.

Decision:

```text
DIRECT R12 FINAL VISUAL: NOT ADOPTED
ANIMATION/STATE REFERENCE FOR PARTITION WINDOW: STRONG
```

# 5. PROTOFACTOR Golem — reconfiguration grammar reference

Source:

`https://www.fab.com/listings/c74b579c-a793-49f6-8113-7b4312e58eab`

Current product metadata states:

- 11.2k tris;
- 34-bone rig;
- 25 animations;
- rock and ice variations;
- includes an **animated split-into-pieces variation** so the golem can construct/explode instead of only playing a standard death animation.

That split/construction behavior is directly relevant as a **mechanics presentation reference** for:

```text
Reconfiguration
```

The useful lesson is not `make the final boss a rock golem`.

It is:

> Reconfiguration should physically rearrange, split, reconnect or expose parts of the guardian so the player sees the system changing configuration.

Possible final-guardian application:

```text
outer segments detach / rotate / reconnect
→ emitter topology changes
→ Cascade Line origins change
→ exposed central node becomes reachable
→ Network Link pattern visibly changes
```

Decision:

```text
DIRECT R12 FINAL VISUAL: NOT ADOPTED
CONSTRUCT / DISASSEMBLY / REASSEMBLY MOTION REFERENCE: STRONG
```

# 7. Refined final-guardian target

The search should stop using `golem` as the primary noun.

Current target language becomes:

# **segmented fantasy Anchor automaton / ancient network construct**

This is an internal search description, not a player-facing final name.

The required body now combines lessons from the external references:

```text
singular heavy final-act silhouette
+ fantasy/ancient construction rather than modern robot language
+ dominant central core/control zone
+ 3–5 meaningful outer segments/nodes
+ dedicated protected/open barrier states
+ physically visible reconfiguration / split / rotate / reconnect behavior
+ 3+ attack origins
+ cast/channel state
+ hit/stagger/shutdown
```

Strong preferred animation vocabulary for the next candidate:

```text
Idle / Active Idle
Move / Reposition
Attack A / B / C+
Channel / Cast
Barrier Close
Barrier Open / Vulnerable
Reconfigure / Assemble / Disassemble
Hit / Stagger
Shutdown / Death
```

A candidate lacking one of `Barrier/Open` or `Reconfigure` may still work if the skeleton/segmentation clearly supports authoring those motions without destroying quality.

# 8. Consequence for the final encounter sheet

Do **not** write anatomy-specific attacks before the model exists.

The following mechanics remain locked at behavior level:

- Network Link;
- Cascade Line;
- Partition Window;
- Reconfiguration.

But exact authored moves wait for the body. For example, do not decide now that `the left arm fires the cascade beam` when the eventual accepted model may use shoulder rings or floating nodes instead.

The final sheet closes in this order:

```text
accepted model + rig
→ identify truthful attack origins / protected parts / weak zones
→ bind existing four mechanics to anatomy
→ define attack sequence / recovery / camera / hitboxes
→ bind VFX/SFX
→ Minecraft-scale visual test
```
