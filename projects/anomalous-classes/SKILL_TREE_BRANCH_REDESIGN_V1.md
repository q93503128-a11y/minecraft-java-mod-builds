**중요:** 소형 노드와 주요 노드의 비용 **합계만** 900SP이다. 기존 900SP에 작은 스탯 100~200SP를 덧붙이지 않는다. 기존 270~300랭크 효과를 다시 270~300개의 노드로 만드는 것도 아니다.

## 4. 기존 효과의 정확한 압축 법칙

1. 각 원본 패시브를 **기존 10랭크마다**, **기존 돌파 지점마다**, **마지막 상한 랭크마다** 자른다. 같은 지점은 한 번만 쓴다. 따라서 대부분 구간은 5~10랭크이고, 현재 돌파 없는 35랭크 스킬은 10/20/30/35 등으로 끝난다.
2. 각 구간마다 **작은 일반 능력치 노드 1~3개 → 주요 스킬 노드 1개**를 연결한다. 작은 노드에는 Minecraft의 최대 체력·방어력·이동속도·기본 공격력만 사용한다. 이 단계에서는 새로운 상태이상·스킬·재화·무기·특수 트리거를 추가하지 않는다.
3. 주요 노드를 구입할 때 해당 원본 패시브를 **구간 끝의 구 원본 랭크**까지 올린 것과 **동일한 기존 수치 보정**을 획득한다. 예: '권능 응축' 구 0~10/10~20/20~30을 각각 주요 노드 1개로 나타낸다. 모든 주요 노드를 사면 최종 **권능 직접 효과 +15%**라는 기존 시험 수치를 그대로 유지한다.
4. 원래 **다중 결속 5랭크마다 +1마리**, **기생 생존 전이 10/20/30 충전**, **결계 다중 전개 15/35랭크 추가 설치** 같은 실제 변곡점은 절대 놓치지 않는다. 새 스킬을 추가하지 않고 기존 돌파를 구간 끝 주요 노드에 귀속한다.
5. 주요 노드가 다른 경로를 통해 보이더라도 **같은 원본 패시브의 직전 구간 주요 노드**는 선행되어야 한다. 기존 기술 자체(지배·기생·결계 배치·계약 권능·군체 역할·인형 기본 운용)를 SP로 새로 잠그지 않는다.
6. 모든 기존 랭크의 **최종 효과 크기·비용·돌파 효과를 보존**하는 것은 계산상 검증 가능하다. 그러나 **강화가 1랭크씩 증가하던 체감이 구간별 큰 획득으로 달라지는 점**은 의도된 재설계이며, 실제 레벨 속도와 함께 플레이테스트해야 한다.

### 원본 실제 비용으로 계산한 계약술사 예시

- **권능 응축:** 1-10: 4+3+25=32; 11-20: 4+3+3+34=44; 21-30: 5+4+4+48=61 (구 비용표에서 합계 **137SP**)
- 위 표기는 **작은 노드들 비용 + 주요 노드 비용 = 이전 동일 랭크 구간의 실제 비용**이다. 작은 노드를 찍은 뒤 주요 노드를 살 SP를 모으는 선택이 생기며, 최종 강화 효율은 구 30랭크와 같아진다.
- `이중 조율`은 기존대로 2계약 이상일 때만 유효하다. 노드를 샀다는 이유로 무료 계약이나 계약별 고유 패시브를 만들지 않는다.

## 5. 일반 능력치 노드의 초안

- 대상은 기존 바닐라 Attribute: `max_health`(HP), `armor`(방어력), `movement_speed`(기본 이동속도 비율), `attack_damage`(기본 공격력).
- 1개 일반 노드당 후보: **최대 HP +0.20**, **방어력 +0.08**, **기본 이동속도 +0.12%**, **기본 공격력 +0.04**. 이 수치는 원본의 기존 900SP 특수 효과에 **추가되는 작고 제한적인 별도 보정**이며 확정된 밸런스가 아니다.
- 기생술사의 인간형이 강한 전사가 되는 일을 방지하기 위한 후보: **HP +0.05 / 방어 +0.02 / 속도 +0.12% / 공격 +0.01**. 숙주 BD·종 숙련·숙주 HP/공격 공식에 직접 중복 적용하지 않는다. 실제 스탯 적용 대상을 구현 전 규정한다.
- 노드 하나는 작은 수치 1종만 준다. 기존 스킬의 수치 복사 또는 '성공률 1%' 같은 미확정 새 확률 노드는 만들지 않는다.
- 플레이어 직업 변경·무료 초기화·사망·재접속 때 각 유효 Attribute modifier를 **UUID/ID 기준으로 한 번만** 적용/제거한다. 최대 체력 변동은 비율·상한을 안전하게 처리한다. SP 비용과 보정량은 data-driven이어야 하며 클라이언트 단독 변경을 금지한다.
- 나중에 실제 게임 난이도에서 과도하면 **일반 노드 수치만** 조정한다. 원본 주요 스킬의 최종 효과를 몰래 깎아 보상하는 방식은 금지한다.

## 6. 비용 배분 원칙

기존 랭크 가격을 `c[1..R]`라 하면 `a+1..b` 구간의 원래 비용은 `S = Σ(c[a+1..b])`이다.

- `S ≤ 15`: 소형 1개, `16..37`: 소형 2개, `S ≥ 38`: 소형 3개.
- 소형 노드 공동 비용 `max(개수, round(S×0.22))`을 정수로 최대한 고르게 나눠 배분하고, 남는 금액이 그 구간의 **주요 노드 구매비**가 된다. 최종 합산 `ΣS = 900`이므로 직업별 비용은 정확히 불변이다.
- 구간별 큰 주요 노드를 획득하기까지는 SP 저축이 필요하다. 초반 최소 1SP 소형 강화가 가능하도록 설계했지만, 원본의 1랭크씩 곧바로 강화 가능한 성장감과 차이가 있으므로 Lv5/10/25/100 실전 테스트에서 조정한다. SP 900 맞춤만으로 밸런스 완료를 주장하지 않는다.

## 7. 경로와 전용 스킬트리 화면

**화면은 더 이상 3개의 고정 세로 카테고리 열이 아니다.** 중앙에서 3개 큰 계열이 서로 다른 방향으로 뻗어 나가며, 각 계열 아래 기존 스킬들의 여러 가지가 **서로 갈라지고 작은 노드 가교로 연결되는 방사형 대형 지도**다.

- 중심점과 3개 계열 입구는 무료 안내 지점이며 구매 노드가 아니다. 각 계열 내부 기존 스킬마다 별도 성장 가지를 갖는다.
- 선의 굵기·색·밝기는 미투자/진입 가능/취득 완료를 구분한다. 평면 직선 연결 외에 유효한 가지와 가교가 보이도록 한다.
- 일반 능력치 노드 = 작은 원형 또는 원석, 기존 효과 구간 주요 노드 = 큰 직업 고유 아이콘, 구 돌파를 포함하는 주요 노드 = 한 단계 큰 프레임. 구매하지 않은 효과는 획득한 것처럼 표시하지 않는다.
- 다른 가지의 작은 노드로 이어지는 가교는 **소형 보정 접근 경로만 추가**한다. 주요 스킬 후반 구간의 선행 단계를 건너뛰게 해서는 안 된다.
- 트리 전용 배경은 **밤하늘·고대 성좌/희미한 지형 원경처럼 읽기 쉬운 지도형 공간**으로 제작한다. 프로필·직업 관리의 기존 보라색 벽지/금속 틀을 화면 전체에 복제하지 않는다. 화려한 과광 효과보다 노드 대비·가독성을 우선한다.
- 영역 이동(빈 공간 드래그), 확대/축소(마우스 휠), 현재 트리 전체 맞춤 보기, 선택 노드 위치 복귀, 상세 설명 고정 영역을 지원한다. 상세 영역은 누적 수치·현재 효과·다음 구매 가격·서버 응답을 표시하고 노드 위치와 분리한다.
- 16:9·16:10·4:3 / GUI Scale 2·3·4, 한글·영어, 클릭 판정, 드래그/줌 범위 제한, 텍스처 스케일의 **9-slice 또는 개별 코너/변 분리 렌더링**을 실제 Minecraft에서 검사한다. 기존 스크린샷의 외곽 아틀라스 깨짐과 텍스트 겹침을 방치하지 않는다.

### 세 계열의 이름

- **정신 지배자:** 장악 / 결속 / 간섭
- **인형술사:** 조립 / 운용 / 전투
- **기생술사:** 침투 / 공생 / 생존

## 8. 저장 마이그레이션 (반드시 구현 전에 검증)

현재는 직업별 9~10개 정수 랭크를 기존 `SavedData`에 저장한다. 신규 노드는 수십 개이므로 기존 월드를 단순히 새 길이 배열로 읽으면 **SP 소실 또는 중복**이 생길 수 있다.

1. **원래 각 스킬에서 완전히 구매한 구간만** 새 주요 노드+해당 소형 노드를 전부 구매 상태로 변환한다.
2. 마지막으로 부분 투자한 구간의 기존 소비 SP는 해당 직업의 미사용 SP에 **전량 환급**한다. 원래 부분 효과는 신규 구간 주요 노드로 부여하지 않는다.
3. 완성 구간의 새 노드 총비용은 원래 랭크 구간 비용과 동일하므로 `기존 남은 SP + 기존 소비 SP = 새 남은 SP + 새 소비 SP`를 보존한다.
4. 변환 버전·중복 수행 방지·크래시 중 저장 원자성을 보장한다. 과거 백업이 없더라도 기존 데이터는 복구 가능하게 하고, 계약/BD/인형/군체/장비·원본 RPG 레벨/XP는 변경하지 않는다.
5. **부분 랭크 환급**은 사용자 체감 변화를 수반하므로 실제 도입 전 명시적으로 검수한다. 최초 개발 빌드만 대상으로 할지 기존 월드 전체에 적용할지도 구현 시 명확히 한다.

## 10. 명시적 노드·연결 좌표 설계 (추가 검증)

[**경로 그래프 전체 좌표·연결선 JSON**](./ui/SKILL_TREE_GRAPH_LAYOUT_V1.json)은 위 비용·단계 모델에서 생성한 **원본 6직업 총 581개 구매 노드**의 위치와 연결을 모두 명시한다. 각 직업은 중앙 무료 시작점과 계열별 무료 내비게이션 허브를 거쳐 기존 스킬들의 방사형 가지로 뻗는다. 같은 계열의 이웃 가지는 중간 작은 스탯 노드끼리 실제 가교로 연결한다. 가교는 특수 노드의 기존 순서 선행을 우회하지 못한다.

- 6직업 모두 중앙에서 모든 노드가 연결되어 있음을 그래프 탐색으로 확인했다. 각 노드의 구매비 합은 정확히 **900SP**, 구간 주요 노드의 부모 스킬·원래 랭크 구간·기본 선행도 확인했다.
- GUI 실제 좌표는 월드 단위로 저장했으며 렌더러에서 확대/이동 변환을 적용해야 한다. 이는 **배치 데이터의 산술 검증**이지 실제 Minecraft UI 렌더링·글자 겹침·상용 수준 시각 품질 검수가 아니다.
- 연결만 있다고 모든 주요 노드가 구매 가능한 것은 아니다. 주요 노드의 `requires_previous_major`와 `requires_stage_minors`를 서버가 함께 검사한다. 소형 스탯 노드의 가교 접근은 가능하지만 기존 스킬의 상위 단계를 건너뛸 수 없다.
