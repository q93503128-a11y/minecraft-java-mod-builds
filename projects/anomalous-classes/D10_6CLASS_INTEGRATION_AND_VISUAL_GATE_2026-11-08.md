## 4. 시안 착수/승인 게이트를 분리

### VISUAL CONCEPT READY — 조건부 통과

1. [UI/연출 제작 기준](./ui/D10_UI_VFX_PRODUCTION_BRIEF_V1.md)의 **정보 계층/화면 상태·배치 UX**를 시안의 유일한 최신 입력값으로 사용. 기존 4화면 HTML은 흐름 구조의 자료이지 최종 미술 언어 아님.
2. **첫 세 화면**: 직업 선택(8명단 중6 상세/2 보류 표시를 인게임 사용성 최종 확정과 구별) → SP·스킬트리·직업 전용 매개체(특정 직업마다 9/10노드) → 실제 플레이 HUD(바닐라 핫바/체력/허기 보존). 네번째부터 직업별 부하/결계/계약/군체 관리.
3. 상용 게임 정보 계층은 **학습만** 하고 원본 UI 아이콘/텍스처/로고/3D 모델은 복사하지 않는다. 레퍼런스/사용 조건을 문서에 기록.
4. 스킬/VFX는 실제 서버 판정·피격/사거리/대상 개수와 일치해야 하며 수치가 미결정인 장면에는 테스트용 텍스트로 구분. 모델/사운드/애니메이션/프레임타임/GUI Scale은 화면 실측 단계에서 검사.

### GAME IMPLEMENTATION READY — 아직 미통과

- 월드 생성·소유권·자원 소비의 서버 상태와 UI 명령 요청/응답 계약, 초기 SP/회수 정책·활성 기술 전체 전달/로그인 데이터, NeoForge/외부 종속 모드 실제 동시 부팅·실시간 렌더링/원본 외부 몬스터 어댑터 및 GameTest가 필요하다.
- UI만 원형 사각형으로 만들어 compile 성공을 품질 성공으로 표시하지 않는다.
- 다음 중요한 의미 단위의 구현은 **기초 직업 선택/전환→서버 상태 읽기→성장 SP 투자→실제 HUD** 같은 유효한 단일 흐름과 실제 Minecraft 화면 검수로 시작. 그 전에 UI/스킬 디자인 시안 승인 선행.
