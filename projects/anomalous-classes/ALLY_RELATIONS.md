# 아군 판정 및 인형 피아식별 계약 (초안)

> 2026-11-04 / **게임 플레이 규칙: 사용자 피드백 반영, 기술 구현 방식: 제안**. 인형술사는 인형이 주인/같은 팀 플레이어/같은 팀의 다른 소환물에 **피해를 주지도 받지도 않도록** 설계한다. 다른 직업과 외부 몬스터 모드가 공존하는 서버에서 서버 권위 판정이 필요하다. 아직 Minecraft 버전/로더는 미정.

## 2026-11-06 최신 상위 결정 — PvP는 서버 설정을 따른다

**D06 사용자 확정:** 서버 PvP=true일 때 적대 플레이어에게 직업 공격·일반 CC 적용 가능, PvP=false이면 소환체·지배체·숙주·광역/반사 피해를 포함한 **플레이어 대상 모든 가해 효과 차단**. 양쪽에서 **기존 같은 팀/아군 인형의 양방향 보호**는 유지하며, 일반 몬스터 대상 PvE와 자기 보호는 정상 작동한다. 타인의 카메라·입력/인벤토리를 빼앗는 **플레이어 직접 지배/기생은 자동 허용되지 않음**. 상세 서버 권한, 상태이상·지연 투사체·소유권 판정 및 미실행 QA는 [공통 PvP 정책](./PVP_SERVER_AUTHORITY_POLICY_V1.md)을 따른다. 이 문서 아래의 초기 '로더 미정'이나 기타 예전 설명은 당시 기록이다.

## 외부 기준

- [Minecraft Wiki: Scoreboard](https://minecraft.wiki/w/Scoreboard): Java scoreboard **team**은 플레이어와 엔티티를 그룹화하고 `friendlyFire`를 지원한다. **scoreboard tag**는 개체에 문자열을 붙여 선택/검색하는 별도 기능이며 팀 관계 판정의 단독 근거가 아니다.
- [Minecraft Wiki: /team](https://minecraft.wiki/w/Commands/team): `friendlyFire`는 플레이어 피해나 일부 엔티티 예외에 주의가 필요하며, 투사체/포션 등의 특수한 행동이 모두 막히는 것은 아니다. 각 모드의 커스텀 피해는 별도 연동이 필요하다.
- 이미 설치된 팀/파티 모드 또는 바닐라 scoreboard team을 사용하는 플레이어가 있을 수 있다. 사용자 관리형 팀을 임의로 삭제하거나 다른 모드의 기존 팀을 덮어쓰지 않는다.

## 플레이 규칙

1. **소유자**와 소유자의 모든 **인형**은 서로 우호적이다.
2. 서로 다른 플레이어라도 **서버에서 같은 편으로 인정되는 팀/파티**이면 서로 우호적이다. 같은 팀 플레이어의 인형, 지배 생명체, 군체, 기타 해당 모드의 통제형 소환물도 우호 그룹에 포함한다.
3. **우호적인 인형 ↔ 같은 팀 플레이어/소환물** 사이에는 양방향으로 **직접·간접 피해와 적대적 상태 효과를 차단**한다. 인형은 아군을 AI 공격 대상으로도 선택하지 않는다.
4. 인형은 **적대 생물 또는 대립 관계 플레이어/소환물**에 정상 공격한다. 플레이어 간 피해는 서버 PvP 설정과 기존 권한을 따른다.
5. 모든 종류의 다른 아군 생명체까지 전역 무적화하는 규칙을 만들지 않는다. 정신 지배자의 `player_damage_allowed` 토글과 충돌하면 **인형이 행위자/대상으로 포함된 쌍에서 인형의 우호 피해 차단이 우선**한다. 단, 팀 플레이어가 지배체를 직접 공격하는 행위에는 기존 지배체 토글을 그대로 적용한다.
6. 차원·언로드·로그아웃·소유자 사망 후에도 소유권/팀 ID를 올바르게 복원하고, 팀을 탈퇴하면 그 이후 피해 판단에 즉시 반영한다. 소유자 정보가 일시 미해결이면 아무에게나 공격을 허용하지 않는 보수적인 상태로 둔다.

## 식별 데이터 및 서버 경계 (권장 구조)

- 인형/지배체: `ownerPlayerUuid`, `controlledEntityUuid`, `controlledKind`, `lastResolvedTeamId`(캐시), `dataVersion`, 필요 시 원본 관계 정보. owner/team의 진실 데이터는 서버에서 조회한다.
- 플레이어: `playerUuid`, `currentPartyOrTeamId` (기존 파티 API 또는 scoreboard team에 대한 검증된 **어댑터**로 읽는다; 같은 팀 관계의 절대 근거로 임의의 문자열 태그를 신뢰하지 않는다).
- 공용 서버 함수: `isAllied(actor, target, context)`와 `canDamage(source, victim)`을 명확히 분리한다. DamageSource에서 **근원 개체(발사자/시전자), 직접 개체(화살/소환 투사체)**, 피해 소유자와 실제 타깃을 확인한다.
- 구현 1순위: 자체 서버 관계 레지스트리 + 관계 해석기. 외부 scoreboard/party API와의 매핑은 옵션으로 하고, 없는 서버에서는 **주인과 자신의 인형·소환물만 우호**로 처리한다. 바닐라 scoreboard 팀 속성이 있으면 **읽어 관계 판정의 입력**으로 사용하되 플레이어/인형의 다른 모드 팀을 무단 변경하지 않는다.
- 일반 엔티티 태그(예: `anomalous_puppet`)는 **시각 표시/검색 최적화 용도**, 소유권·팀·피해 권한을 입증하는 데이터가 아니다. 클라이언트가 임의로 보낸 태그/팀 ID로 아군 판정을 변경할 수 없어야 한다.
- 개체별 공격 타깃 선택, 근접 피해, 투사체, 폭발, 광역 기술, 지속 피해·상태 효과, 반사 피해, 마운트·도구·미끼 엔티티, 다른 모드 커스텀 DamageSource에서 동일하게 관계를 적용한다. **물/용암/낙하/적의 공격 같은 환경 및 적대 피해는 정상**이다.
- 실제 서버에서 접근 가능한 DamageSource/API로 가로챌 수 없는 타 모드의 특수 피해는 **호환 어댑터와 게임테스트** 대상이다. 지원 범위를 검증하기 전에 모든 외부 모드 공격에 100% 무적이라고 주장하지 않는다.
- 적대 관계의 모호함: 팀 없는 일반 몬스터는 기본 적으로 판정할 수 있지만, 중립 주민/가축은 주인이 명시적으로 지정하지 않는 한 표적에서 제외하는 보호 방향을 검토한다. 다른 플레이어 소유의 길들인 생물은 PvP/팀 정책으로 처리한다.

## 피아식별 테스트 케이스 (미실행)

| 상황 | 기대 |
|---|---|
| 주인이 인형을 때림 / 인형이 주인을 공격함 | 피해·적대 디버프 모두 차단 |
| 다른 팀원이 인형을 근접·활·광역기로 공격 | 인형에게 피해·적대 디버프 없음 |
| 인형이 팀원의 철 골렘 / 정신 지배체를 공격 | 유효 표적에서 제외, 간접 피해 차단 |
| 정신 지배체 `player_damage_allowed=ON` | 팀원의 **직접 공격**은 기존 토글대로, **아군 인형 공격**은 아군 인형 규칙으로 차단 |
| 인형 투사체 폭발이 적과 아군을 함께 덮음 | 적에게만 피해, 아군에 해로운 효과는 제외 |
| 스코어보드 팀이 없고 파티 시스템도 없음 | 소유자-자기 소환물 우호, 서로 다른 독립 플레이어는 임의 아군 처리 안 함 |
| 팀 가입/탈퇴 또는 플레이어 사망·재접속 | 현재 서버의 팀 관계가 반영, UUID/소유권 지속 |
| 외부 몬스터 모드 커스텀 피해 / 소환체 공격 | 서버 피해 소유자 추적 가능한 범위에서 차단 검증, 미지원은 명확히 보고 |
| 인형이 용암·추락·적대 보스에게 피해 | 정상 피해 |
| 관리/데이터 업데이트 중 원본 팀 어댑터 오류 | 임의로 타인에게 피해를 허용하지 않고 오류 진단 |

## UI와 개발 책임

- HUD/관리 화면은 팀 아이콘/색상, 연결된 인형의 소유자, 타깃 지정 가능/불가 이유를 표시할 수 있다. **아군 판정의 실제 성공은 서버가 결정한다.**
- UI 구현을 맡는 Codex가 자체적으로 소유권·`isAllied`·피해 권한 판정 로직을 만들지 않는다. UI가 서버 상태를 읽고 요청만 보내도록 데이터 모델 계약을 선행한다.
- 세부 팀 식별(파티 앱 연동 vs 바닐라 scoreboard, 팀 무소속 동작)과 다른 직업의 비전투 동료 정책은 추후 서버 및 모드팩 구성 결정 후 확정한다.
