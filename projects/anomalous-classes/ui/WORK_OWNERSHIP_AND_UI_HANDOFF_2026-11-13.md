# 이능 직업 서바이벌 — 게임 시스템/UI 제작 역할 분리 (2026-11-13)

> 이 문서는 사용자가 재확인한 작업 분담을 이 프로젝트에 적용한다. 이전 Codex 통합 구현 프롬프트에서 게임 시스템까지 Codex에 맡긴 부분은 더 이상 유효한 작업 지시가 아니다. 기존 결과물을 무단 삭제·되돌리지 않고 현재 `main`에서 이어간다.

**최신 사용자 UI 정정:** [실게임 관리·장비 슬롯 수정 정본](./CLASS_MANAGEMENT_CORRECTIONS_2026-11-13.md) 우선. UI는 직업별 기능만 관리하고 프로필/스킬트리를 중복하지 않으며, 장비는 Minecraft 인벤토리 전용 슬롯에서 장착한다.

## 소유권 및 책임

| 담당 | 책임 | 금지/경계 |
| --- | --- | --- |
| ChatGPT (게임 시스템 담당) | 직업별 게임 규칙, AI·전투·성장·밸런스, 엔티티, 서버 권위 서비스, 데이터·저장·이관, 관련 서버 네트워크 계약, 회귀 검증 및 실제 게임 기능 개발 | Codex가 새 게임 메커니즘을 만들었다는 이유로 검증 없이 완료 승인하지 않음 |
| Codex (UI/UX 담당) | 시안과 기존 UI 아트의 고품질 실제 구현, 텍스처·레이아웃·애니메이션·상호작용, 반응형 화면, 번역·툴팁·버튼, 기존 서버 계약에 따른 화면 조회·명령 연결, 시각 검수 | 서버 AI/전투·소환·경제·정신력·저장/소유권·밸런스·신규 아이템/레시피를 임의 구현·변경하지 않음 |

- Codex가 UI를 연결하는 과정에서 기존 서버 payload/서비스에 변경이 필요하면 **필요한 필드·명령·검증 계약을 먼저 식별해 ChatGPT 담당 작업으로 남긴다**. 서버 권한을 우회하는 임시 패킷/가짜 백엔드/하드코딩된 게임 상태를 만들지 않는다.
- ChatGPT는 구현한 서버 기능의 실제 상태·데이터 스키마·행동 명령을 Codex가 화면에 연결할 수 있도록 명세한다. 이미 만들어진 기능을 역할 오류 때문에 버리지 않는다.
- 디자인·기능 작업은 **병행 가능**하다. 다만 백엔드가 없는 직업의 버튼이 실제로 작동하는 것처럼 노출되어서는 안 된다.

## 적용 대상과 실제 상태

- 프로젝트: `projects/anomalous-classes/`. 현재 실제 구현 판정은 최신 `main`의 소스 및 `BUILD_AND_RUNTIME_REPORT.md`로 확인한다.
- 공통 관리 허브와 30종 매개체/실제 제작법/장착 UI가 구현되어 있다. 실제 매개체 전투 효과는 일부만 연결되었으며 여섯 직업 전체 완료가 아니다.
- 정신 지배자 서버 동작/전용 관리창이 2026-11-13 기준 구현되어 있지만, **CLIENT TESTED / PLAYTESTED / MULTIPLAYER TESTED = NO**. 코드 작성/정적 테스트만으로 게임 완성이라고 표현하지 않는다.
- 인형술사·기생술사·결계술사·계약술사·군체술사 고유 관리 기능은 서버 구현 전이다. UI 아트/레이아웃 디자인은 먼저 진행 가능하지만 미구현 기능의 가짜 인게임 버튼/데이터는 불가하다.

## Codex UI 작업 계약

1. 이전 7개 시안 ZIP의 이미지를 재확인한다. 첫 두 장은 회화적 아트 컨셉, 나머지 다섯 장은 주로 **레이아웃 와이어프레임**으로서 최종 미술 품질이 아니다. ZIP 내 과거 `CODEX_PROMPT.md`의 서버 게임플레이 구현 명령은 이 문서의 역할 분담으로 대체한다.
2. `ui/CLASS_MANAGEMENT_UX_PLAN_2026-11-12.md`와 현행 UI 리소스를 따른다. **기존 외곽 장식 프레임은 변경하지 않는다.**
3. 우선 실제 서버 상태가 있는 **정신 지배자**의 `MentalDominatorScreen`을 실제 고품질 2열 목록·상세 화면으로 마무리한다. 데이터, 서버 검증, NPC 명령의 의미를 수정하지 않고 시각 설계와 조작 흐름만 고친다.
4. 이후 나머지 직업의 차별화된 UI 에셋·레이아웃·상태별 디자인을 제작한다. 서버 기능이 없다면 정적 리뷰 아트/테스트 렌더러로 작업하고, 인게임 동작처럼 꾸민 임시 연결은 만들지 않는다.
5. 공통 매개체 제작법 화면은 기존 실제 레시피 데이터와 연결을 유지한다. 바뀌지 않은 30개 제작식/장착 규칙은 보존한다.
6. 한국어/영어, 16:9·16:10·4:3, GUI Scale 2·3·4의 텍스트/버튼/목록 스크롤을 실제 Minecraft 화면 기준으로 확인한다. Java2D 정적 이미지는 GPU 플레이 검수로 간주하지 않는다.
7. `M` 프로필, `J` 스킬트리, `U` 관리, 삭제된 `K` 직업선택 단축키 상태, 기존 페이지 이동/소유권 결과 처리를 변경하지 않는다.
8. 관련 없는 서버 상태/밸런스/AI 코드는 수정하지 않는다. 수정이 불가피하다면 작업을 멈춰 인터페이스 요구를 보고하고 ChatGPT가 담당하게 한다.

## 검증 및 완료 판정

- **UI 완료:** 실제 Minecraft에서 모든 제공 상태의 화면/입력/가독성/스크롤/서버 응답이 정상 확인되어야 한다.
- **게임 기능 완료:** ChatGPT의 서버 코드 검증과 실제 게임플레이 테스트가 별도 필요하다.
- 정적 렌더, 컴파일, JAR 생성, 클라이언트 실행, 실제 인게임 화면 조작, 멀티플레이는 서로 다른 단계로 기록한다.
- 게임과 UI를 한 번에 대규모 재설계하거나 기존 구현을 삭제해 빌드만 통과시키지 않는다.
