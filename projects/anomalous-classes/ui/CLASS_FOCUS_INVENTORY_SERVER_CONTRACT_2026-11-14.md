# 직업 매개체 인벤토리 슬롯 — 서버 계약 및 상태 (2026-11-14)

> 기존 [직업 매개체 장착 슬롯 정본](../CLASS_FOCUS_SLOT.md)과 [UI 수정 정본](./CLASS_MANAGEMENT_CORRECTIONS_2026-11-13.md)을 따름. **서버-side 첫 구성 요소 / 전체 인벤토리 통합은 아직 미구현.**

## 구현된 첫 단계

- `state/ClassFocusEquipmentContainer.java` 는 플레이어별 **단일 `Container` 슬롯**을 제공한다. 실제 저장 원천은 **기존 `PlayerClassProfile.equippedFocus()`**이며 별도의 복제 저장소를 만들지 않는다.
- 현재 직업과 맞는, 실제 등록된 매개체 아이템 **1개만 삽입 가능**하다. 다른 직업의 기존 장착 매개체는 잃지 않고 볼/회수할 수 있어야 한다.
- `removeItem` / `removeItemNoUpdate` / `setItem` / `clearContent`는 기존 프로필 revision 증가 및 SavedData dirty 처리를 사용한다.
- 현재 30종 매개체는 `ClassFocusItems`가 생성한 단순 ID 기반의 비중첩 아이템이며, 기존 저장 데이터가 그 ID를 나타낸다. 기존 월드의 `equippedFocus` 스키마를 바꾸지 않았다.
- 기존 매개체 관리 화면의 버튼과 서버 핸들러는 사용자 장착 기능을 잃지 않도록 **변경하지 않았다**.

## 남은 핵심 백엔드 (ChatGPT 담당)

1. 실제 바닐라 플레이어 `InventoryMenu`에 슬롯을 추가할 수 있는 **동일한 서버/클라이언트 메뉴 구성**을 선택·검증한다. 서버는 위 `Container`, 클라이언트는 동기화용 1슬롯 컨테이너를 사용한다. 기존 메인 인벤토리/갑옷/보조손/2×2 제작칸/다른 모드와의 상호작용을 보존한다.
2. `Slot`의 삽입/제거/커서 스왑/Shift+Click/숫자키 교체/Q 버리기/드래그/더블클릭/Creative를 포함하여 서버 권위 원자적 거래를 검증한다. 불법 아이템, 악의적인 패킷, 새 세이브/구형 세이브 및 컨테이너 재접속을 포함한다.
3. 바닐라의 사망 드롭 및 `keepInventory` 정책과 인벤토리 복제·유실 방지를 실게임/전용 서버에서 검증한다.
4. 서버 인터페이스를 UI 담당 Codex에 넘긴 후, Codex가 **바닐라 인벤토리 안에** 하나의 전용 슬롯을 시각적으로 표시한다. 이때 기존 별도 제작법 화면의 장착/해제 버튼을 읽기 전용 제작법 조회로 교체한다.

**중요:** 이 파일 하나를 추가했다고 사용자가 인벤토리에서 매개체를 장착할 수 있는 것은 아니다. 게임/클라이언트/멀티플레이 테스트는 미실행이다. 실제 NeoForge 전체 Gradle 빌드 결과도 아직 확인 전이며 CI 결과가 나오면 별도로 보고한다.
