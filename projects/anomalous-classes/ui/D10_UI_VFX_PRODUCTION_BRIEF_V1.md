## 2. 전투 HUD: 게임 세계를 가리지 않는 정보 우선순위

- **L0 항상**: **바닐라 HP/허기/핫바/XP/오프핸드/조준점**은 원래대로. 직업 HUD가 기본 UI 요소를 가리거나 강제로 숨기지 않음. 실제 인게임에서 중요한 몹의 신체·공격 예고·바닥 범위가 항상 보이도록 중앙 시야/크로스헤어 주변 과밀 금지.
- **L1 항상/작게**: 현재 직업·현재 Lv / 자원이 있는 경우 *그 직업의* 핵심 자원(정신력/숙주 상태/군체 N/결계 수 등) / 준비된 직접 액티브의 **실제 키+쿨다운**. 본체 클래스 HP와 바닐라 HP 중복 대형 게이지 금지. 실제 서버 상태값과 화면 수치 일치.
- **L2 관련 문맥에서만**: 조준 적의 적법 여부·침투 진행/실패, 부하 목표, 결계 미리보기 유효/불가, 새 계약 제물 확인/서약 위험, 군체 비행 중 실제 분담, 계승 모드 ON일 때 1~0 기술 페이지. 평시 직업 전체 하위 메뉴를 HUD에 항상 띄우지 않음.
- **L3 사용자가 관리 화면을 열었을 때만**: SP 상세/노드별 비용·나머지 재료·모든 계약과 금기/지배체 전원·인형 전체 제작 데이터/기생 전체 계승기 목록/군체 저장 전술 편집. 특히 16계약/48자동패시브를 항상 HUD로 쌓지 않음.
- 모든 실패/제한을 **짧은 이유+즉시 회복 가능한 행동**으로 통지(예: '대상이 범위 밖에 있습니다', '계약 제물이 부족합니다', '군체가 부족합니다'). 플레이어에게 P0/P1/debug/alpha/dev 같은 제작 내부 용어를 노출하지 않음.
- 공격 예고·직접 스킬 범위·명중과 실제 서버 데미지가 일치. HUD VFX·사운드는 사용자가 화면 흔들림/과도한 화면 효과를 줄일 수 있는 설정 후보 검토. 플레이어의 아군/지배체/인형이 타격 대상일 때 피아식별 표시 정확성 우선.

## 3. 제작할 첫 세 화면 — 상태/동작/가독성

### S1. 직업 선택 / 변경 화면

**목표:** '다음 30시간의 전투 방식이 무엇인가?'를 플레이어가 **대표 행동**으로 이해한 뒤 선택. 서사 설명이나 스킬 목록을 한눈에 모두 보여주려고 작은 카드 수십 개를 늘어놓지 않음.

- 목록 범위: 8직업 이름은 프로젝트 정본에 존재. 상세 대상 6직업만은 자체 능력의 사실·예시를 표시. **중력/공명은 기획 보류**이므로 이 단계에서 플레이 가능한 것처럼 거짓 시연/버튼 제공 금지. 실제 출시 시 8직업 노출·보류 직업 접근 정책은 별도 검수.
- 현재/비활성 직업 각각의 **서버 실제 Lv/SP/영구 성장 기록** 표시. 진행 중 캐릭터가 전환 시 처음부터 재육성된다고 오해하지 않게 보존 안내.
- 상태: `not_selected` / `current` / `previously_played` / `first_time` / `combat_locked` / `server_rejected` / `not_available`. 비전투 중 월드 어디서나 클래스 전환 가능, 전투 중 버튼 비활성의 사유 명확히 표시.
- 전환시 계약·숙주/지배체·인형·군체/결계의 **전환 전 안전 처리** 및 장착한 직업 매개체 비활성/복원 정책은 [클래스 생명주기](../CLASS_SWITCH_LIFECYCLE_POLICY_V1.md)의 서버 상태를 읽는다. UI가 소유 엔티티를 직접 삭제하거나 바닐라 아이템을 소멸시키지 않음.
- 첫 6직업의 대표 연출: 정신=적 정신 간섭→원본 생물 지휘, 인형=실이 이어진 실제 3D 인형, 기생=인간형→숙주 카메라/몸 전환, 결계=실제 지형에 독립 결계, 계약=한 상대의 강력한 가호와 현현 기운, 군체=0.2블록 유효 생물 무리의 진형/엄호/비행. **스킬 이펙트 색/모델/물리 타격은 독립 샘플로 연구**.

### S2. SP·패시브/직업 장비 화면

- 공통 구조: 현재 직업·Lv·서버 보유 SP·매개체 장착 등급과 효과 / 3개 고유 계열 / **실제 노드 9~10개** / 선택 노드의 현재랭크·최대랭크·다음 랭크 효과·서버 검증 가능 비용. Lv300이라 300랭크가 자동으로 모두 열리는 것으로 묘사 금지.
- 정신 270랭크, 인형 290, 기생 285, 결계 300, 계약 270, 군체 270은 **기존 기획의 비교값/후보**다. 270~300개의 개별 아이콘을 그리지 않음. SP 투자 행동은 실게임 정책 확정 후 서버 적용/원자적 차감. 초기 SP/초기화/환불 비용은 사용자 확정 전 가짜 버튼·가격 제공 금지.
- 계약술사 **48계약 귀속 자동 패시브**는 공통 패시브 트리의 별도 SP 노드가 아니라 '현재 계약 정보/고유 효과'로 구분. 계약 체결 여부·심화/관계에 따라 서버 읽기 상태로 제공.
- 직업 매개체 **1전용 슬롯**, 등급 규격/변조/변칙/이형/불가해는 사용자 확정 재료/효과와 일치. 기존 1~5등급 **30개 일반 3×3 제작대 제작식**은 인벤토리/레시피북/JEI에 자연스럽게 연결, 상위 장비를 메뉴에서 공짜 업그레이드하는 가짜 버튼 없음.
- 각 행동 상태: `available` / `insufficient_sp` / `capped` / `locked_condition` / `pending_server` / `success` / `server_rejected`. 잠겨 있는 이유를 보여주되 확정되지 않은 선행 조건/비용을 창작하지 않음.

### S3. 인게임 HUD / 직업별 문맥 상태

- 16:9 화면 크기/서버 GUI scale 2~4를 기본 테스트하되 16:10/4:3, 창모드, FOV 변화, 상태이상/보스바, 고해상도 텍스처·일반 채팅·JEI 겹침 전부 검증.
- 퀵슬롯 기본 표시=**실제 직접 액티브/등록 키/쿨다운**. 6직업에 동일 6개 필수 스킬 버튼을 만들어 빈 버튼/쓸데없는 카드 나열 금지. 인형/군체 R은 무료 표적 지정이라 무의미한 쿨다운/버프바로 표시 금지.
- 플레이 상황: `peaceful_mining`, `single_enemy`, `six_enemies_ranged`, `boss_cast`, `inventory_open`, `chat_focused`, `dead_or_respawning`, `reconnecting`, `class_switching`, `ability_invalid`. 마지막 상태가 안전하게 초기화되지 않으면 입력 중복/바닐라 핫바 이탈 발생 위험.

## 4. 6직업 전용 UX 인수 시나리오 — 실제 화면 이벤트 상태

| 직업 | 화면을 보고 즉시 이해해야 할 것 | 이벤트 시퀀스 1~4 |
|---|---|---|
| 정신 지배자 | **지배 가능한 대상/집중 진행/현재 유지비/계약 아닌 소유** | 적 조준→침투 진행→원본 생명체 소유 등록→동행·대기·해제. 서버 실패/사거리/대상 상태가 HUD와 맞음 |
| 인형술사 | **전개 실제 개체·손상도·수리 비용/인형 조종** | 인형제작대 조립·3D 실루엣 미리보기→전개→R 무료 표적→전투 후 응급 접합/제작대 수리·부품 교체/분해 구분 |
| 기생술사 | **내가 현재 어떤 숙주인지, V 계승 모드인지** | BD자격 확인→침투→종 원래 몸 조작→V ON 1~0=실제 배운 계승기, V OFF=바닐라 핫바. 숙주 죽음/인간형 배출·재기생 상태 정확 |
| 결계술사 | **미리보기는 아직 설치가 아님** | R 1회 반투명 조준 범위→Z/X 편집→R 2회 설치/서버 확인→G 마지막 성공 종류·크기 즉시 설치. 증폭은 그 순간 유효한 자기 결계 **전부** |
| 계약술사 | **계약 하나만으로 강한 전투, 위험·제물은 별도** | 현재 계약1의 가호/3자동패시브→Z/X 기본 액티브→2/3번째 제물 상세·확인→다음 계약 직접 키/추가 페이지. 계약 현현/파기는 높은 비용·별도 확인, 일반 액티브가 아님 |
| 군체술사 | **실제 N이 공격/엄호/비행에 어떻게 쓰이나** | 사용자 직접 이름 붙인 전술 만들기→G 빠른 전술 화면 후보에서 즉시 전환/비율 편집→R 적 지정→N 실제 손실/재증식→비행시 운반 N 예약·안전 하강. 고정 4전술 제공 금지 |

**직업별 조작 조건:** 정확한 V/R/G/H/M 물리키·GUI 내 활성 콘텍스트 일부는 [D09 최신 헤더](../D09_DIRECT_SKILL_KEYBIND_AND_CLASS_COMMANDS_V1.md) 우선. **결계 R 두 단계**, 기생 V 1~0, 군체 기존 탭/홀드 폐기는 이미 정해진 원칙. M은 유망한 통합 메뉴 후보지만 직접 승인된 최종 기본키로 주장 금지.

## 5. 실제 디자인 시스템을 만드는 절차 (임의 네모 UI 금지)

1. **레퍼런스 구조 분석:** 위 상용/실게임 자료에서 유효 정보 계층/안전한 취소·확정·랭크 탐색/보스전 시야 처리를 분리 기록. 사용 허가 없는 아이콘·리소스·트레이스 텍스처 복제 금지.
2. **프레임/재질·색상 의미 정하기:** 직업 하나에만 어울리는 과도한 glow/그라디언트·검은 투명 네모 연발 대신 **전체 게임 공통 판독 가능한 프레임·상태 레이어·질감과 직업 정체성 차이**를 설계. 실제 플레이 스크린샷 위에서 먼저 검증. 구체 색 hex·픽셀·폰트/에셋은 **시각 원안 선택 후** 지정.
3. **유저 행동이 먼저:** 성공/실패/쿨타임/일시 봉인/피격/오프라인 등 최소 6상태가 화면에서 서로 구별. 텍스트만 길게 쌓거나 모든 상태를 색깔 하나로 구분하지 말고 모양/아이콘/짧은 문구/위치로 구분.
