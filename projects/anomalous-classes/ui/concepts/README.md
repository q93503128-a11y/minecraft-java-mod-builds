# 이능 직업 서바이벌 — 핵심 UI 구조 시안 v1

> **STATUS:** Concept / Wireframe only. **최종 UI 구현·디자인 확정·Minecraft 실행 화면이 아니다.** 2026-11-04. Codex에게 최종 UI 디자인·구현을 맡기고, 게임 시스템 코드는 이 프로젝트 작업에서 별도로 개발하는 역할 분담을 전제로 한다.

## 파일

- [STRUCTURAL_UI_V1.html](./STRUCTURAL_UI_V1.html) — 브라우저에서 열면 직업 선택 / 스킬 트리 / 지배체 관리 / 전투 HUD의 **4화면 구조 시안**이 보인다. 상단 메뉴로 전환.
- 브라우저 파일 끝에 `?screen=class`, `?screen=skills`, `?screen=manage`, `?screen=hud` 쿼리를 붙이면 해당 화면으로 바로 열 수 있다.
- HTML은 **정적 UX 레퍼런스**이고 Minecraft 클라이언트의 UI 코드가 아니다. 버튼은 화면 전환 이외에 게임 데이터를 변경하지 않는다.

## 화면별 역할 및 이유

1. **직업 선택**: 확정된 8직업 모두 노출, 상세 설명은 현재 완료된 정신 지배자만 표시. 인형술사 등 아직 기획 중인 직업의 미확정 공격 수치·난도는 창작해 넣지 않는다.
2. **스킬 트리**: 장악·결속·간섭의 세 계열이 한눈에 구별되어야 하며, 패시브 10개를 **270개 버튼으로 확장하지 않는다**. 노드마다 현재/최대 랭크, 다음 랭크, 다음 돌파까지의 조건을 보여주고 선택된 노드의 상세 설명에 충분한 폭을 준다. 다른 직업은 같은 UI 시스템을 쓰되 실제 트리 구조와 노드 수가 달라질 수 있다.
3. **지배체 관리**: 소유 개체 목록, 동행/대기, 플레이어 공격 허용 ON/OFF, 지배 해제, 개별/집단 유지비와 슬롯을 한 화면에 둔다. 개체 바라보고 관리키로 개별 관리, 대상 없이 관리키로 전체 화면을 연다는 제안과 호환되어야 한다.
4. **전투 HUD**: 바닐라 핫바/체력/허기를 대체하거나 가리지 않으면서 정신력, 현재 지배 수/유지비, 5개 액티브, 대상 장악도를 최소한으로 표시한다. 실제 게임 화면에 고정 위치 테스트가 필요하다.

## 레이아웃 의도와 Codex 인계 경계

- 16:9 데스크톱 시안을 기본 참고로 만든다. 실제 마인크래프트 GUI Scale 2~4, 해상도 16:9/16:10/4:3 및 작은 UI 사이즈에서 **재배치/스크롤/툴팁 지연** 등 별도 반응형 설계를 해야 한다.
- 색상/프레임/기하학/가상의 클래스 아이콘/가상의 몬스터 실루엣은 **초기 정보계층 확인용 플레이스홀더**이다. Codex는 참고한 상용 게임 UI와 프로젝트 기존 디자인 언어로 최종 그래픽을 새로 설계한다. 지금의 사각형 배치를 그대로 최종 아트로 제출하지 않는다.
- 실재 게임의 브랜드 UI, 아이콘, 스크린샷/텍스처를 가져다 쓰지 않는다. 원본 코드·리소스가 필요한 외부 자산은 라이선스와 제작자 정보를 먼저 기록한다.
- 새 직업 하나가 추가될 때 직업 선택·스킬 트리가 프로그램적으로 채워지도록 **데이터 바인딩**을 정의한다. Codex가 정신력·지배/스킬포인트/소유권을 자체 계산하지 않도록 서버 API(읽기 전용 UI 모델 + 행동 명령)를 나중에 별도 문서화한다.
- 지배체 공격 허용과 지배 해제 같은 중요 조작은 서버가 최종 검증. 이 HTML은 실제 행동을 수행하지 않는다.
- 예시 화면의 Lv100, 380/1071 정신력, 지배 3/6과 유지비 2.23/초 등 수치는 **기존 미확정 밸런스 공식을 설명하는 샘플**이다. 인게임/기획에서 최종 확정된 밸런스가 아니다.

## 인형술사 확장용 UI 계약 (2026-11-04 반영)

- 기존 **4화면 HTML 원본은 구조 시안으로 보존**한다. 인형술사는 정신 지배자의 3개 계열과 지배 목록을 그대로 복제하지 않고, 공용 선택창·스킬 화면 틀에 맞는 자체 데이터를 제공한다.
- 직업 선택 상세에는 **실 연결 마리오네트 제작/강화/분해** 정체성과 마리오네트 조종틀의 상징을 표현. 전용 장비 모양은 나무 십자 조종대에서 5등급에 따라 발전하되 핵심 실루엣 유지.
- 인형술사 관련 관리에서는 개체 ID/골격/행동 장치/구동핵/**현재 크기·실제 충돌 크기**/손상도/분해 재료 예상 반환량/전개 가능 수/동행·대기/팀 관계 확인이 필요하다. 소재별 재료·분해 규칙은 [인형 제작 경제 설계](../../classes/PUPPET_CRAFTING_ECONOMY.md)를 참고한다. 부품 **교체(기존 부품 그대로 반환)**와 부품 **분해(일부 원자재 반환)**가 화면/문구에서 혼동되지 않아야 한다. 메뉴가 복잡해지지 않게 **정비 시 세부 편집, 전투 시 표적 지정**으로 작업을 구분한다.
- 표적 지정은 **쿨타임 없는 기본 명령**, 유효한 적군만 우선 대상으로 선택. UI가 커스텀 쿨타임 바를 임의로 그려 넣지 않는다.
- 같은 팀 인형/플레이어/소환물의 쌍방 피해 금지는 [ALLY_RELATIONS.md](../../ALLY_RELATIONS.md)에 기술된 서버 권위를 따른다. UI는 아군/소유자/명령 성공·실패 여부만 표시.
- 새 [인형제작대 기획](../../classes/PUPPET_SCALE_AND_WORKBENCH.md)에 따라 **별도 인형제작대 정비 화면 1개**에서 실제 3D 몸체 크기 미리보기, 필요 구조 재료, 경량/중장 공속·크기별 HP·리치, 제작·개조·수리·분해를 제공한다. 기존 4화면 HTML 구조 시안은 변경하지 않는다.
- 인형의 눈에 보이는 실은 경량 클라이언트 렌더링/거리별 LOD를 검토하고, 성능을 무시한 Display Entity 수십 개 복제로 구현하지 않는다. 실제 16:9/16:10/비표준 GUI scale에서 시각 검수 필요.

- 인형술사 스킬 트리는 [PUPPET_SKILL_TREE.md](../../classes/PUPPET_SKILL_TREE.md)의 3계열/10노드/290랭크 구조 및 [돌파 기능](../../classes/PUPPET_MILESTONES.md)을 서버 모델로 표시. 오래된 정신 지배자 전용 270랭크를 복제하지 않는다.
- 조종틀 화면/툴팁은 [MARIONETTE_CONTROL_BAR.md](../../classes/MARIONETTE_CONTROL_BAR.md)의 5등급·승급 비용·효과를 읽기만 한다. **등급별 동시 조종 수 +1~+5기, 인형 공격력·최대 체력 % 증가만 표기**한다. 이전 시안의 명령 거리·반응/연결 특수 보너스는 표시하지 않는다. 최종 UI는 Codex, 비용·슬롯·장착·소유권은 서버에서 판정한다.

- 인형술사의 기본 명령(전개/회수, 무료 표적 지정)과 액티브 **실 견인/응급 접합/연계 구동**은 [액티브 및 자동 성장](../../classes/PUPPET_ACTIVES_AND_GROWTH.md)을 따로 읽어 표시한다. 정신 지배자 액티브 5개를 그대로 복제하지 않는다. 응급 접합은 서버가 계산한 **재료 비용·복구량**, 연계 구동은 **남은 버프 지속시간·재사용 대기·피해/공속 보정·적용 인형 수**, 실 견인은 실제 이동 가능 여부를 표시한다. 평시 자동 협공은 버프와 관계없이 그대로 동작한다.
- HUD 기본 숫자는 인형술사에선 마나 유지비가 아니라 **전개 수/최대 수, 현재 표적, 3개의 액티브 재사용 대기** 중심. 인형술사 스킬을 위해 새로운 정신력 바·유지 연료 바를 임의 추가하지 않는다.

## 기생술사 UI 확장 계약 (실숙주 기생 v7 / 2026-11-04)

- [현행 기생술사 숙주 기생·생체 데이터 기획](../../classes/PARASITE_MORPHER.md)에 따라 공용 직업 선택창에 **허약한 인간형과 실제 생물 숙주를 오가는 직업, 생체 데이터가 쌓여야 더 강한 숙주 기생 가능**이라고 설명. 기존 정신 지배자·인형술사 화면과 4화면 HTML 원본은 변경하지 않는다.
- 인간형/숙주 상태를 구분하고 HUD에는 **현재 숙주 종·실제 HP/상태·생체 데이터(BD) 영구 스탯·현재 종 숙련**을 과하지 않게 표시. [성장·최소 기생 요구량 시안](../../classes/PARASITE_BIODATA_GROWTH.md)에 따라 목표를 조준하면 **현재 BD/해당 종 최소 BD/기생 시도 가능 여부**를 명확히 보여준다. BD는 소비 게이지가 아니며 기생할 때 줄지 않는다. 기생체의 바닐라 인벤토리/레벨/장비와 숙주 기반 행동이 구분되어야 한다.
- [BD 활동 보상·종별 숙련·침투 집중](../../classes/PARASITE_BIODATA_ACQUISITION_AND_INTRUSION.md) 시안은 HUD에 **필요 시 BD 증가량을 작고 짧게 표시**하고, 종별 숙련은 현재 종 진행도와 **고유 기술/탐험/생존의 최초 숙련 보너스**를 한눈에 보여준다. 종별 숙련도 100은 타 숙주 계승 해금. 침투 중에는 대상·진행도·중단 사유를 보여준다. 별도 생체 화폐/경험치 상점 UI를 추가하지 않는다.
- **[숙주 사망/긴급 재기생](../../classes/PARASITE_HOST_DEATH_AND_TRANSFER.md)**: 숙주가 죽으면 허약한 인간형으로 튀어나오며, 기생술사 HUD에 **재기생 불능 남은 시간 또는 긴급 재기생 보유 횟수**를 간결하게 표시한다. 스킬 트리 '생존 전이' (가칭) 노드의 10/20/30랭크는 긴급 기생 +1/+2/+3회 후보, **긴급 시도도 최소 BD·침투 저항 조건을 우회하지 않음**. 숫자는 검증 전.
- 숙주 전환/기생 성공·실패 시 시선·카메라 높이·충돌박스, 호스트의 원본 AI/상태, 멀티플레이 소유권 전환 피드백을 안정적으로 처리하고, **숙주 죽음의 인간형 배출·정상 플레이어 사망을 구분**한다. 근처 대상 기생 가능 여부는 서버에서 판정한다.
- [285랭크 패시브 트리](../../classes/PARASITE_SKILL_TREE.md)는 **침투·공생·생존 3계열/10노드**로 표현하고, 랭크별 소폭 능력 및 돌파는 각 노드의 툴팁으로 제공. 특히 생존 전이의 **긴급 재기생 1/2/3회**를 정확히 설명. 아직 확정되지 않은 포인트 지급 속도/장비 스탯을 임의로 설계하지 않는다.
- [새 액티브 3종](../../classes/PARASITE_ACTIVES.md)은 **침투 고정(침투 방해 완화), 생체 수복(숙주 HP 회복), 본능 각성(공격·이속 상승/피격 위험 증가)**. 기본 기생 시도·숙주 해제/교체·숙주 종별 고유 기술은 별도 추가 액티브 키·슬롯이 아니다. 인간형에서 사용 불가한 기술은 비활성 상태를 정확하게 표시하고 HUD는 서버 지속/쿨타임 정보를 읽기만 한다.
- [완전 숙련 100 기반 종족 특성 계승](../../classes/PARASITE_TRAIT_INHERITANCE.md): **현재 숙주 선천 능력은 처음부터 사용**, **종별 숙련도 100에서 다른 몸으로 영구 계승**. 배운 모든 특성 사용 가능, 장착 한도 없음. **벽 타기·수중 호흡/이동 등 환경형은 쿨타임 없이 자동**, **엔더맨 투사체 회피 등은 조건형 자동 방어**, **크리퍼 폭발·광선·수동 순간이동은 직접 발동형**으로 구분. 능력 휠에는 **직접 발동형만** 넣고 최근 사용/즐겨찾기/편의 단축키로 관리한다. 30종 기술을 30개 키/패널로 늘리지 않으며 인간형에서 강한 종 기술 비활성.
- [공생 핵 5등급](../../classes/PARASITE_SYMBIOSIS_CORE.md): **현재 숙주 최대 HP·공격 피해 +5/10/15/20/25% 후보**만 표시. BD 기생 요구량/계승 기술 슬롯/생존 전이 충전 증가 등 장비에 없는 옵션은 표시하지 않는다. 실제 장비 판정과 재료는 서버 권위.
- **이전 3기관 장착 UI·표본 채집 목록·기생 부하 바·4액티브는 현재 기본 계약에서 제외**한다. 새 기획에서 실제 필요가 입증되어 다시 승인받지 않는 한 Codex가 임의로 재추가하지 않는다. [옛 기획 보존](../../classes/PARASITE_MORPHER_V1_ARCHIVE.md).
- 인형제작대 같은 전용 제작대/생체 재화 메뉴는 기생술사에 복제하지 않는다. 기존 바닐라 UI와 직접 숙주 조작을 우선. 모든 생체 데이터/숙주 전환/피해는 서버가 최종 결정한다.

- **[8직업 공통 매개체 장착 슬롯 — 방향 확정](../../CLASS_FOCUS_SLOT.md)**: 주손/왼손 대신 전용 슬롯 하나에 직업 장비를 장착(구체 UI/API 미구현). 바닐라 방패·토템·횃불/도구 조작을 그대로 보존, 스킬 시전 순간 조율기/조종틀/공생 핵 외형만 일시 표현. 아이템을 실제 손으로 옮기거나 같은 장비를 두 군데 동시에 장착하지 않는다.

## 결계술사 UI 확장 계약 (결계 기본 성능 상향 v4·2026-11-04)

- [결계술사 v4](../../classes/BARRIER_CASTER.md)는 **방어·압축 공격·격리의 서로 다른 결계 주문을 지정 범위에 독립 설치**하는 구조. 이전 '결계 1개/3모드 교체' 방식은 철회. 종류를 선택한 뒤 실제 **중심 위치·반경·높이·설치 가능 여부**를 미리보기로 확인하며, 기존 다른 유형의 결계를 자동 덮어쓰지 않는다. 술식 선택 UI는 공통 휠/간결한 단축키를 검토하되 3모드 토글로 설명하지 않는다.
- **배치 미리보기**는 유형별 실제 3차원 경계·중심/반경·설치 가능 여부를 표시. **설치된 서로 다른 결계들에는 각각 유형/위치·잔여 내구·지속시간**을 보여준다. 방어·압축·격리의 공간 효과가 실제 서버 판정과 일치하고, 전투 시야를 가리는 거대한 면/불필요한 패널 반복은 피한다.
- **방어·압축·격리 결계는 핵심 결계 주문**이며, 술식탄·순간 방벽·결계 증폭은 별개의 보조 주문 후보. 이전 '경계 압축' 별도 액티브는 압축 결계와 중복되어 철회. [결계별 상향 시전/지속/타격 시안 v2](../../classes/BARRIER_COMBAT_BALANCE.md): **기본 3개 동시**, 소·중·대 반경3/5/7블록, **중형 방어 내구64HP/압축 총 피해26HP/격리 내구52HP** 후보. 압축 0.7초 예고 후 1.2/2.2/3.3/4.5초 4타, 방어18초·압축4.5초·격리14초. **모두 실제 플레이 전 초안**. Codex는 서버 확정 공격·차단·아군/적군·저항 판정만 읽어 표시한다.
- [결계술사 형성·압축·경계 300랭크 트리](../../classes/BARRIER_SKILL_TREE.md): 3계열/9노드, 계열별 100랭크 후보. **다중 전개 15/35랭크에서 활성 결계 +1/+1**, 기본3→4→5 후보. 격리+압축 추가 피해는 **실제 양쪽 결계 범위의 유효 교집합 대상**에만 보정. 기본 결계 시전/범위 프리뷰를 랭크로 잠그지 않는다.
- [결계 매개체 5등급](../../classes/BARRIER_FOCUS.md): 장비 툴팁의 옵션은 **방어·격리·순간 방벽 경계 내구 +5~25%, 압축 결계 피해 +5~25%** 두 항목만 표시. 직업별 공통 매개체 슬롯 사용, 주손·보조 손 자유. 제작 원가는 실제 서버 레시피에서 판정.
- **공통 직업 매개체 슬롯**을 사용하고, 방패/토템·기존 바닐라 상호작용과 충돌하지 않는다. 결계 설치 중 채굴·아이템 사용이 무조건 중단되도록 하지 않는다.

## 계약술사 UI 기획 연결 (v1·2026-11-04)

- [계약술사 1차 기획](../../classes/PACT_CASTER.md): **대가와 위험을 지불해 강한 능력을 얻는 직업**으로, 초기 후보 계약 **추적/교환/반격 3개**를 동일 공용 스킬/직업 선택 UI에 데이터 바인딩. 정신 지배자의 유지 정신력·기생술사의 BD/숙주·결계술사의 결계 수를 복제하지 않는다.
- 계약 선택 전 **'얻는 효과 / 계약의 대가 / 남은 기한·성공 조건 / 실패 시 적용 / 재사용대기'**를 읽을 수 있어야 하며, 전투 중 큰 모달창을 반복 열고 서명을 여러 번 누르게 하지 않는다.
- 활성 계약은 기본 **1개 후보**. HUD는 현재 선택 계약 1줄 요약과 **실제 HP 봉인·받는 피해 증가·계약 상대/남은 시간/후유증** 등 필요한 정보만 표시. 계약실패/종료 이유는 짧게 알려주고, 근거 없는 '부채 재화'·잔고/도감/새 메뉴 생성 금지.
- [공통 매개체 슬롯](../../CLASS_FOCUS_SLOT.md)의 **계약 증표** 가칭을 보존하고, 주손·보조 손과 독립. 캐릭터/주변 몬스터 소유권·전투 보상·HP와 계약 성공/실패는 서버 정본에서 계산. UI가 임의 피해/체력 봉인을 계산하거나 시전 성공을 먼저 선언하지 않는다.
- 계약의 구체 세계관·반사 공격 VFX·계약 실패 연출은 검증된 실물/게임 레퍼런스를 기준으로 디자인하며, 피·고어·불필요한 검은 카드/그라디언트/서명 패널 남발을 피한다. **아직 사용자 확인 전 시안**.
