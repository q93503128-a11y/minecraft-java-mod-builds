# 이능 직업 서바이벌 — 6직업 관리 UI/UX 통합 설계 (2026-11-12)

**상태: UX 기획/구현 출발 설계안. Minecraft 클라이언트 미검수, 고유 관리 시스템 코드 미구현.**
요구: 높은 실제 조작 편의성, 클래스별 다른 정보 구조, 공통 조작 관례, 중대형 비전체화면, 매개체 5등급 제작법, 낮은 우선순위의 작은 직업 변경 버튼, 현재 M/J/U 바로가기. 코드 완성·플레이테스트로 혼동하지 않는다.

## 1. 현행 정본의 경계 / 보존 원칙

- 이 계획은 현재 main의 PROJECT.md, CLASS_SWITCH_ORIGINAL_STATE_POLICY_V2.md, D09_DIRECT_SKILL_KEYBIND_AND_CLASS_COMMANDS_V1.md, ui/D10_UI_VFX_PRODUCTION_BRIEF_V1.md, 클래스별 상세 기획과 FOCUS_SHAPED_RECIPES_AND_UI_2026-11-12.md를 따른다.
- 직업 8개 중 6개 상세 대상(정신/인형/기생/결계/계약/군체), 중력/공명은 상세 보류. 6개 관리 본문은 **절대 6개 똑같은 슬롯/탭으로 강제하지 않는다**.
- 직업 관리 현재 실제 구현은 중앙 내용이 없는 ClassManagementScreen + 프로필/직업 변경 버튼뿐이다. 고유 직업 관리자, 매개체 아이템/제작 레시피, 직업 능력의 게임 내 엔티티 연동은 아직 완성되었다고 주장하지 않는다.
- 비전투 중 월드 어디서나 직업 변경. 변경 때 현재 직업의 전투 효과는 종료/원상복귀하고 직업별 성장 정보는 보존. 특히 지배 링크 해제, 인형 원본 회수, 기생 숙주 원상복귀, 결계 종료, 계약 효과 비활성(계약 자체 유지), 군체 N 및 전술 저장 정책을 지킨다. **전환 버튼을 누른 즉시 복귀 불가능한 정리 작업을 실행하지 않는다.**
- 6직업 각자 성장 데이터와 직업 매개체 전용 슬롯 1개, 등급 규격→변조→변칙→이형→불가해와 3×3 고정 레시피 30종을 보존. 별도 UI에서 무료 제작/매개체 승급 금지.
- 이미 동작하는 프로필·스킬트리 화면, 캐릭터 UI 에셋, 버튼 렌더링을 보존. 사용자가 수정 중단을 요청한 **기존 외곽 장식 프레임은 변경하지 않는다**.

## 3. 공통 화면 계약

### 공간 / 구조

- 전체화면 스킬트리와 구별. 중앙 **중대형 비전체화면**(16:9 기준 화면 너비 약 80%, 높이 약 80%를 시안 출발점으로 검토; 고정 수치는 실게임에서 조정), 월드 배경은 주변에서 약하게 보이도록. 기본 가독성과 중앙 집중 유지. 무조건 불투명 검정·그라디언트·의미 없는 카드 남발 금지.
- 제목 + 현재 직업 아이콘/이름(간결한 상단), **직업의 핵심 현황 + 조작 본문**, 가장자리의 작은 보조 진입점. 중요 정보는 초기에 표시, 모든 텍스트를 두 겹으로 겹쳐 넣지 않는다.
- 직업별 내부 레이아웃: 정신/인형/계약은 **왼쪽 소유 목록 / 오른쪽 선택 상세** 중심; 기생은 **현재 숙주 중심 상태 / 숙련·계승 상세**; 결계는 **전개 현황 / 조작 설정**; 군체는 **현재 N·역할 분담 / 전술 편집**. 공통 모양을 강요하지 않음.
- **공통 보조 항목**: 매개체(5등급 제작법), 필요할 때 프로필, 화면 닫기. **직업 변경은 우측 하단의 작은 2차 버튼**. 빈 공간을 채우기 위한 같은 크기의 큰 직업 변경 CTA 금지.
- 흔한 항목을 한 번 열기 → 상세 선택 정도로 제한. 장문 도감/계약서/계승기/매개체는 본문 내 2차 영역(드로어·세부 보기·탭 중 맥락에 맞는 1개)에서 열며 깊은 다중 메뉴 체인 금지.
- 인게임 GUI scale 2~4, 16:9·16:10·4:3, 작은 창에서 각 영역의 폭/높이 가변; 필요한 경우 목록/상세를 전환하되 동일 핵심 행동 모두 접근 가능. 스크롤 영역을 내용별로 분리해 전체 화면이 뜻하지 않게 튀지 않음.
- 기존 버튼·프레임 에셋의 디자인 언어 사용. 픽셀 밀도/여백/폰트 계층/버튼 상태 통일. 클래스별 무드·문양/일러스트는 다르게 해도 기본 조작 피드백은 일관.

### 입력 / 이동

- **M 프로필, J 스킬트리, U 직업 관리** (현재 코드의 재매핑 가능한 키), 기본값 및 변경한 키가 버튼에 실시간 반영되도록. U/JEI 같은 GUI 컨텍스트는 인게임 월드 vs 인벤토리·제작대/오픈 메뉴에서 분리되어야 한다.
- U로 관리창 열면 곧바로 **현재 직업의 핵심 화면**. 매번 프로필을 경유하지 않는다. 프로필에서의 직업 관리 버튼도 동일 상태로 접근.
- Esc는 확인/편집이 없는 경우 즉시 창 종료; 위험 행동 확인창이 열려 있으면 그것만 취소. 미저장 비율/이름 편집은 조용히 덮어쓰지 않고 상태를 명시하며 종료 처리 선택을 검토(기본 편집 영역과 적용된 실제 전술의 구분).
- 목록의 선택 대상 및 스크롤 위치는 상세 보기에서 돌아와도 보존. 서버 최신 데이터 변경으로 대상이 사라졌다면 이전 개체를 계속 조작하는 대신 명확히 알리고 유효 항목으로 안전 복귀.
- 컨텍스트/월드 지휘 바로가기(G/H/R 등은 직업별 D09 우선)는 전체 관리창을 열지 않고도 실행. 이미 철회된 G 길게/Shift+G은 재도입하지 않는다.

### 피드백 / 상태

- 서버가 확정할 동작: 소유권, 지배·인형·숙주·결계/계약·군체, 명령 성공, 소비재·스탯·전술 저장/적용. UI는 결과 수신 전 성공처럼 그리지 않는다.
- 명확한 상태: 사용 가능 / 불가(이유 표시) / 처리 중 / 성공 / 서버 거부 / 언로드·정보 불확실. 실패 예시는 "이 대상은 현재 다른 차원에 있습니다", "수리하려면 인형제작대가 필요합니다" 등 실제 복구 행동이 가능한 문장.
- 일반 동행·대기·전술 선택에는 불필요한 확인 팝업 없음. 삭제·해제·분해·계약 파기/고비용, 귀한 지배체를 풀어야 하는 직업 전환은 **대상명+정확한 결과/비용** 명시 후 확인. 확인 요청 중 중복 누름/지연 서버 응답 방지.
- 비동기 실제 상태 갱신은 선택 대상 ID/revision을 검사해 오래된 응답이 새 대상을 덮어쓰지 않도록. 장기간 로딩·무반응 버튼 금지.

## 4. 직업별 구체 UX

### 4.1 정신 지배자 — 지배체 운용이 1순위

**첫 화면:** 지배 슬롯 점유(현재/최대), 정신력 총 유지비·감당 여부, 현재 동행/대기 수, 지배체 목록.
- 목록 행: 실제 몹 이름·아이콘, HP, 동행/대기/휴면/언로드/사망 상태, 현재 차원 및 최종 확인 위치(유효한 데이터가 있을 때만). 정렬은 활성·위험 상태가 먼저 오게 하되 사용자가 원하는 행을 추적 가능하게.
- 행 클릭 → 해당 개체 상세: 현재/최대 HP, 유지 정신력, 현재 명령, 플레이어 피해 허용 ON/OFF, 주요 능력/종류. 자주 쓰는 **동행 / 대기**를 가까운 위치에 나란히 제공; 해제는 작고 분리.
- 기존 기획의 **전체 동행/전체 대기**는 상단에서 접근하되 한 번에 여러 개체의 명령 상태만 변경. 실체를 소환·지나친 거리 즉시 텔레포트·오프라인 강제 로드하지 않는다.
- **지배 도감**은 별도의 2차 정보 보기: 지배에 성공한 적 있는 종/변종/강적 기록; 도감은 소환기나 무상 부활기가 아니다.
- 실제 월드에서 지배체를 조준한 경우 맥락 관리/동행·대기 빠른 명령 접근은 전체 목록을 대체하지 않고 병행. 입력 키 상세는 기존 승인·보류 상태 유지.
- 정신력 부족 자동 해제 우선 순위는 최신 정책을 따르며 사용자가 강제 조작해야 할 새 큐 관리 UI를 만들지 않음.

**대표 시나리오:** U → 이름/상태로 개체 선택 → 대기 클릭 → 서버 적용 표시. 긴급하게 바로 옆 몹을 지시할 때는 화면 전체 대신 맥락 명령 사용.

### 4.2 인형술사 — 제작 인형의 상태와 정비

**첫 화면:** 전개 수/보유 인형 수, 전개 인형 건강 상태, 보유/전개 목록. 가능하면 현재 인형 모습/부품 시각을 선택 상세에 활용.
- 목록 행: 이름/모델, 전개·회수·파손 상태, HP·손상, 주된 역할. **동행/대기**는 선택 상세에서 쉽게.
- 상세: 부품·무장·강화 기록, 손상, 수리에 필요한 현재 공식 재료/부족분, 제작대에서 가능한 정비·분해 예상 반환량. 데이터/실제 장비가 없는 부분은 표시하지 않는다.
- **인형제작대**에서 해야 하는 조립/정밀 수리/분해를 U 관리창에서 원격 무료 실행하지 않는다. 현장에서 가능한 긴급 접합/실 견인 능력은 D09의 실제 액티브 판정과 분리.
- 회수 가능 대상/거리·전투/청크 조건을 충족할 때만 **회수**를 활성화하고, 오작동 시 이유를 제공. 저장된 인형과 월드 실체 중복 생성/무료 HP 복원 금지.
- **분해**는 별도의 작업대 화면과 실제 회수 예상 재료를 확인하는 위험 행동으로 관리. U에서 즉시 파괴/분해 금지.

**대표 시나리오:** U → 파손 상태 우선 표시 → 인형 선택 → 부족 재료를 확인하고 제작대로 이동, 실제 정비.

### 4.3 기생술사 — 한 숙주와 모든 영구 계승

**첫 화면:** 현재 숙주(없다면 인간형) 초상/종, HP, 생존 및 상태, 공용 BD, 현재 종 숙련도(0~100)와 다음 이정표. 단순 보유 몹 목록 UI 사용 금지.
- 2차 **숙련·계승**: 종별 숙련 내역을 검색/정렬하고 100 완료 여부, 다른 숙주에도 사용 가능한 계승 능력/현재 숙주 원래 능력을 명확히 구분.
- **직접 시전 계승기**와 **항상 활성인 자동/환경형 계승**을 분리 표시. 이미 보유한 계승 기술은 UI 페이지 10칸을 넘어도 전부 보존.
- 사용 중인 **V 계승 모드**(ON 시 1~0 직접기, OFF 시 바닐라 핫바)를 화면 상단에서 확인. 배정 기술 목록 및 페이지는 관리창에서 조정·조회할 수 있게 설계하되 11번째 이후 페이지 전환 키는 기존 미결정을 임의 확정하지 않는다.
- 현재 숙주 사망·인간형 이탈·기생 전이와 영구 BD/숙련의 차이를 명확히 표시. 직업 전환 시 현재 숙주는 해방되지만 영구 숙련·계승은 남는다는 기존 계약 유지.

**대표 시나리오:** U → 현재 숙주/현재 종 숙련 확인 → 계승 목록에서 사용할 기술/배치 상태 확인. 전투 중 계승 직접기는 V+숫자키, 매번 U 열지 않음.

### 4.4 결계술사 — 활성된 공간 효과 관리

**첫 화면:** 현재 설치 수/한도, **활성 결계 목록**(종류, 남은 시간, 내구/피해, 중심·차원·크기), 현재 편집 종류·크기, **최근 설치에 성공한 종류·크기**를 서로 다르게 표시.
- 결계 행 클릭 → 효과/남은 시간/위치 상세 및 **해제**. 개별 해제는 시전 소모·쿨타임 환급이 아님.
- 아직 설치된 결계가 없으면 선택한 주문 종류·범위 및 조작 힌트만 간단히 표시. 의미 없는 빈 결계 카드 강제 금지.
- **R 1회 미리보기→Z/X 종류/크기→R 2회 설치**, **G는 마지막 성공 종류·크기를 현재 조준에 즉시 재시전**하는 최신 기획을 유지. 오래된 R 단번 설치/선택 결계 1개만 증폭 기획 재도입 금지.
- 실제 보조 주문, 전체 유효 결계 증폭은 전투 중 직접 액티브로 쓰고, 관리창에 새로운 강화/무료 충전 버튼을 넣지 않는다.

**대표 시나리오:** U → 만료 직전 결계 선택 → 세부·해제. 새 결계 시전은 월드에서 R/Z/X/G.

### 4.5 계약술사 — 계약서와 위험을 읽는 화면

**첫 화면:** 현재 실제 체결된 계약 수, 계약 상대 목록(위계·이름·유효 가호/주요 금기·미이행 위험), 선택한 계약의 **계약서 상세**. 미체결 16종을 현재 계약처럼 보이지 않게 구분.
- 상세: 상대의 가호·고유 권능·실제로 갖춘 자동 패시브(기준 3종), 관계/심화 상태, 개인 금기·의무, 현재 채무·상환 조건, 현현의 실제 비용/가능 여부. 여러 계약의 가호 합산은 가장 큰 동일 스탯 가호 100% + 나머지 각 50% 규칙을 안내하되 모든 효과·금기·채무가 50%인 것처럼 그리지 않음.
- **다음 계약 체결**은 해당 상대와의 실제 접촉/제단·의식 조건을 따른다. U는 조건·제물·부족분·충돌 위험을 미리 확인하는 장부, 공짜 원격 계약 버튼이 아니다.
- 심화/면책/파기는 기존 비용·서버 규칙 준수. **계약 파기**는 해당 계약명, 잃는 효과와 위약금/남는 채무를 실제 값으로 확인하는 2단계 위험 행동. 정기 계약 유지비/일일 제물 자동 청구라는 신규 시스템 생성 금지.
- 동시 계약이 많아지면 목록 정렬/상태 필터는 제공하되 화면을 16개의 동일 크기 대형 카드로 채우지 않음.

**대표 시나리오:** U → 원하는 계약 선택 → 다음 심화 조건과 제물 부족분 확인 → 월드의 실제 조건 충족 장소에서 실행.

### 4.6 군체술사 — 사용자가 만드는 전술이 중심

**첫 화면:** 실제 N/Nmax, 지금 공격·엄호·운반·재결집 중 수량, 현재 표적/비행 여부, **활성 전술**, 전술 목록, 전술 편집.
- **공격% 슬라이더/숫자 입력과 엄호% = 100−공격%**로 묶어 조작. 0:100과 100:0을 포함해 사용자 값을 서버가 임의 보정하지 않는다. 비행 중 운반 예약 개체는 별도 수량으로 보여주고 나머지에 사용자가 정한 역할 비율을 적용.
- **저장된 전술 이름·비율·퀵휠 배치** 확인. 새 전술 만들기/이름 수정/적용/저장/삭제/빠른 목록 순서 변경. 고정 사전 전술 4종, 강제 명칭, 개체별 수동 편집, 별도 군집 엄호 액티브는 금지.
- **지금 전투에 일시 적용**과 **이름 붙인 전술 덮어쓰기 저장**은 별개 버튼/상태. 저장 없이 조정해도 즉시 적용할 수 있으나 기존 명명 전술은 임의 변경하지 않는다. 실제 병력 배치는 시간이 걸리므로 목표 비율과 현재 실제 배치가 다르면 두 값을 구분.
- **빠른 전술 휠**(현재 G 후보)은 전투 중 기본 접근. U는 자세한 저장/관리용. G 홀드/Shift+G를 되살리지 않고 한 번 누르는 즉시 화면으로 설계. 직접 이름/비율 수정이 퀵휠에서도 가능한 기존 정책 유지.
- 전술 슬라이더가 0% 공격대일 때 공격대 전용 스킬이 공짜로 개체를 만들어 공격하지 않으며, 엄호 0%에서 없는 엄호 개체가 화살을 막지 않는다.
- 원격 표적 지정 R과 군집 급습/군체 소모 실제 액티브는 U 슬라이더에 흡수하지 않는다.

**대표 시나리오:** 전투 중 퀵휠→저장 전술 1회 선택; 전투 후 U→현재 전술 비율 수정→임시 적용 또는 저장. 둘 모두 한 화면에서 작업.

## 5. 공통 매개체: 조회용 서브화면

- 모든 직업 U 화면 가장자리의 공통 **매개체** 항목에 들어가서 현 직업 매개체의 **5등급**을 즉시 전환. 현재 장착 등급과 현재 열람 중 등급은 별개로 표시.
- **실제 제작대와 같은 3×3 슬롯**, 아이템 실물 아이콘, 각 칸의 수량/호버 이름, 화살표→결과 슬롯, 결과 아이템의 등급/장착 효과. 등급 2~5의 **직전 매개체는 중앙 칸**. 패턴 정본: FOCUS_SHAPED_RECIPES_AND_UI_2026-11-12.md.
- 계약술사 불가해 등급의 **불사의 토템 / 바다의 심장** 대체 조합을 명시적으로 바꾸어 열람 가능하게.
- 구현 시 레시피 데이터와 3×3 시각 정보는 **동일한 정의 또는 일치 검산**을 적용. 원본 재료/개수/전용 슬롯 1개/일반 작업대 제작 모두 유지. UI에서 즉석 제작·무료 강화하지 않는다.
- JEI가 설치된 경우 중복 조회를 장황하게 구현하기보다는 기존 레시피북/JEI 조회를 방해하지 않는 연결 제공. 단독 모드에서도 제작대 배치는 볼 수 있어야 한다.

## 6. 게임 조작 일관성 및 접근성

- 가독성: 직업 아이콘만으로 상태 구분하지 않고 텍스트·숫자를 함께 표시. 폰트·툴팁은 GUI scale 2~4/다양한 언어 길이에서 잘림 검수.
- 컨텍스트 단축키 표시: J/U는 현재 키 설정에 맞는 텍스트로 표기. 화면이 열려 있는 동안 J/U가 뒤에서 세계 기술을 발동해서는 안 된다. JEI의 아이템 hover+U는 GUI 맥락에서 동작할 수 있으므로 충돌 여부를 실제 동시 로드로 확인.
- 데이터 단위: 위치/차원/HP/시간/BD/계약 채무는 **서버가 현재 확인하는 값만 표시**. 불러오지 않은 청크의 대상은 실제 HP가 실시간으로 갱신되는 척하지 않음.
- 큰 소환체 목록 등에서는 필요한 화면 범위만 렌더/갱신. 매 프레임 원격 모든 엔티티를 훑거나 UI 연출을 위해 청크 로딩하지 않는다.
- 사망·로그아웃·직업변경·멀티 동시 접근/패킷 지연 시 현재 UI의 낡은 상태가 명령을 덮어쓰거나 복제/이중 소비를 일으키지 않아야 한다.
