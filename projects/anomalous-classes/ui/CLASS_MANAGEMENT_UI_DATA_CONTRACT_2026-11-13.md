# 직업 관리 UI 서버 데이터 계약

이 문서는 UI 담당 작업과 서버 게임 시스템 작업의 경계를 정리한다. 화면에 표시할 데이터는 서버가 승인한 응답만 사용하고, 서버 기능이 없는 항목을 임의 수치·상태·성공 결과로 채우지 않는다.

## 현재 UI가 실제 기능과 연결된 부분

### 정신 지배자

현재 `MentalDominatorStatePayload`가 정신력/최대 정신력, 초당 총 유지비, 지배 슬롯 수, 상태 코드와 revision, 지배체 UUID·이름·종류·명령·로드 상태·플레이어 피해 설정·유효할 때의 체력·개별 유지비·차원 및 위치, 지배 도감 종 목록을 제공한다. UI는 이 응답으로 목록·선택 상세·체력 표시·전체/개별 동행과 대기·피해 허용·해제 확인·도감을 표시한다. 변경은 `MentalDominatorActionPayload`로 요청하고 서버 응답 전에는 입력을 잠근 뒤 응답으로 상태를 갱신한다. 이 화면에 필요한 추가 데이터 계약은 현재 없다.

목록 아이콘은 `minecraft:<entity>_spawn_egg`가 실제 등록된 바닐라 아이템일 때만 해당 아이템을 사용한다. 아이템이 없거나 대상이 모드 엔티티이면 아이콘 자리를 비워 두며, 잘못된 아이템을 추정하지 않는다.

### 매개체 제작법

현재 UI는 프로젝트의 실제 매개체 카탈로그와 레시피 데이터를 읽는다. 이 작업은 레시피, 장착 규칙, 장비 효과, 제작 결과를 바꾸지 않는다.

## 아직 서버 기능이 없는 직업 화면

다섯 화면은 `ui/reviews/2026-11-13/class-management-design-review/`의 시각 검토 이미지로만 존재한다. 게임에 등록하거나 실제 데이터를 가진 것처럼 표시하지 않는다. 서버가 각 시스템을 구현할 때 최소한 다음 서버 권위 조회 응답, revision, 작업 결과를 제공해야 실제 메뉴에 연결할 수 있다.

### 인형술사

- 안정적인 인형 ID, 이름/종류, 전개·회수·손상 상태
- 서버가 유효하다고 판단한 체력과 위치/로드 여부
- 실제 골격·행동 장치·구동핵 및 강화 정보
- 정비대 작업에 필요한 실제 재료 수량과 보유/부족 수량
- 선택 인형 ID와 상태 revision
- 서버가 지원하는 명령과 성공/거부 결과

관리 UI는 재료 확인만 보여주고, 수리·분해 같은 월드 변경은 실제 인형제작대 작업과 서버 응답에 연결한다.

### 기생술사

- 현재 숙주 존재 여부, 안정 ID/종류, 로드 및 상태; 인간형 여부
- BD 총량(소비 화폐로 취급하지 않음), 종별 숙련도
- 영구 계승 능력 ID/표시명/발동 구분(직접·상시·반응)
- V 계승 모드와 숫자키 배치 상태, 바인딩되지 않은 영구 계승 능력 보관 목록
- 숙주 전이·사망에도 계승 기록을 보존하는 서버 응답 및 revision

슬롯 부족을 이유로 영구 계승 능력을 삭제하거나 숨기지 않는다.

### 결계술사

- 활성 결계별 안정 ID, 종류, 범위, 차원/위치, 남은 시간, 실제 내구도 및 효과 상태
- 현재 편집 중인 설정과 마지막 성공 설치 설정을 구별한 값
- 미리보기·설치·해제 결과와 서버 revision

활성 결계가 없거나 위치를 확인할 수 없을 때 추정 상태를 표시하지 않는다.

### 계약술사

- 체결된 계약 ID, 상대, 위계
- 서버에서 조회한 가호·권능·고유 패시브·금기·의무·관계·채무·심화 조건
- 계약 체결/파기 검토에 필요한 실제 조건 및 제물 목록
- 권능 단축키 배치와 실제 동작 지원 상태, 서버 revision/결과

관리 화면은 계약 의식이나 제단을 대체하지 않는다. 조건과 결과가 서버에 구현되기 전에는 계약·파기 버튼을 노출하지 않는다.

### 군체술사

- 현재/최대 군체 수, 공격·엄호·운반·재결집 수량, 표적/비행 상태
- 저장 전술 목록(신규 캐릭터의 기본 목록은 0개), 안정 ID와 사용자 지정 이름
- 저장 비율, 현재 편집 초안 비율, 현재 적용 비율의 분리된 값
- 저장 순서 및 빠른 선택 배치
- 생성·수정·삭제·순서 변경·임시 적용의 서버 결과와 revision

공격 0%/엄호 100%, 공격 100%/엄호 0%를 허용한다. 자동·공격 우선·균형·엄호 우선 기본 전술을 만들지 않는다. UI는 키 바인딩이 승인되기 전까지 미승인 빠른 휠 단축키를 표시하지 않는다.

## 화면 연결 원칙

- 읽기 전용 표시와 실제 서버 작업을 시각적으로 구분한다.
- 서버 응답 전에는 SP·상태·전술·장비 결과를 확정 표시하지 않는다.
- 빈 목록, 아직 제공되지 않은 데이터, 언로드되어 알 수 없는 상태는 서로 다른 상태로 표현한다.
- 네트워크 요청은 소유권과 직업 검증을 거친 서버 결과에 맞춰 갱신한다.
- 메뉴 레이아웃은 서버 데이터 계약이 준비될 때까지 오프라인 검토 이미지로만 검토한다.
