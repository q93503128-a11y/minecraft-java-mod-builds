## 1. 필수 품질 기준

1. **강하지만 실제로 쓸 수 있다.** 각 계약은 플레이어 본체 가호부터 유효하고 주력 권능은 보통 서바이벌 전투에서 반복 활용할 수 있어야 한다. 맵 특정 지점·날씨·희귀 몬스터·매번의 제물·낮은 RNG에 의존하는 공격만 있는 계약 금지. 특별한 장소는 극대화/현현/계약 의식과 연결하되, 이미 체결한 계약의 평상시 유용성은 유지.
2. **종결 계약의 보상은 압도적이다.** 4위계는 같은 역할의 1위계 최대 심화보다 주력 본체 전투·권능에서 확실히 강하고, 3위계 역시 통상 후반에 값어치가 있어야 한다. 높은 비용을 이유로 '사용 조건이 까다로워 거의 못 쓰는 고급 기술'을 정당화하지 않는다. 수치 확정 전 동일 레벨·장비·대상 기준으로 효과를 비교.
3. **계약 상대의 개성은 유지한다.** 구현이 복잡하다는 이유로 다른 외형의 동일 투사체/동일 버프만 만드는 안은 거부. 그러나 매 존재마다 새로운 범용 엔진·별도 재화·매일 퀘스트·하위 UI를 덧붙이지 않는다. '공통 관계 수치 엔진 + 존재별 표시 이름/실제 상승 사건/권능/금기'를 우선.
4. **관리 노동보다 자연스러운 선택.** 신앙심/명예/신용/공명 등의 관계 수치는 행동에서 자동 정산, 변화가 의미 있을 때만 간결히 알림. 별도 매일 출석·주기적인 제단 방문·수시 점검·그냥 대기 강제 금지. 하스텔 같은 계약 고유 부채/위약금은 지속적으로 UI 작업을 요구하지 않고 실제 사건/기한에서 명료한 결과를 주도록 한다.
5. **마인크래프트 기본 플레이를 지킨다.** 채굴·건축·무기·방패·토템·탐험은 지속 가능. 계약 기술 사용 때문에 손 슬롯이나 재료 창을 항시 열게 하지 않는다. 일반 직업도 제단의 상자/작은 테마별 보상을 얻고 계약술사만 핵 사용.
6. **돈과 위험이 납득 가능.** 주요 제물은 계약 체결·심화·현현·면책·해약에 쓰되 일반 공격을 쓸 때마다 비싼 제물 강제 금지. 높은 해약 위약금·신앙 저하·채무·조건부 HP 봉인은 사전 표시하고 회복/해결 경로를 제공. 일반 계약에 회복 불가 영구 최대 HP 감소 강제 금지.
7. **전투 피드백과 실판정 일치.** 보이는 범위·타격 타이밍·상태 변화·가호 효율이 실제 서버 판정과 일치하고, 강한 기술은 모델/애니메이션/VFX/사운드/카메라까지 고려한다. 빌드 성공만으로 완료 판정 금지.
8. **안정적 기술 경계.** 외부 모드 몹 공격을 마법처럼 모두 지원한다고 가정하지 않는다. 구현 불가한 고유 공격 종류는 명시적으로 기본 공격/유사 프로필로 폴백하며 대상이 공격·방어/보스 특성을 전부 무시하거나 crash하지 않음. PvP/멀티/저장·재접속/월드 보호·청크 부하를 고려한다.
9. **사용자 승인된 안전한 계약 UX.** 제단 핵 한 번 클릭으로 계약되지 않고 상세 계약서 → 별도 최종 확인 → 서버 재검증/원자 소모. 악성 반복 클릭/중복 패킷으로 제물 이중 소비 금지. 같은 스탯의 이중계약은 강한 가호 100% + 약한 가호 **50%** 보존.
10. **불필요한 기술·노드·제단을 만들지 않는다.** 핵심 루프를 개선하지 않는 추가 스킬 버튼, 능력치 게이지, 수십 개 세부 상태, 복잡한 의무·전용 재화를 거절. 필요하면 기존 기능을 더 깊이 구현하는 쪽을 택한다. 다만 이미 유저 승인한 기능을 무조건 제거하지 않고, 더 간단한 구현/표현 방법과 비교해 결정한다.

| **상위 제물·시련·복잡한 심화** | 제물 목록이 자꾸 늘고, 날씨·차원·구조물 RNG에 발목, 종결 계약을 획득해도 실제로 사용 불가 | 높은 가격은 **이미 있는 희귀 재료 + 각 존재를 대표하는 한 가지 중요한 시련** 중심. 적절한 대체 루트를 마련해 특정 월드 구조/운에 무기한 막히지 않게 함. 심화는 중요한 기술 변형을 제공하고 무한 반복 클릭/별도 경험치 게이지를 강제하지 않음 | 강한 존재에게 대가를 치르고 권능을 얻는 성취 |
| **패시브·관계·장비·이중 가호 중복** | 많은 배율로 피해/최대 HP 폭주, 스탯 다시 계산 시 무료 회복 | 공통 공식: 각 계약별 가호→관계/심화→같은 스탯 높은 100%+낮은 50%→공통 패시브→매개체 순 **각 한 번만**. 레벨별/보스별 전투력 측정. 모든 계수는 구현 전 시험 후보 | 본체가 체감되게 강해지고, 이중계약이 강력한 선택 |
| **계약 서명·파기·상호작용** | 오조작/복잡한 메뉴/비용 미고지 | 계약 전 계약서와 **별도 확인**, 위험/해약 비용/충돌 미리 보기. 평상시엔 간결한 정보/바로 사용 가능 기술만 보이기. 서버 원자 소모/상태 보존 | 실제로 위험한 존재와 계약한다는 긴장감 |

## 3. 기능별 최소 플레이 만족 조건

- **강함:** 계약 체결 직후 기본 가호와 대표 권능은 실제 일반 적/강적에게 유용해야 한다. 고위/종결 계약은 희귀 제물을 쓰고 얻는 보상이 체감되며, 조건이 안 맞을 때도 여전히 주력 기술 사용 가능.
- **자주 쓸 수 있음:** 적절한 재사용 대기/발동 범위, 고비용은 궁극급/의식에 집중. 항상 특정 차원·날씨·해양·몹 종류가 필요한 권능만 있다면 재설계.
- **쉽게 이해할 수 있음:** 플레이어에게 '무엇을 얻고 무엇을 바치고 무엇을 하면 약해지는지'를 예측할 수 있게. 매 전투 HUD는 가호/기술·상태 중심, 제단 상세 계약서는 필요한 경우에만.
- **선택이 있음:** 같은 성능의 +N% 카드만 반복하지 않고, 각 존재가 공격·탐험·방어·회복/위험 감수 중 **특징적 조작/전투 상황 하나 이상**을 만든다.
- **자유로운 전환:** 금기·파기는 가볍지 않되 해결 가능해야 하고, 초기 잘못 고른 계약 하나로 게임이 영구적으로 망가지는 함정 금지.
- **실현 가능:** 서버 엔티티/피해/월드/저장으로 실제 판정 가능한가. 무리라면 판정 구조를 단순화하고 핵심 연출/게임성을 살린다. **핵심 재미를 망가뜨릴 정도의 축소는 실패**로 간주.
- **멀티/성능:** 파티/적대/소유권·월드 보호를 지키고 다중 현현/큰 제단에서도 FPS/TPS 문제를 실측. 클라이언트 화면·애니메이션 미검수 상태를 '완료'로 표시하지 않는다.

### 3.1 3단계 결정법 (새 콘텐츠/권능마다)

1. **이 스킬을 평상시 언제 실제로 쓰는가?** 예: 보통 전투에서 최소 한 번은 유의미한가? 부가 가호뿐이고 기술이 사실상 장식이라면 재설계.
2. **같은 재미를 더 안전/간단하게 구현할 수 있는가?** 구현 방식을 줄이되 서로 다른 존재의 특징과 화면 품질은 보존. 어려운 외부 사례를 모방하기보다 검증된 서버 판정/모델/애니메이션 조합을 선택.
3. **비용 대비 보상이 실재하는가?** 능력이 체감되는 플레이·높은 단계의 우위·장비/공통 성장과의 중복/관리 부담을 모두 점검. 문제 있으면 새로운 잡기능보다 기존 권능의 효과·입력·경제를 손본다.

## 4. 구현 단계별 품질 확인(아직 수행하지 않음)

- **계획 단계:** 계약별 `main combat loop`, `ordinary use`, `signature effect`, `cost`, `outcome`, `fallback`, `visual requirement`, `risk`를 간단히 정의. 기술 구현 난이도: 낮음(바닐라 피해/이동/상태)·중간(전용 피해/모델/VFX/UI)·높음(외부 모드 AI/죽음/월드 구조/인과 재현)을 구분.
- **작은 수직 슬라이스:** 최초 1위계 계약 1종에서 서바이벌 입문→제단 또는 접촉→두 단계 계약 확인→전투→제물 심화→관계 변화를 실제 Minecraft에서 검수. 이를 확인했다고 나머지 15종을 '테스트 통과' 취급 금지.
- **위계 비교:** 1위계 최대 심화 vs 2·3·4위계의 기본·심화 상태, 동일 레벨/장비·실제 적·보스 위협에서 TTK, 12~30초 DPS, 손 조작 부하, 제물 회수 시간, 스킬 발동 빈도와 가독성 체크. 목표치 자체는 실측 뒤 결정.
- **실제 화면 품질:** 대형 제단 지형/구조물, 계약서와 최종 확인, 현현의 모델·애니메이션·사운드와 공격 판정 일치, 아이콘/툴팁, 플레이어 피드백 반영. 정적 이미지/컴파일만으로 완료 표시하지 않는다.
- **서버 안전:** 제물 원자 소모/중복 재요청·파기/재로그/죽음·장비 HP 비율·외부 엔티티 미지원 폴백·멀티 경쟁·엔티티/월드젠 스파이크 등 위험에 비례한 테스트.
- **품질 실패 시 수정 우선순위:** (a) 입력·효과가 체감되는가 → (b) 핵심 계약 성격을 보존하면서 복잡도를 줄일 수 있는가 → (c) 기존 8직업 성장/서바이벌 루프와 조화로운가 → (d) 모델·VFX·음향/성능 검수 → (e) 필요한 수치 조정. **그냥 기능 삭제/no-op/가짜 API/테스트 삭제로 빌드만 통과시키지 않는다.**
