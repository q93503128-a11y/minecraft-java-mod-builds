# 계약술사 — 3개 이상 동시 계약과 제물 지수 소프트캡 (D07 정본)

> 2026-11-06 사용자 확정: **동시 계약 3개 이상 허용**, 계약 수가 늘수록 필요한 제물이 **곱절로 증가**해 자연스럽게 많이 유지하기 어렵게 한다. **세 개 이상에서도 가장 큰 가호는 100%, 나머지 가호는 50%**. 기존 최대 2개는 미승인 시험안이었으므로 폐기. 기존 계약별 존재·위계·금기·심화·위약금·현현·계약서 두 단계 최종 확인은 보존한다. 본 문서는 설계 명세이며 게임 구현/플레이테스트 완료를 뜻하지 않는다.

## 2026-11-06 사용자 추가 확정 — 계약 정기 유지비 없음

- **동시 계약 수가 늘어나도 계약 자체를 유지하기 위한 시간당/일일/접속 주기 제물 소모는 없다.** 기존 제물 배수는 다음 계약을 **새롭게 체결할 때만** 적용하며 과거 계약에 소급 청구하지 않는다.
- 계약 심화·고위 현현·위반/면책·해약 및 원래 계약 채무는 별도 사건이며 전부 정기 유지비로 자동 변경되지 않는다. 단순히 계약을 계속 활성 상태로 둔다는 이유로 빚을 생성하거나 자동 만료시키지 않는다.
- 최종 **4위계 최초 계약 재료와 제물 개수는 미확정**이다. 나하르의 메아리 조각/네더의 별 등은 후보로만 존재하고 **심화할 때마다 같은 초희귀 재료를 다시 요구하기로 결정한 적 없다**. 실제 드롭 수급/대체 경로·계약 수 배수와의 곱셈은 경제/플레이테스트 전.

## 1. 확정한 플레이 규칙

1. **3개 이상의 계약을 동시에 유지할 수 있다.** 2계약을 하드캡으로 막지 않는다. 실제 체결할 수 있는 대상은 세계에 존재하며 각 계약의 조건을 충족한 서로 다른 계약 상대. 현재 16개는 존재별 기획 후보 집합으로, 최종 등록 종 수/기술적 상한은 별도 정본에 따른다.
2. **소프트캡은 제물 요구량**이다. 동시 계약 수가 하나 늘어날수록 다음 계약에 필요한 **체결 제물**의 부담이 이전 단계보다 배가 되도록 한다. 새 공용 계약 화폐나 강제 '계약 슬롯 확장' 레벨/패시브를 만들지 않는다.
3. **가호 반영:** 각 능력치의 계약 가호 증가분을 비교하여 **가장 큰 가호 증가분 100%**, 그 외 계약에서 같은 능력치에 제공하는 **각각의 증가분 50%**를 반영한다. 기존 2계약의 '높은 100% + 낮은 50%'를 3개 이상에 일반화한다. 가호의 원본 크기는 각 존재의 관계·심화·계약 조건을 먼저 적용해 계산한다.
4. 가호를 50% 반영하는 것은 **고유 권능의 원래 기술/시전권·조항·채무·위약금·발동 위험 전부를 임의로 반으로 줄인다는 뜻이 아니다.** 각각의 계약은 본래 권능을 조건에 맞게 사용하고, 금기/제물/채무는 계약대로 판정한다. 여러 강력한 권능 동시 사용의 쿨타임·애니메이션/중첩 제한은 별도의 실제 게임성 검증 대상이다.

## 2. 제물 소프트캡 계산 — 구현용 명세 초안

### 2.1 체결 순서별 두 배 제물

한 계약의 **기본 체결 제물 묶음**을 B(대상 존재/위계별 상이)라 하고, 그 계약을 추가했을 때 **동시 활성 계약 총수**를 n이라 하면, 추가 계약의 소모 제물에 다음 배수를 적용한다.

`RequiredOffering(newContract, n) = BaseOffering(newContract) × 2^(n-1)`

| 새로 체결하는 계약 순서 n | 원래 해당 존재의 체결 제물 기준 |
| --- | ---: |
| 첫 계약 | 1배 |
| 두 번째 | 2배 |
| 세 번째 | 4배 |
| 네 번째 | 8배 |
| 다섯 번째 | 16배 |
| 여섯 번째 | 32배 |

이는 **사용자가 정한 '곱절' 요구를 수학적으로 정리한 기준**이다. 위계·대상에 따라 원래 요구하는 B는 다르므로 **모든 계약의 실제 제물 개수가 같다는 뜻이 아니다**. 예컨대 어떤 계약 기본 체결 제물이 금괴 4개라면 세 번째에 체결할 때 금괴 16개가 필요하다. 실제 계약별 4개 등은 설명용 예시일 뿐 확정 레시피가 아니다.

- **항목별 스케일 적용은 아이템 등 소모 가능한 체결 제물에 우선.** 특정 제단 발견·한 번만 얻는 자격·금기·관계 수치·유일한 구조물 자체를 4번/8번 반복 요구하는 게 아니다.
- **현재 HP 제물**처럼 단순히 곱하면 즉사나 결제 불능으로 불가피한 하드캡이 생기는 항목은, 해당 존재의 별도 제물·희생 계약과 조화되게 **안전한 추가 재료/동등한 대체 제물** 등으로 비용을 분리하는 기술 설계를 검토한다. 이 예외의 정확한 등가 교환율·최종 요구량은 미확정이다. 'HP 곱절로 즉사'를 숨은 체결 조건으로 만들지 않는다.
- 심화용 제물, 계약 파기 위약금, 현현 시전 비용, 계약 위반 면책 비용까지 **전부 체결 배수를 자동 적용한다고 해석하지 않는다**. 이 비용은 계약 종류별 원래 규칙이 우선. 여러 계약의 충돌·채무로 인한 **추가 부담**은 별도 처리하며 정확한 추가 계산은 향후 검증한다.
- 계약서 미리보기에서 **기본 제물 B / 현재 동시 계약 수 n / 배수 / 최종 필요한 재료·부족분 / 금기 충돌·위약금**을 분명히 보여준다. 최종 승인 직전 서버에서 현재 계약 수·인벤토리·제물/HP·관계·권능 조건을 재검사하고, 정확히 한 번 소비 및 체결. 실패·닫기·거절·충돌·다른 계약 해지로 배수가 바뀌면 **돈을 먼저 빼지 않고 재확인**.
- 이미 정상적으로 맺고 유지 중인 계약의 과거 제물을 **계약이 추가됐다는 이유만으로 다시 청구하지 않는다**. 직업 변경/사망/재접속/차원 이동은 추가 체결 사건이 아니므로 배수 재정산이나 영구 기록 소실을 일으키지 않는다.
- **의도적 해약 후 재가입**은 원래 계약서·위약금/신용/금기/재계약 조건을 적용한다. 해약/재계약을 반복하여 무료 슬롯·제물 회수·가호 중복을 발생시키지 않는다. 체결 순서 악용과 재계약 비용의 세부 기술 설계는 QA에서 결정.

### 2.2 실제 자원과 숫자 안전

- 제물이 여러 스택을 초과하더라도 UI는 전체 필요한 수량을 정확히 표시하고, 수집 가능한 아이템/유효 대체 재료로 실제 체결 가능성을 보존한다. 복잡함 때문에 별도 '계약 코인'을 강제하지 않는다.
- 계약별 요구량 산술은 정수 오버플로/음수·소수 수량·클라이언트 허위 수량을 허용하지 않는다. 최종 등록 가능한 존재 수 이상의 가상 수량으로 계산하지 않는다.
- PvP·멀티·월드 데이터 오류/자동 재접속에서 계약 중복 등록·값 비정상 변경·부채 초기화/재료 중복 소비 없음. 실제 데이터 정합성 검증이 최우선이다.

## 3. 다중 가호 공식과 예제

같은 능력치에 대해 관계·심화·금기 영향을 각각 적용한 계약별 **양수 가호 증가분**을 b1, b2, …, bn 이라 두면:

`TotalBoon(stat) = max(b_i) + 0.5 × (sum(b_i) - max(b_i))`

- **가호가 없는 능력치에는 다른 계약에서 50% 디버프를 만들지 않는다.** 같은 능력치를 제공하는 계약이 한 개뿐이면 그 가호 100%를 적용한다. 패널티·저주·빚을 가호로 둔갑시켜 절반만 부담하게 하지 않는다.
- 예시: 근접 공격 가호가 +50%, +30%, +20%인 3개 계약이면 합산 증가는 **+75%** (=50+15+10)이다. 실제 HP·공격 배율은 게임 엔진의 기존 계산 순서대로 각각 적용하고 전체 캐릭터 기본 스탯을 무조건 1.75배+기타 무한 곱셈으로 합성하지 않는다.
- 3계약 예: A는 근접 가호 +50%, B는 방어 가호 +30%, C는 근접 가호 +20%면, 근접 **+60%**, 방어 **+30%**다. 스탯별 가장 강한 가호를 정하므로 주계약 1개를 모든 능력치에 일괄 지정해 다른 종류의 유일 가호를 반으로 깎지 않는다. **최신 사용자 발언의 '제일 강한 것 100%, 그 외 50%'는 기존 스탯별 규칙을 확장해 해석**했으며, 만일 사용자가 계약 하나를 전체 대표 100%로 지칭한 의도였다면 별도 확인 후 조정할 수 있다.
- 기존 공통 패시브/증표 효과는 **전체 유효 가호 증가분에 한 번** 적용. 가호 효과와 각 존재 고유 공격 권능이 동일 스탯을 중복 적용하거나 죽음 회피/반격을 n회 무료 발동하지 않도록 구분한다.
- 여러 계약의 서로 상충하는 서약은 사전 경고·면책/파기/위반 정책을 따른다. n이 커져도 모든 계약의 금기를 면제하지 않는다.

## 4. 플레이 밸런스·게임성 기준

- **세 번째 계약은 실제로 달성 가능한 야심찬 목표**, 네 번째부터는 더 큰 희생·특별한 선택이어야 하지만 **임의의 '3계약 이후 금지' 하드캡은 두지 않는다**.
- 저위계 계약 여러 개가 4위계 한 계약의 고유 주력 분야를 언제나 압도해 상위 위계를 무가치하게 만들지 않도록, 실제 보유 재료·준비 시간/가호·권능/금기·동시 입력 부담을 종합 비교한다. 동일 DPS를 강제하지 않는다.
- **체결 순서/계약 대상의 기본 제물값 차이 때문에 값비싼 계약을 먼저 사고 싼 계약만 나중에 더하는 '순서 악용'**, 재계약 반복을 실제 저장 상태·서버 게임테스트에서 검증해 경제 소프트캡이 무력화되지 않게 한다. 필요한 경우 기존 계약의 가치가 포함된 추가 제물 계산을 제안하되, 사용자가 확정한 *곱절 증가·3개 이상 허용* 방향을 훼손하지 않는다.
- 0/1/2/3/4/5개 계약, 높은·낮은 위계 혼합, 관계/심화 변동으로 스탯별 최고 가호가 바뀌는 경우, 금기 상호 충돌, 제물 부족, 중간 취소·동시 서버 패킷·사망/직업 전환/재접속을 통합 검증한다.
- **실제 수치 밸런스/어떤 가호끼리 겹쳐지는지/이능 단축키·모델/시안은 미구현·검증 전.** 비용표 숫자 1/2/4/8은 사용자 지정 배율의 규칙화이고, 각 존재의 기본 레시피와 전투 계수는 추후 플레이테스트 수치다.
