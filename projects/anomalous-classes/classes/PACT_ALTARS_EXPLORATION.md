## 0. 이전 사용자 승인·필수 보존

1. 계약술사 직업이 **단 한 명도 없어도** 제단 구조물은 월드의 탐험 콘텐츠로 존재한다. 모든 직업이 **제단 상자와 분위기에 어울리는 소규모 전리품**을 얻을 수 있고, 계약술사만 계약 핵으로 체결/심화/재협상할 수 있다.
2. 비계약술사가 계약 핵을 상호작용하면 간결하게 `이 제단은 계약술사만 사용할 수 있습니다.`라고 안내한다. 상자/발굴/주변 지역 전리품은 제한하지 않는다.
3. 계약을 한 번 눌러 바로 체결하거나 제물을 잃으면 안 된다. **상세 계약서→계약 진행→별도 최종 확인→서버 확정** 순서와 원자 소비 보장. 1위계는 제단 없이도 입문 계약 가능.
4. 4위계는 같은 유형의 저위계 대비 성능이 압도적이며 제물/위험도 무겁다. 추가 제물 심화, 관계 수치·금기·위약금·이중계약(약한 가호 50%)을 임의 변경하지 않는다.
5. **품질 방향:** 재미와 실제 이용 편의성, 보기 좋은 건축/모델/빛/애니메이션과 구현 성능을 우선. 16종을 의미 없는 동형 제단/지루한 16개 퍼즐로 만들거나, 반대로 16개의 거대한 독립 던전을 무조건 강요하지 않는다.
6. 제단 건축 이미지는 **reference**일 뿐 실제 배포 가능한 asset/직접 사용할 schematic으로 자동 승인되지 않는다. 외부 자산 사용 시 출처/라이선스 검토.

## 1. 핵심 플레이 루프와 난도

**평범한 서바이벌 탐험 → 지형 위에 눈에 띄는 유적의 흔적 발견 → 진입/전리품 탐색 → 중앙 의식 핵에서 존재 정체 확인 → (일반 직업: 귀환 / 계약술사: 계약서 확인·현재 계약 관리) → 희귀 제물·조건이 충분하면 의식 실행.**

- **탐험 보상은 계약 없이도 즉시 획득** 가능해야 한다. 전체 유적을 조사하려면 전용 계약 스킬/전용 부적/계약 UI가 필요하게 만들지 않는다.
- **긴 전투나 복잡한 퍼즐을 모든 제단에 강제하지 않는다.** 1위계는 단순 탐색, 2위계는 짧은 지형 특성, 3위계는 하나의 명확한 시련 또는 간단한 진입 선택, 4위계는 특별한 분위기와 하나의 의미 있는 의식/도전 정도를 후보로 둔다. 이는 계약 자격·시련과 유적 전리품 접근을 **구분**하는 원칙이다.
- **위험을 쉽게 알아보도록** 적절한 광원·폐허 흔적·초기 진입 경로를 둔다. 공격하지 않는 장식 몬스터·지속 경고 팝업·필요 없는 UI 상자 늘리기 금지.
- 발견한 핵 위치/제단 종류를 계약 관리에 간단히 기록하는 옵션. 자동 텔레포트와 무한 지도 핑 등은 기본 제공을 확정하지 않는다. 첫 발견 후 복귀 시 다시 1시간 구조물 찾기를 강요하지 말자.
- **1위계 첫 계약은 유적 RNG에 봉쇄되지 않는다.** 1위계 소형 유적 자체는 세계의 흔적/소규모 보상을 제공하지만 제단을 못 찾아서 직업이 무능해지는 일 없음.
- 최초 계약 UI에서 모든 제물·가호·금기·해약 위약금을 확인하고, 재료 부족이면 해당 항목을 알려주되 탐험 보상은 유지. 재료를 잃는 자동 계약/자동 서약 없음.

## 2. 제단 건축 공통 시스템 4계열

**네 건축 계열은 공통 블록/loot interaction/서버 계약 기술을 재사용하기 위한 제작 묶음일 뿐, 16종의 건축을 단순 팔레트 스왑으로 처리한다는 뜻이 아니다.**

| 건축 계열 | 소재/색/형태 | 자연 입지·서사 | 구분되는 공간 요소 |
| --- | --- | --- | --- |
| **성역** | 흰 석재·금빛/밝은 문양·광륜, 부서진 높은 기둥 | 평원·산등성이·넓은 동굴의 옛 성역 | 전면 계단→열린 홀→위로 빛이 스미는 핵 |
| **금단** | 검은 돌·붉은/재빛 표식, 부서진 왕좌·봉인문 | 동굴·산기슭·바위 협곡, 특정 고위 존재는 지하 넓은 의식실 | 구부러진 길→낮은 복도→극적인 금단 핵 |
| **거석** | 거대한 자연석·암반·석판·거인 손 모양, 규모 대비 작은 플레이어 | 높은 산·넓은 계곡·지하 대지 균열 | 멀리서 읽히는 거대 손/뿔/돌기둥→바닥 각인→핵 |
| **이형** | 별빛·심해 빛·비정상 기하·기록/뿌리/우주 이펙트 | 고원·연안·심해·오래된 숲 등 존재별 특화 | 외부에서 모양을 알아보는 기이한 실루엣→짧은 발견 연출→핵 |

**중심 UX 단일 규칙:** 주 구조물은 자연 생성된 건축 블록/정적 장식, 계약 핵은 간단한 서버 Block/BlockEntity 상호작용. 핵을 볼 때 근처 전체 엔티티를 매 틱 검색하거나 거대한 상시 애니메이션 인스턴스를 여러 개 생성하지 않는다. 활성 의식 때만 짧은 VFX·사운드/모델. 구현 방식은 Minecraft 버전·로더 선정 뒤 결정.

### 2.1 위계별 건축 규모 지향 (시험 범위)

| 위계 | 월드에서 느끼는 크기/발견 | 전리품·시련 역할 | 건축 직경 대략(후보) |
| --- | --- | --- | --- |
| **1위계** | 눈에 띄지만 부담 없이 탐사하는 작은 성소 | 소규모 상자, 기본 탐험 랜드마크, 계약 의식은 필수 아님 | 약 **12~20블록** |
| **2위계** | 언덕·동굴·해안에서 형태가 읽히는 유적 | 보통 탐험 보상, 지형 특징 1개, 계약 핵 접근 | 약 **22~36블록** |
| **3위계** | 먼 거리에서도 알아볼 수 있는 큰 성역 | 강력한 정체성/고급 전리품, 계약 자격 시험이 있을 수 있음 | 약 **36~56블록** |
| **4위계** | 희귀 지형에 연결된 종결 랜드마크 | 명확한 종결 목표, 보상은 모든 직업도 획득, 계약은 별도 | 약 **50~85블록** |

이 범위는 실제 자연 지형에 잘 배치될지 검증 전의 **크기 지향**이지 16개 전부를 85×85 사각 NBT로 생성하라는 뜻이 아니다. 물/산/지하와 만나는 곳은 지형에 맞춘 손상/부분 구조와 분할 템플릿을 검토하고, 자연 지형을 대량 덮어써 플레이어의 집을 부수지 않는다. 특히 4위계 제단을 초희귀 1개만 배치해 단일 멀티서버의 모든 플레이어 진입을 막지 않도록 한다.

| 4 | **비아르** | **첫 숲의 심근** / 오래된 거목 뿌리가 감싼 살아 있는 석조 성소 | 오래 자란 숲/울창한 숲·대체 숲 조건 | 뿌리 간격 길 → 따뜻한 발광 심장 | 식생·회복·희귀 식물·생존 보상 |

### 3.1 발견 가능성/바이옴 병목 방지

- 위 표의 바이옴은 **분위기 후보**다. 특정 희귀 바이옴에서만 4위계가 등장하고 월드 시드에 따라 그곳이 수만 블록 떨어져 있다면 실제 획득 난도가 지나칠 수 있다. 각 제단에는 2~3개 이상 적합 입지·대체 구조물 배치를 검토한다. 바다/산/숲 전문 존재는 테마를 유지하되 위치 찾기만 강제 노가다가 되지 않게 한다.
- 동일 장소에 여러 제단이 과밀하게 나오거나 마을/다른 구조물을 크게 덮지 않도록 **spacing/biome/height/surface 및 월드보호 안전**을 검증. 한 곳은 작아도 자주, 다른 곳은 거대하지만 희귀하게 한다.
- 위계별로 제단이 보이는 거리·흔적의 거리·실제 생성 빈도는 실제 탐험/지형 테스트 전에 임의 확정하지 않는다.
- 네더·엔드 이동을 기본 필수로 강제할지는 **프로젝트 전체 정책 미확정**. 따라서 표의 구조물은 우선 오버월드형 탐험 콘셉트이며, 제물의 차원별 획득 경로는 별도 다듬는다.

## 4. 전 직업 보상과 계약 보상을 깔끔히 분리

### 4.1 기본 전리품 (모든 직업 동일 접근)

- 모든 유적에 **눈에 띄는 보상처 최소 1곳**. 보통 상자 하나와 가끔 작은 숨겨진 저장처 정도로 간결하게 유지. 제단 핵에 계약하지 않으면 못 여는 보물방, 제물 바쳐야만 여는 일반 상자 금지.
- Loot는 `위계별 보상 값대`와 `계열/지역 테마`의 조합으로 설계해 재사용. **16개 독립 경제/전용 코인/전용 텍스처 아이템을 마구 늘리지 않는다**.
- **1위계:** 철·구리·금 조각·소량 음식/물약/발광 재료 등 발견했을 때 작은 이득. **2위계:** 자수정·엔더 진주/해양 소재·소량 물약/광물 등 수급 가치. **3위계:** 고급 제물 일부/인챈트 관련 확률 보상/생존 소모품. **4위계:** 고급 광물·특별 장식·인챈트 보상 일부와 매우 희귀한 가치 있는 물품(모두 확정 지급 X).
- 제단을 발견해 얻는 보물은 **제단이 요구하는 가장 중요한 종결 제물을 자동으로 모두 대체하지 않아야** 한다. 예: 네더의 별을 요구하는 계약의 바로 옆 상자에서 네더의 별 확정 지급 금지. 반대로 누군가가 모든 자원을 얻으려고 반복해 같은 제단만 돌 필요 없게 **일회 전리품** 기본.
- **추가 소형 발굴 요소(선택):** 일부 아르켄/리드나/이사엘 유적에는 유물 단서/수상한 모래·자갈 발굴 후보. 브러시가 없다고 필수 핵/핵심 일반 보상을 못 얻는 구성은 피한다. 바닐라 고고학 시스템처럼 일부 유적에만 분위기 보상으로 활용. 참고: [Minecraft 공식 트레일 유적 탐험](https://www.minecraft.net/en-us/article/trail-ruins), [Minecraft Wiki 고고학](https://minecraft.wiki/w/Archaeology).
- 상자 loot table/보상 횟수는 **월드 생성 1회(기본)**. 계약 체결/심화·파기/직업 변경으로 상자를 무한 리필하지 않도록 계약 블록 상태와 전리품 생성 상태 분리.

### 4.2 멀티플레이 보상 분배 (미확정 대안)

- **간단한 초기안**: 바닐라 유적과 같이 월드에 생성된 실제 상자/상태를 서버가 공유. 먼저 찾아 온 사람이 보물을 가져갈 수 있지만, **핵 계약/심화는 개인별 상태**라 상자 획득 여부와 무관하게 여러 계약술사가 같은 제단을 사용 가능.
- **멀티플레이 공정성이 문제라면 후속 옵션**: 플레이어별 최초 발견 보상/인스턴스 전리품. 단 개인 UUID별 전리품을 영구 기억/동기화하는 저장 부담·악용·UI가 크므로 실제 요구와 테스트 결과가 나오기 전 무조건 도입하지 않는다.
- **현재 사용자 확정:** 전리품은 계약술사 전용이 아니고 모든 직업이 접근 가능. **'각 플레이어에게 동일한 개인 보상을 보장'은 아직 확정하지 않는다**.

## 5. 계약 핵 상호작용, 제단 내 의식, 안전한 계약

- **비계약술사:** 우클릭하면 `이 제단은 계약술사만 사용할 수 있습니다.` 액션바. 소리/짧은 빛은 있어도 계약 목록·제물 소비 없음.
- **계약술사:** 현재 존재 이름·위계·대표 가호·필요 제물/보유량·서약/금기·정식 해약 위약금·기존 계약과 충돌·다음 심화·현현 종류를 단계적으로 표시. 이곳에서 가능한 행동은 `계약 보기` / 이미 체결했다면 `심화` / `계약 관리` 같은 맥락 기능만. 매 번 서약 경고를 10개 누르게 만들지 않는다.
- `계약 체결` 입력 전에 **별도의 명시적 최종 승인**이 필요. 미리보기/계약 진행 단계에서는 제물/현재HP/관계·채무 상태를 변경하지 않는다. 최종 승인 이후 서버가 조건을 재검증하고 **정확한 1회 원자 소비/상태 커밋**.
- 계약술사가 유적에서 상자를 얻는 것은 **개인 계약 한도/계약 가능한 존재/신앙 등과 무관**. 기존 계약을 먼저 해약하라고 보물 접근 차단 금지.
- **제단 핵 내구성**: 구조물 장식은 일반 월드/건축 규칙을 존중하지만 유일한 계약 진입 핵을 타 플레이어가 부숴 서버 전체에서 영구 이용 불가가 되지 않도록 보호/복구 방법 필요. 세부 파괴 가능성·서버 관리자 설정·WorldGuard 등 외부 모드와의 상호작용은 후속 기술 정책에서 결정.
- 시련이 필요해도 **계약 자격 심사**와 **일반 보물 찾기**를 분리한다. 고난도 시련에서 플레이어가 실패했다고 보물창고가 사라지는 일은 기본 정책으로 만들지 않는다.
- 모든 플레이어의 제단 상태/복귀 좌표/서버 권위 계약은 멀티/사망·재로그·월드 저장과 일치해야 한다.

## 6. 비용·품질·기술 구현 우선순위

### 6.1 개발 구조

1. 하나의 **공통 제단 상호작용/계약서/보상** 기반을 설계. 재료, 지역, 존재, 공용 아이템을 data-driven으로 유지한다.
2. 실제 건축은 **한 건축 계열당 대표 1종씩** 고품질로 시험한다. 우선 성역 이사엘, 금단 벨칸, 거석 우르겐, 이형 리드나 같은 1위계 대표 후보. 코어 모델·상자·월드젠 배치·적법한 서명 흐름 확인. 이들이 잘 되었다고 나머지 12종 검수 완료는 아님.
3. 2위계 카르다/네르아/셰로/하스텔을 도입할 때는 그 존재 고유 지형·외형/표면 발견을 시험. 특히 바닷속 입장·안전 공기주머니, 산/동굴 지형 절단/평탄화 방지.
4. 3·4위계는 대표 2종 정도의 **산·높은 성역·이형 다중 파츠** 월드젠 품질 검수 뒤 확장. 실제 크기/초당 생성량과 청크 충돌/구조물 스폰 밀도 실측.
5. 세계 구조물 배치에는 목표 Minecraft/로더에서 **검증된 Template/NBT·Structure Set·jigsaw/processor**, loot table, block entities 등의 가능성을 비교. **특정 API/버전/모드를 현재 확정하지 않는다.**
6. 외부 빌드 자산은 출처/라이선스 확보. 유료·미승인 schematics 무단 전송이나 무조건 복제 금지. 사용 허가된 schematic은 **editable base** 여부를 확인하고, 프로젝트 오리지널 구조물과 소재 밀도/디자인 언어를 일관되게 맞춘다.

### 6.2 비주얼 완료 기준

- **실루엣:** 아무 텍스트 없이 20~50블록 거리에서 계열과 장소의 특별함이 느껴지는가?
- **탐험 동선:** 입구→보상→계약 핵을 찾을 수 있고, 함정이나 난해한 길찾기가 기본 이용을 방해하지 않는가?
- **질감·환경:** 블록 팔레트·조명·자연 노후화·산/해양 접합부·간결한 이펙트가 일관되는가?
- **현현/의식:** 계약할 때만 적절한 모델/파편/광륜·사운드, 완료 시 크고 명확한 피드백. 고정된 3D 모델을 매틱 모두 재렌더/스폰하지 않는다.
- **멀티·기능:** 같은 제단에서 여러 명의 계약술사가 각기 다르게 계약/심화할 수 있고 비계약술사는 보물을 획득할 수 있는가? 계약자는 제물 소비·계약 상태 중복 없이 저장되는가?
- **성능:** 제단이 과밀 스폰되거나 월드젠을 오래 정지시키지 않는가? FPS/TPS와 구조물 로딩/메모리/BlockEntity 수를 실제 측정.
- **사용자 체감:** 보상이 쓸모 있는가, 유적이 단순 랜덤 장식에 그치지 않는가, 고위 제단 발견이 좋은 추억/목표로 남는가?
- 정적 이미지·외부 월드 링크·컴파일 성공만으로 실제 Minecraft 3D 화면/서버 성공이라고 주장하지 않는다.
