# 정신 지배자 — 지배체 조작·생존·저장 계약 (설계안)

> Status: DESIGN PROPOSAL / NOT APPROVED / NOT IMPLEMENTED / NOT TESTED. 2026-11-04. 이 문서는 실제 플레이 UX와 저장 경계에 대한 권장 구조이며 사용자가 정식 확정하기 전에는 최종 기획이 아니다. 구체 단축키, 거리, 보호 규칙은 플레이테스트 전까지 미정. 기존 보스·주민·말·동물 지배 가능, 정신력 유지비, 플레이어 피해 ON/OFF, 동행/대기/해제, 270랭크 장기 스킬트리와 충돌하지 않게 설계한다.

## 1. 외부 참고 사례·기술적 제약

- [Domestication Innovation](https://modrinth.com/mod/domestication-innovation/): 길들인 펫 Follow/Stay/Wander 전환, 아군 공격 관통으로 오폭 방지, 조건부 보호 및 회수의 장단점. 우리 게임은 복잡함을 줄여 동행/대기/해제 중심으로 사용하고, 원작의 펫 부활·인벤토리 저장을 그대로 복제하지 않는다.
- [Doggy Talents Next 명령 안내](https://doggytalentsnext.wiki.gg/wiki/Commands): 별도 개체 UUID를 활용한 locate/revive 관리 기능. 우리 게임은 개체 UUID를 중복 생성 없이 추적하는 점만 참고. 부활 기능 도입은 확정하지 않는다.
- [Minecraft Wiki — despawning](https://minecraft.wiki/w/Despawning): 일부 적대 몹은 자연 소멸하며, 이름표·영속성 플래그 등으로 방지할 수 있다. 조작해 만든 엔티티도 난이도를 Peaceful로 바꾸면 자연스럽게 사라지는 종류가 있어 기획의 '항상 절대 사라지지 않는다'를 기술적으로 무조건 약속해서는 안 된다.
- [Minecraft Wiki — Chunks](https://minecraft.wiki/w/Chunks): 언로드 청크의 엔티티는 처리가 정지된다. 전 세계 지배체를 항상 활성화하기 위한 강제 청크 로딩은 비용이 큼.
- [Fabric Data Attachments (26.2)](https://docs.fabricmc.net/develop/serialization/data-attachments): 엔티티 데이터의 persistent attachment/sync 수단 존재.
- [NeoForge Data Attachments](https://docs.neoforged.net/docs/1.21.10/datastorage/attachments/): 엔티티에 저장 가능한 attachment와 world SavedData 존재.
- 로더/버전은 아직 미정이므로 위 API 둘 중 하나를 이미 선택된 전제처럼 취급하지 않는다. 표준 기능과 외부 몹별 특수 기믹은 나중에 로더·모드팩을 선택한 뒤 검증한다.

## 2. 전투 중 조작 경험 — 가장 단순한 권장안

### 필수 기능

| 입력 시점 | 액션 | 응답 |
|---|---|---|
| 지배되지 않은 살아있는 대상 바라보고 '정신 침투' 시전 | 장악도 증가, 성공 시 지배 | 대상 위 장악도/저항, 정신력 부족·지배 한도 도달 명확한 안내 |
| 지배체 바라보고 **관리키 1회** | 간결한 개체 메뉴 열기 | 동행/대기, 공격 허용 ON/OFF, 지배 해제, 상태 |
| 지배체 바라보고 **Shift+관리키** | 동행↔대기 빠른 전환 (추천 단축) | 작은 토스트/사운드로 변경 확인 |
| 아무 대상도 바라보지 않고 관리키 | 간단한 지배 현황 열기 | 현재 N/최대 슬롯, 전체 유지 정신력/초, 전체 동행/전체 대기 및 간단한 위치 정보 |
| 지배체 메뉴에서 '지배 해제' | 의도 확인 후 해제 | 대상 생명체는 현재 자리에 남아 원래 AI로 복귀; 실수 방지 |
| 소유하지 않은 지배체 바라보고 관리키 | 다른 사람의 개체 관리 금지 | 간단한 소유자·상태 안내 또는 일반 상호작용 유지 |

- 키 이름·입력 우선순위는 아직 확정하지 않는다. 기본 Minecraft F(보조 손 교체), Q(드롭), E(인벤토리)와 충돌하는 키를 무심코 강제하지 않는다. 키 재바인딩을 지원한다.
- 동행/대기/해제/공격 허용은 이전 정본의 의미 유지. 플레이어 피해 OFF는 플레이어 근접·원거리·스킬 피해 차단(보호 범위를 일관되게). 비플레이어 적·환경 피해는 정상. ON이라고 주인에게 자동으로 적대하지 않는다.
- 전체 동행/전체 대기는 **기존 소유권 개체에 대한 명령 모드 전환**이지, 언로드 개체들을 즉시 생성하거나 강제로 월드에 불러오는 행동이 아니다.
- 지배체마다 애완동물/주민/철 골렘/보스의 원래 생태와 공격 패턴을 최대한 유지한다. 주민에게 임의로 공격 스킬을 만들거나 외부 보스 기믹을 삭제하지 않는다.
- 원거리 몹 명령을 위한 별도의 부대 편성, 20개 버튼, 개별 '우선순위 규칙 편집기'를 만들지 않는다.
- 관리 UX는 상용 게임·Minecraft 실제 화면을 참고해 목업을 검증한다. 지금의 메뉴/단축은 인터랙션 계약일 뿐 디자인/최종 아이콘이 아니다.

## 3. 실제 지배체 동작 상태

### FOLLOW(동행)

- 같은 차원, 로딩되어 실제로 시뮬레이션 중인 환경에서는 지배자가 이동하면 정상적인 원래 이동 능력으로 따라간다. 전투 가능 개체는 지배자의 적을 자동 공격한다.
- 길 찾기에 막히면 일정 시간 재경로 탐색을 시도하되, **매 tick 전체 주변 몹 검색/강제 청크 로딩** 금지.
- 거리 이탈 때문에 개체를 그냥 삭제하거나 새 복제 개체를 순간 소환하지 않는다.
- 같은 차원·로드 완료·전투 중이 아닌 경우에 한해 제한적 근거리 안전 위치 보정/회수 기능을 나중에 검토할 수 있다. 처음부터 보스·말·승객·보스 페이즈를 무차별 순간이동시키지 않는다.
- 다른 차원으로 이동할 때 자동 차원 순간이동·보스 강제 이동은 구현하지 않는다. 실제 포털을 통과하는 정상 동작은 원본 엔티티의 지원 여부와 외부 AI를 보고 결정한다.

### STAY(대기)

- 현재 위치의 실체를 유지하고 플레이어에게 따라오지 않는다. 공격 가능한 개체는 범위 내 적에게 반응할 수 있으나, 방어 대상/타깃 규칙은 추후 정한다.
- 주인이 온라인이고 해당 청크가 실제로 엔티티 처리 중이면 **개별+집단 유지비가 계속 든다**, 다른 플레이어가 주변에 있거나 주인이 다른 차원에 있어도 마찬가지. (원격 기지 수호를 무료로 제공하지 않음.)
- 청크가 언로드되면 모드의 별도 '무료 강제 로딩'은 하지 않는다. 그때에는 유지비와 개체 AI tick이 멈추지만 **지배 슬롯은 점유**하고 원본 개체 저장 상태는 유지.
- 대기 패시브 유지비 할인은 [MILESTONE_DESIGN.md](./MILESTONE_DESIGN.md)의 수치 후보이며, 오프라인 보관 자원의 복제 기능이 아니다.

### SUSPENDED(연결 휴면)

- 청크 언로드/오프라인 소유자/소유자 사망 후 복구 대기 등으로 일시 비활성. **지배 해제 상태가 아니라 원래 지배체와 연결되어 있는 상태**이다. UUID/소유자/행동 명령 유지; 슬롯 점유.
- 언로드 시 AI·유지비 처리 없음. 다른 플레이어가 청크를 로드해 소유자가 오프라인인 경우에는 지배체를 휴면 대기로 놓고 공격/추격 행동을 하지 않게 한다. 다만 외부 적/환경으로부터 무적이 되는 설정은 아니다.
- 소유자 오프라인에 정신력이 자연적으로 무한 충전되거나, 언로드 중 비용이 음수로 정산되는 일이 없게 한다. 로그인 후 저장된 정신력과 개체 상태를 복구한다.
- 이 정책은 '온라인인 동안 강한 보스 유지에 실제 비용이 든다'와 '오프라인으로 지배체를 잃지 않는다'를 동시에 만족시키려는 권장안이다.
- 소유자가 돌아왔을 때 로드된 개체와의 연결을 재검증하고, 정신력 부족이면 안전한 개체별 해제 정책에 따른다. **보스만 시간이 지나면 무조건 해제되는 규칙은 없다.**

### RELEASED / DEAD

- RELEASED: 지배 상태/유지비/강제 영속성 보정 제거, 원래 소유권·길들이기/안장·마을/거래·생태 상태 복원. 같은 UUID의 원래 엔티티가 계속 존재한다.
- DEAD: 세계 안에서 실제로 사망한 엔티티는 제거, 슬롯 반환 및 지배 기록 정리. **무료 자동 부활/무료 재소환은 도입하지 않는 안**. 선택적 도감에는 '지배에 성공했던 종류/기록'을 남길 수 있다.
- 악용 방지: 지배/해제 반복으로 전리품·경험치·보스 처치 플래그·마을 보상 등이 복제되어서는 안 된다.

## 4. 사건별 기대 결과

| 상황 | 행동 | 소모/보관 계약 |
|---|---|---|
| 정상 근거리 이동 | FOLLOW에 따라옴 | 로드되고 소유자 온라인이면 일반 유지비 지불 |
| 너무 멀어져 청크 언로드 | 해당 위치·차원에 저장된 원본 개체가 잠듦 | 유지비 중지, 슬롯 점유, 위치 정보 저장 |
| 다른 차원으로 이동 | 반대편 차원의 실체는 원래 위치에 남음 | 원격 청크가 로드되고 온라인이면 유지비, 언로드면 중지 |
| 로그아웃 | 지배 관계 유지, 로드된 개체는 오프라인 휴면 | 유지비 중지, 정신력 재접속 시 복원 |
| 서버 재시작 | 저장된 관계·명령·피해 허용값 복구 | 별도 개체 새로 스폰하지 않음 |
| 소유자 사망 | 소유 개체는 사라지지 않고 **그 자리 대기·휴면** | 슬롯 유지, 부활 후 적절한 위치에서 재연결. 사망으로 무료 정신력 리셋·복제 불가 |
| 개체 자체 사망 | 원래 생명체 사망 결과 | 슬롯 반환, 자동 부활 없음 |
| 지배 해제 | 현재 위치에 실체 유지·원래 상태 복원 | 슬롯 반환; 원래 적대 개체는 플레이어를 다시 공격할 수 있음 |
| 평화로움 난이도 전환 | 자연 소멸하는 적대 타입과 충돌 가능 | 바닐라/외부 모드 소멸 동작 검증이 필요; 절대 보존 보장 불가 |
| 다른 플레이어가 소유한 길들인 생물 | 소유권·PvP/서버 권한 정책과 충돌 가능 | 서버 규칙에 따른 보호/허용 정책을 별도 결정; 타인 소유권 데이터 강제 덮어쓰기 금지 |

## 5. 실제 저장 구조 권장

### 원본 엔티티(단일 실제 개체)에 귀속하는 영속 정보

- 실제 **entityUUID** (중복 불가, 새 복제 생명체 생성으로 회수하지 않음).
- 소유자 **playerUUID**, 지배 상태(활성/휴면/해제), FOLLOW/STAY, 플레이어 피해 허용 ON/OFF.
- 대상 **dimension**, 마지막으로 정식 저장된 위치, 소유자와 재결합할 조건.
- 지배 전 원본 persistence/despawn 관련 플래그, 기존 tame owner/안장/직업 및 원래 AI를 훼손하지 않기 위한 adapter용 최소 상태.
- 외부 보스의 phase/arena/world state는 원본 모드가 계속 책임진다. 지배 링크만으로 보스 월드 상태의 리셋·중복 클리어를 발생시키지 않는다.

### 플레이어/월드 Registry (조회·슬롯 계산)

- `playerUUID -> [entityUUID + dimension + lastKnownLocation + commandMode + status]` index. 최대 동시 지배 수를 셀 때 **언로드/휴면 개체도 포함**한다.
- 원본 엔티티가 실제로 로드되면 UUID로 Registry와 교차 확인 후 복원·중복 정리. Registry에 있어도 엔티티가 죽었거나 제거된 상태라면 적절한 엔티티 제거 이벤트/불일치 처리 절차로 정리한다.
- 저장의 **진실 소스는 실제 엔티티의 영속 상태**, Registry는 잃어버린 개체 확인·슬롯 계산·위치 파악용 색인이다. 언로드 시 최신 상태를 잃지 않도록 서버에서 변경 시 양쪽을 **원자적으로/일관되게** 갱신해야 한다.
- 죽음/차원 이동/복제·변신 등에서 entity UUID가 변경되는 외부 모드 기믹은 임의의 새 개체로 주인 복제하지 말고, 변신 이벤트와 원본 UUID 매핑을 검증한다.
- 위 구조는 로더 미선정이므로 Fabric persistent data attachment, NeoForge serializable attachment 등 후보 방식이다. 정확한 저장 API와 동기화는 실제 버전 결정 후 검증한다.

### 명시적인 보존 한계

- 청크 언로드는 **주인과 거리 이탈 = 개체 사망**으로 취급하지 않으며, 저장된 실체를 잃지 않아야 한다.
- 지속적인 유료/강제 청크 로딩 금지, 글로벌 모든 개체 매 tick 검색 금지. 일정 주기/이벤트 기반 추적.
- 원래 엔티티를 'Pokéball'처럼 마음대로 전자 데이터로 복제·재생성하거나 동시 소환하는 기능은 이번 기본 범위에서 제외한다.
