## 1. 이번 사용자 결정의 의미

- **군체술사는 군체 관리 패널을 직접 여는 전용 단축 조작이 있어야 한다.**
- **전투 도중에도 짧은 입력만으로 빠른 설정과 전술 변경**이 가능해야 한다. 멀리 돌아가는 메뉴, 3개 이상 깊은 하위 메뉴, 상시 마우스 커서 점유, 일일이 생물 지휘를 요구하지 않는다.
- 군체의 공격/엄호 분담, 적에게 맞아 실제 죽는 엄호·비행 개체, 자연 증식, 원격 표적 지정, 비행 시 일부를 운반에 배정, 시야 보전은 이전 승인 방향을 유지한다.
- 이전 문서의 '수동 비율 슬라이더/개별 편성 창은 필요 없음'은 **강제로 관리 노동을 만들지 말라**는 의미였지만, 이번 **사용자 요청의 직접 설정 권한을 막는 제한으로 사용하지 않는다**. 오히려 **관리 패널에서 선택형 비율 설정을 제공하되, 빠른 설정은 프리셋으로 편하게** 하는 방향이 최신 제안이다.
- **각각의 실제 마릿수, 화면 레이아웃/그래픽, 기본 키, 홀드 판정 시간, 비율/가속·전환 시간**은 이번 신규 세부 제안이며 확정되지 않았다.

## 2. 두 단계 조작: 패널과 전투 퀵 설정

### 2.1 빠르고 일관된 기본 조작 후보

| 입력 후보 | 결과 | 중요한 구현 조건 |
|---|---|---|
| **공통 직업 관리키 짧게 탭** (`G` 가칭) | 군체 **상세 관리 패널** 열기/닫기 | 관리키는 프로젝트 다른 직업의 공통 관리 액션과 충돌하지 않고 현재 직업에 맞게 표시. 실제 기본 물리 키는 키바인딩 통합 때 확정 |
| **같은 키를 약 0.20~0.25초 길게 누르기** | **전술 퀵 휠**을 누르는 동안만 화면에 표시 | 방향/마우스 움직임으로 전술 선택, **키를 놓으면 한 번만 확정**. 중심/취소/ESC는 변경 없이 닫기. 오조작 방지 |
| **휠 열린 상태에서 선택 키/숫자(옵션)** | 화살/키보드만으로 전술 선택 | 숫자 1~4를 쓰면 바닐라 핫바 숫자 전환과 동시에 동작하지 않도록 GUI 입력 컨텍스트에서 소비. 실제 사용성 테스트 전 후보 |
| **기존 원격 표적 지정 키** | 현재 목표 직접 지정 | 퀵 휠·관리창을 열지 않고 언제든 가능; 군체를 따로 선택하지 않음 |
| **비행 기존 전환 키** | 비행 모드 시작/종료 | 전술 퀵 설정이 비행 모드 자체를 무단 켜거나 끄지 않음 |

- **핵심 기능은 1개 '직업 관리' 동작에서 짧게/길게 누르기로 분기**하는 추천. 본 게임 설정의 키맵에서 재설정하고, 모드 키충돌/키 홀드 접근성 문제가 있으면 **패널 키/퀵휠 키 2개 분리 설정**을 대안으로 허용.
- 퀵 휠은 여러 단축키를 외울 필요 없도록 **4칸만** 제공: **자동 / 공격 우선 / 균형 / 엄호 우선**. 자세한 수치는 패널에서 수정.
- Hold 판정이 풀려 탭이 한번 처리된 뒤 휠이 또 열리는 문제를 막기 위해 **짧은 누르기 결정은 키를 뗀 시점**, 긴 누르기는 누른 시간 임계를 넘으면 한 번 진입. 키 반복/중복 요청 억제.
- 퀵 휠에서는 카메라를 잠시 고정/메뉴용 마우스 입력으로 분리하되, **WASD 이동·군체의 서버 전투/방어/비행은 멈추지 않음**. 멀티 서버에서 시간 정지 같은 게임 치트를 만들지 않는다. 휠이 열린 시간에도 몹은 공격 가능하므로 선택은 짧게 끝나야 한다.
- Esc/채팅/인벤토리/사망 화면/포털 전환·미포커스에서는 퀵 입력을 종료·취소하도록 하고, 다른 모드에 조작 중인 GUI가 열렸다면 기본적으로 이 UI를 무단 중첩하지 않음.

### 2.2 퀵 프리셋 후보와 실제 전술 의미

| 빠른 전술 | 플레이어가 기대하는 역할 | 예시: 지상 N=80일 때 | 비행 N=80일 때 |
|---|---|---|---|
| **자동 (기본)** | 근접 위협·현재 표적·비행 상황을 보고 **공격/엄호 비중 조정** | 보통 공격/엄호를 동시에 유지 | **필수 비행 개체 예약** 후 남은 군체를 적절히 분배 |
| **공격 우선** | 지정한 적을 빠르게 밀어붙임. 엄호는 최소 수준 가능 | 예시 공격 68 / 엄호 12 | **비행 30을 먼저 예약**, 나머지 50을 공격에 더 많이 할당 |
| **균형** | 공격과 엄호의 사용 비율을 안정적으로 유지 | 예시 공격 60 / 엄호 20 | 비행30 / 공격30 / 엄호20 예시 |
| **엄호 우선** | 위험한 원거리 공격·보스 전투에서 주인 보호 | 예시 공격40 / 엄호40 | 비행30 / 공격20 / 엄호30 예시 |

- **예시 수량은 시험값**이며 사용자 승인 비율이 아님. 공격/엄호 75:25 또는 50:50은 상황 설명용으로, 실제 N/레벨/지형/적의 위치/활성 군체 손실에 따라 **서버가 자동으로 유효 인원을 재할당**한다.
- 비행 중에는 플레이어를 들어 올릴 `liftReserve`를 **모든 전술보다 높은 안전 우선순위로 확보**. 전술을 공격 우선으로 바꾸어 운반 개체를 무단 소모하거나 강제 추락시키지 않음. 비행 자체의 시작·종료는 별도 기존 입력으로.
- 비행 군체가 적 원거리 공격을 맞아 줄어들면 먼저 남은 개체에서 유한한 재배치를 시도하고, 부족하면 이전 기획의 **감속 안전 하강**. 이 재분배는 무적·순간이동·수량 무료 생성이 아님.
- 엄호 우선으로 바꾸어도 **공격대 0 고정** 또는 **플레이어 무조건 100% 원거리 무적**이 되지는 않음. 보호는 유효 군집 위치·탄도 충돌·현재 수량/내구 조건을 따라야 함.
- N이 낮아 프리셋 요구량을 채울 수 없으면 **절대 불가능한 목표 인원**을 화면에 기만적으로 보여주지 않음. 가능한 역할만 배정하고 작은 설명 `군체 부족 — 엄호 인원이 줄었습니다.` 정도를 필요할 때 한 번만.

## 3. 군체 관리 패널: 단일 화면, 당장 쓸 설정

### 3.1 정보 구조 (제안, 화면 디자인 확정 아님)

**간결한 단일 패널**에 다음을 우선 보여준다.

1. **상태/수량**: 현재 N / 최대 N, 재증식 상태(초당 숫자 상시 노출 불필요), 현재 표적 이름·거리/유효 여부, 비행중/지상 등.
2. **현재 역할 분담**: 공격·엄호·운반·재집결의 실제 마릿수. 단 하나의 **분할 비율 바**(Stacked bar)로 보기 쉽게 표시. 전투 HUD에 같은 바 3~4개를 영구 추가하지 않음.
3. **전술 즉시 변경**: 자동/공격 우선/균형/엄호 우선의 네 가지. 패널에서 누르면 퀵휠과 똑같은 서버 전술 변경 요청으로 처리.
4. **선택적 '사용자 지정'**: 원한다면 **공격:엄호 우선 비중을 한 개의 조절기**로 설정. **운반은 비행 안전 최소량 자동 예약**이므로 매번 3개 슬라이더를 정교하게 맞출 필요 없음. 사용자 비율은 즉시 저장/적용하고 다음 퀵휠 선택 항목으로 유지할지 여부는 플레이테스트 뒤 결정.
5. **개체 성장 정보는 간략히**: 개체 공격·소실 내구·자연 증식 효율을 읽기 쉬운 숫자/설명으로, 투자는 공통 **스킬 트리**에서. 여기서 개체별 장비/레벨/식량/분화 UI를 새로 만들지 않음.
6. **표적 해제·군체 복귀**: 필요 시 `표적 해제`/ `복귀` 정도의 명확한 명령. 긴 명령 큐·일일이 개체 선택 없음. 반격 불가능한 아군이나 해제된 전투 대상에게 자동 타격 남지 않도록 함.

- **전체 정보는 서버 상태가 정본**. 패널은 클라이언트에서 최신 스냅샷을 구독해 읽고 전술/표적/복귀만 명령. 임의 마릿수 수정/체력 치트 불가.
- 버튼 위치/숫자/프레임/폰트/아이콘/애니메이션은 상용 게임 레퍼런스와 실제 Minecraft Screen에서 설계. 현재 설명을 그대로 회색 임시 상자 UI로 그려서 완료하지 않는다.
- **플레이어 시야:** 패널은 필요할 때 열고 닫는 UI이고, 평소 HUD는 N/최대 N와 현재 전술의 **작은 아이콘**만 필요. 모드가 전투 HUD 위에 커다란 검은 창을 상시 띄우지 않음.
- **전술 전환 효과:** 짧은 소리/작은 아이콘 교체/군체 진형 변화를 인지할 수 있게 하되 화면 전체에 불필요한 개발자 글·토스트·채팅로그를 남발하지 않음.

## 4. '즉시 명령'과 실제 군체 이동은 구분

- 빠른 설정 적용은 **사용자 입력 즉시 서버로 요청**되며 서버는 소유자/현재 직업/군체 활성 여부/유효 모드/비행 필요 운반량/같은 tick 중복 명령을 검사해 **다음 서버 갱신 시점에 '목표 분담'을 확정**할 수 있어야 한다.
- 실제 역할 전환은 **군체가 이동·재집결하는 짧은 과도기**를 거치며, 공격대가 월드 반대편에서 즉시 플레이어 몸 앞으로 순간이동해 화살을 무료로 막지 않는다.
- 저장/서버 모델 후보: `playerId, selectedTactic, optionalCustomAttackGuardWeight, targetN{attack,guard,lift,regroup}, actualN{attack,guard,lift,regroup}, priorityTarget, movementState, pendingDamageByGroup, seqNumber`.
- `actualN.attack+actualN.guard+actualN.lift+actualN.regroup=totalAlive`를 정확히 유지하고 실제 피격/스킬 소모/자연 증식에 따른 수량 변경과 **역할 재배치 명령이 한 개체를 중복 감소/복제**하지 않게 함.
- UI는 요청 성공 확인 전 즉시 '적용 완료'라고 단정하지 않는다. 짧은 활성 표시를 보여주고, 서버 승인/변경/거절 시 해당 모드/유효 분담량을 업데이트.
- 퀵 명령은 상태 변화로만 전송(마우스 hover마다 반복 패킷 전송 금지), **실제 개체 수/비행/엄호 피격**은 필요 시 동기화. 큰 군단이 전술 바꾼다고 수백 개 독립 AI·경로/사운드가 새로 생성되지 않음.
- 안전/성능: 취소 입력, 빠른 연타, 퀵휠에서 마우스가 중립 영역, 평시/전투, 비행중, 군체 부족/0, 목표 사망/재접속/차원변경, PvP 및 다수 플레이어, 모드 키맵 충돌 검사.

## 6. 완료 판단 전 실제로 검증할 것 (미실행)
