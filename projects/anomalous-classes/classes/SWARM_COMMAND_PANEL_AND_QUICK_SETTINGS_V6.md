## 1. 사용자 직접 확정사항 — 임의 고정 전술 제거

- **관리 패널 전용 단축 조작**과 **전투 중 빠른 전술 설정/실시간 전환**을 지원한다.
- **게임이 이름과 역할이 정해진 전술을 사전 제공하지 않는다.** ‘자동’, ‘공격 우선’, ‘균형’, ‘엄호 우선’이라는 고정 4종 프리셋은 **제안 취소**. 기본 UI에 이 이름을 강제하지 않는다.
- 플레이어가 **전술마다 공격·엄호 비율을 직접 설정**하고, **원하는 이름**을 붙여 **저장·수정·교체·삭제**할 수 있다. 플레이어가 만든 전술이 곧 빠른 전술 선택 목록이 된다.
- **퀵 설정 자체도 직접 편집 가능해야 한다.** 관리 패널에서만 설정을 바꿀 수 있고 퀵 메뉴에서 단순히 고정 전술을 클릭해야 하는 형태가 아니다. 다만 전투 중 한 번의 짧은 입력으로 **이미 저장한 나만의 전술로 즉시 전환**하는 길도 유지한다.
- 개체 1마리씩 육성·지휘/재료·먹이/수리·인원 수동 이동 노동을 강제하지 않는다. 전술의 목표 분배를 플레이어가 정하고 **실제 물리 군체 이동·충돌/피격/증식은 기존 서버 원칙**을 따른다.
- 군체 비행 중에는 **필수 운반 개체 예약은 추락 방지라는 물리 제약**으로 남는다. 저장한 공격:엄호 비율은 **비행을 유지한 뒤 남은 군체**에 적용하며, 안전 개체를 전술 변경 때문에 희생/복제하지 않는다.

## 1.1 8차 최신 확정 — 엄호는 사용자 전술 역할

- **군집 엄호는 액티브 스킬이 아니다.** 플레이어가 직접 지정한 전술의 **엄호 비율에 따라 상시 진행하는 방어 행동**이며, 빠른 전술 변경은 현재 목표 비율과 실제 군체 이동만 바꾼다.
- **엄호 전용 스킬 키/슬롯/쿨타임/지속시간/별도 버프 UI 없음.** 엄호 비율0%일 때는 엄호군이 0이고, 100%일 때는 엄호 전담이다. 별도 버튼으로 전술을 몰래 덮어쓰지 않는다.
- 공격 액티브는 **군집 급습**과 **군체 소모** 두 종류만 현행 후보로 유지한다. 무료 원격 표적 명령/비행/전술 설정은 스킬 슬롯이 아닌 기본 조작.
- 엄호군이 실제 근접·화살 공격에 맞아 군체 수가 감소하고, **비행 중 필수 운반군 예약은 안전 예외**로 계속 유지한다.

## 2. 조작 설계 제안 (기본키·제스처 확정 전)

| 사용자 행동 | 결과 | 비고 |
|---|---|---|
| **직업 관리키 짧게** (예: `G`, 미확정) | 군체 관리 패널을 여닫음 | 공통 직업 관리 동작, 키 재바인딩 필수 |
| **직업 관리키 길게** (예: 0.20~0.25초, 미확정) | 내가 저장한 전술의 **빠른 설정 휠** | **고정 전술명 없음**. 현재 전술 이름/비율을 사용자 데이터로 렌더 |
| **휠에서 저장된 전술을 선택하고 놓기** | 서버에 해당 전술 적용 요청 1회 | 전투/이동/비행은 정지하지 않음 |
| **빠른 설정 편집 행동** (휠 선택 상태의 보조 입력/수정 진입, 미확정) | 휠에서 바로 **공격:엄호 비율을 조절하고, 전술 이름 수정/저장** 가능 | 관리창으로 깊게 이동할 필요 없이 간단한 즉시 수정; 키·휠 UX는 인게임 검수 필요 |
| **관리 패널에서 새 전술 생성/편집** | 이름·공격:엄호 비율·빠른 목록 배치 저장 | 슬롯 수 4~6개 정도는 **임시 후보**이며 실제 한도 미확정 |
| **기존 원격 표적 지정 키** | 멀리 있는 유효 적을 현재 공격 목표로 지정 | 전술 변경과 독립, 무군체소모 |
| **비행 전환 키** | 군체 운반 비행 시작/종료 | 전술 변경만으로 비행이 임의로 꺼지지 않음 |

- 탭/홀드는 **키를 뗀 시점**까지 짧은 누름인지 판정하여 패널·퀵휠 동시 열림 방지. 사용자가 원하면 관리/퀵휠 키를 분리 설정할 수 있는 접근성 대안도 검토.
- 퀵휠은 저장한 전술 이름과 현재 공격:엄호 비율을 표시하며, **비어 있는 칸은 새 설정을 만드는 자리**다. 유저가 이름을 정하지 않은 빈 칸에 ‘자동’ 같은 뜻이 있는 추천 전술을 몰래 채우지 않는다.
- **신규 전술의 최소 초기 상태**가 필요하면 ‘현재 직접 설정(미저장)’ 편집 상태 또는 중립적인 미지정 슬롯을 보여준다. 서버의 엔티티 유지·자연 증식·비행 안전 등 **기본 AI 동작**은 존재하지만 **플레이어용 고정 전술 ‘자동’과 혼동하지 않는다.**
- 실제 전술 저장은 명시적 저장 또는 적용+저장 구분; 전투 중 빠르게 비율을 변경했을 때 원래 전술을 무단 덮어쓰지 않도록 ‘일시 적용’/‘저장’ UX를 명확히 한다.
- 이름은 한글·영어·숫자·일반 문자로 자유롭게 입력하고 전투 휠에 표기한다. 화면 침범/채팅·제어 문자/공백만 이름/저장 악용을 막기 위한 **합리적인 길이 제한 후보**, 사용자 임의의 의미 있는 이름은 금지하지 않는다.
- 캐릭터/월드 저장의 사용자 전술은 재접속·차원 이동·죽음 이후에도 안전하게 보존. 최대 저장 슬롯 수와 서버 권한은 후속 결정.

## 3. 전술 데이터 — 사용자가 전부 정의

**전술 구성 최소값:** `customTacticId`, `playerDefinedName`, `attackWeight` (0~100%), `guardWeight` (합계 100%), `ordering/quickSlot`. 공격과 엄호가 각각 **0%가 되어도 플레이어가 명시적으로 고른 결과**라면 허용하는 방향을 검토한다. 안전한 기본값이 필요할 때에도 ‘개발자가 제공하는 공격 우선 전술’ 따위의 숨은 전술을 만들지 않는다.

| 플레이어가 직접 지을 수 있는 이름의 단순 예 | **플레이어가 직접 정한** 공격 비율 | **플레이어가 직접 정한** 엄호 비율 |
|---|---:|---:|
| ‘보스전’ | 40% | 60% |
| ‘전력 돌격’ | 90% | 10% |
| ‘화살 방어’ | 20% | 80% |
| ‘탐험용’ | 65% | 35% |

**위 네 줄은 예시일 뿐 게임에 제공하거나 강제하는 이름·비율·프리셋이 아니다.** 사용자는 어떤 이름과 비율이라도 만들 수 있다.

### 3.1 실제 배분 규칙

- **지상:** 살아 있는 총 N 중 유효한 재결집/도달 전 이동 상황을 제외한 현재 **배분 가능 인원**에 플레이어가 정한 `attackWeight:guardWeight`를 적용. 실제 N은 피해/증식/표적 거리/재결집으로 달라질 수 있다. UI는 **설정 목표 비율**과 **현재 실제 분담**을 구분한다.
- **비행:** `available = totalAlive - liftReserve - regroupN`; `attackTarget ≈ available * attackWeight/100`, `guardTarget ≈ available - attackTarget`. 비행에 필요한 최소 운반 개체 `liftReserve`는 **예외로 보호**하지만 그 이상의 자동 공격/엄호 성향 전환을 플레이어 모르게 하지 않는다.
- **예: 총80, 비행용30, 재결집0, 사용자 정의 공격80%·엄호20% → 공격40/엄호10/비행30.** 다른 설정이면 다른 비율이 적용된다. 이 숫자는 기능 예시이며 비행 필요 개체 30은 확정값이 아님.
- **상태 변화**: 엄호 개체가 적 화살을 대신 맞아 죽으면 guard 실제 수량 감소, 운반 개체가 피격되면 비행 안정성이 감소. 유효한 대체 개체는 실제 위치/거리·안전 규칙 안에서 **유한한 시간 동안** 이동 배분, 즉시 무료 화살 차단/순간이동 불가.
- **공격 100% / 엄호 0%** 선택 시 플레이어는 엄호를 포기해도 괜찮지만 비행 유지 안전 개체는 여전히 예약된다. **엄호 100%**를 선택하면 공격대가 없거나 소모기 사용 불가할 수 있으므로, 패널에 한 줄로 영향을 알려주되 거부하거나 자동 공격 20% 강제하지 않는다.
- 한 명의 군체가 여러 그룹에 중복 집계되면 안 됨: `actualN.attack + actualN.guard + actualN.lift + actualN.regroup = totalAlive`.
- **전술 변경은 값·역할 목표를 빠르게 적용하되 실제 군체 위치 이동은 연출과 서버 판정에 맞는 시간**이 든다. 플레이어에게 변경이 끝났다고 거짓 피드백을 표시하지 않는다.

## 4. 군체 관리 패널 (하나의 화면)

1. **군체 현재/최대 수량** `N/Nmax`, 원격 표적, 비행/지상 상태, 실제 공격·엄호·운반·재결집 인원.
2. **나만의 전술 목록**: 사용자 정의 이름, 저장된 공격/엄호 비율, 현재 활성 여부, 순서, 재정렬/빠른 슬롯 배치, 변경/삭제.
3. **전술 편집**: 이름 자유 입력, 하나의 비율 조절기(공격%·엄호% 합 100), 필요하면 숫자 직접 입력으로 정확한 값 지정, 저장 / 일시 적용 / 취소.
4. **빠른 설정에 노출할 전술 지정**: 저장 전술을 단축 휠에 원하는 순서로 배치. 휠의 방향 수/한도는 사용성 테스트 후.
5. **개체 성장 정보**: 군체 전체 공격·내구·자연 증식 효율 간단히 표시, 업그레이드는 기존 스킬 트리/군체 핵 시스템 이용(추가 개체별 장비 UI 없음).
6. **표적 해제/군체 복귀**: 실제 적/소유권/원격 지정 원칙 보존, 되돌리기 어려운 삭제는 명확한 확인.

- 평상시 **HUD에는 N/Nmax, 현재 선택한 사용자 지정 전술의 이름/아이콘을 짧게**, 표적/비행이 의미 있을 때만 상태 보조. 모든 역할 슬라이더·관리 화면을 상시 표시하지 않는다.
- UI는 **실제 게임 화면의 크기·키보드·마우스·창 크기·GUI scale**에 맞추고 개발자 로그·임시 코드명/검은 반투명 사각형 남발 금지. 이 문서는 **정보·조작 계약**이지 최종 시각 디자인이 아니다.

## 5. 서버 권한/검증

- **사용자별 전술 저장**: `playerUUID -> [tactic{id, displayName, attackWeight, quickSlot}, ...]` 와 `selectedTacticId`, `temporaryOverride`, `actualN/targetN`. 다른 플레이어가 임의로 이름/비율/현재 전술 변경 못 함.
- **명령은 즉시 요청**하며 서버는 사용자 소유권, 직업, 전술 ID, 허용된 0~100 비율과 합 100, 문자열 길이/제어 문자/중복 요청, 비행 최소 운반 인원, 군체 N 상태를 검증해 다음 갱신에서 승인/실패 반환.
- **이름은 게임 내 자유롭되** 저장 데이터를 깨는 제어 문자/비정상적으로 긴 이름 등만 서버가 검증. 일반 단어 제한이나 플레이 스타일 강제 규칙 X.
- 반복된 휠 hover에 전술 서버 요청 발송 금지. **실제 전환 입력/비율 저장/일시 적용** 시점에만 패킷 전송. 아주 빠른 연속 교체는 마지막 승인된 요청/sequence 처리로 이전의 늦은 응답이 최신 값을 덮지 못하게 한다.
- 멀티 TPS·FPS 성능을 위해 개별 생물 전부를 새 소환하지 않고 기존 군집의 목표 역할/위치만 조정. 부하가 높은 상황도 N/공격·엄호·비행 수량·실제 적 탄도 피해가 보존되어야 함.
- 클라이언트 UI는 승인 전 완료를 확정해 보여주지 않으며 **요청 중 / 적용 완료 / 실패 사유**를 자연스럽게 처리. 에러를 채팅 스팸하지 않음.
- 서버 재접속, 죽음, 차원 변경, 이동 도중 패널 열기, 비행 부족, 퀵 휠 취소, 전술 이름 변경/삭제 중 선택한 현재 전술의 유효 ID, 저장/불러오기 검증.

## 5.1 7차 실전 통합 검수 연결

[**커스텀 비율 0/100 예외·군체 급습/소모/엄호·비행·화살 실피격·자연 증식 통합 시나리오**](./SWARM_TACTICAL_COMBAT_INTEGRATION_V7.md)

- 플레이어 공격100%/엄호0%로 설정하면 **숨은 기본 엄호 전술이 개입하면 안 된다**. 공격0%/엄호100%라면 표적은 기록해도 공격/급습/소모에 가상의 공격대를 만들지 않는다.
- 비행 시 최소 운반 개체만 예외로 먼저 예약하고 나머지는 저장한 전술 비율로 배분한다. 전술 변경은 **목표 배분 즉시 요청/실제 생물 이동은 시간 소요**, 이미 맞은 원거리 피해를 되돌리거나 군단을 순간이동시키지 않는다.
- 전술이 0개인 새 캐릭터의 기본 동행/생존 동작은 가능하나 **명명된 자동 프리셋/게임이 지정한 공격·엄호 전술을 저장하지 않는다**. 첫 전술은 플레이어가 직접 만들고 이름을 붙인다.

## 6. 우선 구현/UX 검증 (미실행)

1. **플레이어가 아무 전술도 만들지 않은 상태**: 고정 이름 4종이 자동 등장하지 않고, 적절한 안내로 첫 전술을 직접 지정. 게임 플레이 자체는 군체 기본 동작으로 계속 가능.
2. 사용자가 ‘보스전’ 공격40%/엄호60%, ‘탐험용’ 공격80%/엄호20%라는 **직접 만든 예시 설정**을 만들고 퀵휠 배치/이름 변경/삭제/순서 변경/저장.
3. 전투 중 퀵 메뉴 진입→저장 전술 즉시 전환, **퀵 메뉴 내에서 비율 직접 수정/일시 적용/저장**, 키 조작/ESC 취소/바닐라 단축키 충돌.
4. 지상/비행 중 동작; 비행 30/N80 같은 예시에서 사용자 설정 80:20을 실제 서버 목표 분담 40/10/30으로 계산하고 충돌 없이 적용. 화살이 엄호대에 실제 적중하면 N이 줄며 모델 사망 표시.
5. `100:0`, `0:100`, `33:67`, 전술 0개, 군체 0마리, 낮은 N, 중복된 이름(저장은 전술 ID로 구분), 긴 한글 이름, 여러 사람이 같은 이름을 쓰는 멀티 상황.
6. UI 반응/시야/인게임 디자인: 전투 중 짧게 변경 가능한지, 퀵 메뉴에 플레이어가 지은 이름이 잘리더라도 상세 확인할 수 있는지, 화면 어두워지는 검은 판/거대한 HUD를 과하게 추가하지 않는지.
