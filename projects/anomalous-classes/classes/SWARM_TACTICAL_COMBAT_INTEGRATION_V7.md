## 1. 지금까지 확정된 플레이 구조 — 추가 선택을 강요하지 않는다

- 진짜 작은 생명체가 **공격·엄호·플레이어 운반 비행**을 분담한다. 적의 근접/화살/유효 광역에 타격되면 실제 개체 수 감소와 죽는 모션이 존재하고, 유효한 전투·시간으로 **자동 재증식**한다. 버튼 +N 증식 액티브는 현재 추천에서 제외.
- 원격 타깃 지정(추가 소모/쿨 없음)과 **두 액티브 공격 기술(군집 급습/군체 소모)**은 서로 다른 명령이다. **엄호는 스킬이 아니라 사용자 전술 비율로 상시 움직이는 기본 역할**이다. 전술 편집이 공격을 자동으로 대체하거나 비행을 강제로 토글하지 않는다.
- 군체의 공격력/내구/증식은 **군단 전체 공통 성장**. 개별 생물 경험치/장비/모드·성별·음식/수리·수십 개 HUD 바/펫 목록 없음.
- 플레이어가 **전술의 이름과 공격:엄호 비율을 직접 만들고 편집·삭제/저장**해 빠른 전술 휠로 호출한다. **‘자동 / 공격 우선 / 균형 / 엄호 우선’ 4종은 폐기**. 게임에서 해당 4개의 전술을 기본 저장하거나 이름을 강요하지 않는다.
- 저장 전술이 하나도 없을 때는 **기본 군체 기능이 막히지 않는다**. 생존 가능한 기본 공격·방어 등 AI의 필수 기초 동작은 정상 작동하지만 '자동 전술'이라는 선택지나 사전 설정 프리셋은 생성/표시하지 않는다. 사용자가 최초로 이름/비율을 직접 만든 뒤 그 전술이 활성 상태가 된다.
- 플레이어가 명시한 공격 비율 `100%` 또는 `0%`도 유효하다. 공격 100%를 골랐으면 **별도 보이는 엄호대/투사체 방어를 공짜로 만들지 않음**. 엄호 100%를 골랐으면 **일반 적 공격과 공격대 전용 액티브를 공짜로 수행하지 않음**. 단 적이 직접 비행 군체를 쳤을 때 운반군이 피해받는 것과 '엄호대가 막는' 행동은 구분.
- 비행 중에는 **비행 유지의 실제 최소 운반 개체**를 먼저 예약하는 안전 예외만 허용. 그 외 공격:엄호 배분은 **플레이어의 현재 전술 비율 그대로** 적용. 비행 연료/전술 에너지/숨은 무료 군체 없음.

## 2. 한 군체 N과 역할별 실제 인원·상태 규칙

### 2.1 유일한 수량 보존식

`totalAlive = attackN + guardN + liftN + regroupN`, `0 <= totalAlive <= maxN(level)`.

- `attackN`: 목표에게 실제로 이동/타격하는 공격대. 무료 원격 표적 지정이나 급습/군체 소모의 **실제 투입/비용 주체**.
- `guardN`: 플레이어 주위 실제 충돌·엄호 위치에서 적의 근접/투사체를 받을 수 있는 엄호대. 허공 전체를 무조건 보호하는 투명 방패 금지.
- `liftN`: 플레이어 몸을 떠받치는 비행대. 비행 유지에 사용하지만 동시에 공격·엄호 개체로 중복 카운트하지 않는다.
- `regroupN`: 공격대와 엄호대가 목표 진형으로 실제 이동/회수 중인 수량. 순간이동으로 바로 특정 위치의 피해를 가로막지 않는다. `regroupN`도 **죽을 수 있고**, 플레이어 상태와 거리/충돌을 검증한다.
- 손실에 따른 `totalAlive` 감소는 적의 유효 피해/소모기의 실제 비용으로만 정산하고 자연 번식·캐릭터 레벨에 따른 최대치 변화는 별도로 처리. 전술 클릭만으로 현재 군체수 N을 증감시키지 않는다.
- 소유자 상태와 정확한 위치/충돌 데이터는 서버 권위; 화면의 작은 생물 숫자/진형/밀도/모션은 실제 공격·가드·비행의 논리량과 동기화.

### 2.2 플레이어 직접 정의된 비율 적용

- **지상:** `available = totalAlive - regroupN`, 플레이어 저장 전술의 `attackWeight`와 `guardWeight=100-attackWeight`에 배정. 정수 나눔의 소수/반올림은 일관되고 편향 없는 방법을 선정하며, 필요하지 않은 큰 폭 재배치/동일 수량의 빠른 진동을 피한다.
- **비행:** `available = totalAlive - liftReserve - regroupN`; 공격대와 엄호대는 **남는 수량만** 사용자의 같은 공격:엄호 비율에 맞춰 목표 배정. `liftReserve`는 레벨·현재 실체 이동·비행 성능·현재 피해 상태를 기반으로 한 서버 규칙이지 사용자가 설정한 전술을 몰래 바꾸는 또 다른 프리셋이 아니다.
- **시험 사례 A:** N80, 지상, 사용자 이름 '보스전', **공격40%·엄호60%** → 공격32 / 엄호48.
- **시험 사례 B:** N80, 비행 reserve30, 동일 '보스전' → 공격20 / 엄호30 / 비행30. 
- **시험 사례 C:** N80, 비행 reserve30, 사용자 이름 '전력 돌격', **공격100%·엄호0%** → 공격50 / 엄호0 / 비행30; 화살을 자동 가로막는 무료 엄호대 없음, 운반군은 직접 맞으면 손실될 수 있음.
- **시험 사례 D:** N80, 지상, 사용자 이름 '생존', **공격0%·엄호100%** → 공격0 / 엄호80. 원격 표적을 찍어도 공격할 물리 공격대가 없으므로 일반/급습·소모 공격을 자동 수행하지 않는다. 사용자가 자신의 상황에 맞게 명확히 선택한 위험이다.
- 위 이름/비율은 **사용자 임의 설정 예시이지 게임이 제공하는 프리셋이 절대 아님**. 실제 최고 효율 분담·비행 예약 인원·위력 수치도 미승인.

### 2.3 정밀 관리가 '잡일'로 바뀌지 않도록

- 전술 수치 편집의 기본은 **공격% 단 하나**, 엄호%=100−공격%. 비행은 안전 유지에 필요한 수량을 자동 예약. 사용자가 원치 않으면 '공격대 단독 목표 A/엄호대 반경 B/비행대 수동 RPM/개별 개체 제어' 같은 20가지 옵션을 추가하지 않는다.
- 퀵 휠에서 **현재 선택 이름을 바로 바꾸거나 비율을 직접 편집/저장**할 수 있는 간결한 UX를 허용. 실제 전투 중 빠른 비율 편집과 이름 키보드 입력은 목적이 다르므로 **짧은 전투 입력에서는 비율 우선**, 이름 변경은 한 번의 명시적 편집 동작으로도 가능하도록 설계. 전투 중 문자 입력 때문에 조작이 멈추거나 플레이어가 죽는 문제 방지.
- 명령 적용은 **서버 목표 비율을 즉시 바꾸고** 화면에 변경 상태를 알려준다. 공격대가 먼 곳에서 플레이어 옆으로 돌아오는 데는 **실제 이동 시간**이 필요하고, 그동안 `regroupN`과 현재 배분 표시를 제공. 실행중 진형/표적 이동을 다시 클릭해서 무한 스킵하지 않는다.
- 저장 전술은 서버에서 개인 데이터로 관리. 재로그·사망·차원 이동에서도 사용자 이름/퀵 슬롯·비율이 유지되고 타인의 전술·이름을 변경 못 한다. 너무 긴 이름/제어문자만 안전 제한.

## 3. 실제 교전 이벤트와 충돌 해결 순서 (후보)

1. **입력/현재 전술:** 저장된 사용자 비율 및 원격 표적 변경/소모기/급습/비행 토글 요청을 **서버 권한으로 검증**한다.
2. **사망·피격·소모 정산:** 이미 적중한 적 투사체/근접·유효 범위 타격 및 `군체 소모`가 실제 공격대/엄호대/비행대에 가한 군체 손실을 **동일 피해 사건 1회**로 정산한다. `군집 소모`가 공격대 부족 시 다른 역할을 몰래 가져오지 않음.
3. **현재 비행 유지 안전:** 비행 유지 `liftN`이 부족할 때 실제 남은 군체에서 재배치가 가능하면 **유한한 실제 이동 시간/반응**으로 전환. 불가능하면 **통제 하강**. 현신하는 추가 군체를 무료 소환해 무한 비행/무적이 되는 것 금지.
4. **목표 역할 배분 재계산:** 나머지 살아 있는 실제 N에 사용자 공격:엄호 비율 적용. 기존 목표가 삭제/언로드되면 서버가 표적을 해제/복귀 처리; 그 사실로 전술을 자동 바꾸지 않는다.
5. **이동·공격·방어:** 군집은 실제 위치/충돌/시야·거리·팀 관계를 지키며 이동. 공격/급습은 도달한 공격대만, 엄호는 실제 탄도·적 공격이 닿는 엄호대만 수행. 재배치 중 무조건 공격·엄호 모두 성공하는 중복 유닛 금지.
6. **자연 재증식·스탯:** 전투/비전투 유효 사건을 통한 기본 재증식이 `maxN`까지만 반영되고 다음 역할 분배를 조정. 빠른 설정 입력 자체는 수량 보충을 수행하지 않는다.
7. **클라이언트 UI 업데이트:** HUD N/Nmax + 활성 **사용자 전술명** + 필요한 시점에 비행·표적/분배 변경 확인만. 관리 패널이 열렸을 때 목표 분할/현재 실제 마릿수, 변경 대기·손실 상태를 보여준다.

이 절차는 **기획상 순서 후보**다. Minecraft 이벤트 콜백/탄체 이동/같은 tick 서버 구현에서 이 순서를 고정할 수 있는지 검증하기 전까지 원자성·멀티 경계/동일 엔티티 이동 주기를 확정하지 않는다. 특히 **맞은 공격의 결과를 전술 변경 요청으로 뒤늦게 무효화**하거나 화살을 이미 맞았는데 이전 프레임으로 회피하는 일을 금지한다.

## 4. 능력별 역할·0% 상태·조작 상호작용

| 플레이 행동 | 플레이어 직접 전술에 따른 결과 | 피해야 할 잘못된 동작 |
|---|---|---|
| **원격 표적 지정** | 원격 대상 UUID만 검증/변경. 공격대가 있으면 실제 이동 후 우선 공격 | 공격 0%일 때 공격대 무단 생성, 사거리 밖 즉시 대미지 |
| **군집 급습** | 실제 위치에서 가용 공격대가 목표/영역을 휩쓸어 주력 피해 | 엄호대·비행대 전원 동원, 벽/경로 무시, 클라 표시와 실판정 불일치 |
| **군체 소모** | **가용 공격대의 일부만** 실제 개체 소모로 비용 지불. 부족하면 명료한 실패/약화 정책 | 공격대 0인데 수량을 엄호/비행에서 자동 차감해 추락 |
| **엄호 전술(상시 기본 행동)** | **플레이어 직접 저장/빠른 설정한 엄호 비율의 실제 군체**가 계속 근접·원거리 공격을 가로막고 희생됨. 별도 발동 버튼·쿨타임·일시 버프 없음 | 공격100%·엄호0%에서 무료 엄호 발생, 목표 비율을 몰래 바꾸기, 비행대 탈취 |
| **화살/삼지창 피격** | 엄호 충돌 체적에 맞으면 해당 엄호 개체의 누적 내구를 깎고 실제 수량 손실. 동료 화살은 관계/발사자 필터에 따라 제외 | 플레이어 항상 무적, 한 발 이중 피격, 화면 밖 초장거리 가짜 엄호 |
| **비행 전환** | 충분한 군체가 있으면 운반군 일부 예약 후 호버링/상승·하강. 남은 N에 저장 비율 적용 | 별도 비행 마나 추가, 기존 전술 이름 교체, 순간 추락·무한 무적 |
| **군체 부족/전멸** | 모든 역할 성능 감소·0이면 다시 서서히 자연 증식. 저수량 상태에서 가능한 기능만 사용 | 자동 버튼 회복, 하위 군체 영구 무력, 메뉴로 빠져나와야만 회복 |
| **비행 중 저장 전술 변경** | 비행 reserve 우선, 나머지에 전술 비율 즉시 목표 반영. 실제 전환은 이동 후 | 저장 전술을 바꿨다고 공중에서 갑자기 새로운 군단 생성/피해 취소 |
| **중립 생물/아군 조준** | 오폭 방지 정책. 서버 소유자·팀·PvP 관계 검사 | 수량 많아졌다고 자연 동물·주민·팀원 자동 공격 |

### 최신 8차 확정과 남은 실제 구현 질문

- **8차 사용자 확정:** `군집 엄호`는 **상시 전략 역할**이며 **액티브 스킬·별도 버튼·지속시간·재사용 대기시간 자체가 없다**. 사용자가 빠른 메뉴에서 엄호 비율을 변경하면 서버의 목표 엄호 인원이 바뀌고, 실제 군체가 이동/배치되어 엄호 효과가 나타난다. 공격100:엄호0에서 숨겨진 방어·한시 전술 오버라이드는 발생하지 않는다.
- **군체 소모의 희생 비율**: 공격대의 일부(예: 25% 초안)는 **현재 총 N의 일부**가 아니라 **현재 공격 가능한 N의 일부**인지 명확히 통일. 추천은 공격대 기준 비용, 생존/비행 예약 침범하지 않음.
- **공격 0:엄호 100에서 원격 표적**: 표적 저장 자체는 허용하되 공격/급습을 실행하지 않는 게 가장 예측 가능. 공격 비중을 올리면 이전 표적에 실제 이동해 공격 가능.
- **자유전술 0개 상태의 AI**: 플레이를 못하게 하거나 ‘자동’이라는 이름의 비공개 전술을 캐릭터 데이터에 생성하지 않음. 기본 동행/생존 군체 동작만 제공하고 첫 직접 전술 생성은 관리/퀵 메뉴 어디서나 가능하도록 한다.

## 5. 실제 재현 가능한 전투 시나리오

### A. 지상 단일 보스와 원격 목표

- N80, 사용자 설정 전술 공격70%·엄호30% → 목표 공격56 / 엄호24.
- 공격대가 보스에게 이동 중 퀵 메뉴로 **공격40%·엄호60%** 전술 변경 → 목표 공격32 / 엄호48. 하지만 실제 인원은 거리에 따라 56/24 → **재결집 과도기** → 32/48로 이동; 플레이어는 일시적 부족분 때문에 보스 화살을 모두 완벽히 막을 수 없음.
- 명령 자체는 무료·빠르고, 주력 공격/엄호의 전술은 플레이어가 직접 변경. UI는 목표 vs 실제 역할을 혼동하지 않는다.

### B. 스켈레톤의 화살과 군체 희생

- 사용자 설정 엄호20명이라도 스켈레톤 화살이 실제 엄호 위치를 지나지 않으면 방어 실패. 화살이 엄호 개체를 실제 때리면 내부 누적 유효 피해로 실제 N 손실, 보이는 작은 생물 사망/반격 타이밍 동기화.
- **공격100%·엄호0%**면 일반 엄호 충돌체가 없으므로 아군 화살·적 화살 모두 그 엄호대로 무조건 막히지 않는다. 자기 피격·방패 사용·바닐라 피해 처리와 명확히 공존.

### C. 비행 중 보스 전투와 재배치

- N80, 비행 reserve30, 사용자 직접 만든 공격80%·엄호20% → 공격40 / 엄호10 / 운반30.
- 전투 중 공격대 10개체를 희생하면 N70이고 역할은 실제 공격30/엄호10/운반30 (이동/피해 중개 N은 별도). 이때 공격대가 적에게 계속 압박하고 비행은 유지.
- 다시 엄호 개체 4가 투사체/광역으로 죽으면 N66, 공격30/엄호6/운반30. 사용자가 비율을 새로 편집하면 부족한 엄호 인원은 **실제로 공격대에서 이동해야만** 새 탄체를 막는다.
- 비행군을 직접 때려 N이 너무 부족해지면 다른 군집의 **실제 이동·양도 가능성**을 검증하고, 실패하면 **안전 감속 하강**. 플레이어가 투사체를 맞았는데 전술 스위치로 과거 피해를 되돌릴 수 없음.

### D. 저레벨·전술 설정 0개·재접속

- 첫 플레이 시작: 별도 관리창을 열지 않아도 작은 생물이 기본 동행하며 약한 적과의 생존 전투가 가능. 관리키로 창/퀵휠을 열면 전술 이름/비율을 **직접 처음 생성**할 수 있음. 개발자 '자동/공격 우선/균형/엄호 우선' 목록 없음.
- 군체 수량이 낮아 분담이 어려울 때는 사용자 목표 비율을 **그대로 기억**, 현재 가능한 마릿수로 근사 배치. 최대 수량이 올라가면 전술을 다시 작성하게 만들지 않음.
- 사용자가 만든 전술 목록·한국어 이름/퀵 슬롯을 재접속/사망/차원 이동 뒤에도 복원하지만, 전투 중 현재 피격/군체 N을 재접속으로 무료 회복시키지 않는다.

## 6. 구현 난도·품질 리스크의 우선순위

| 우선순위 | 실제 어려운 지점 | 추천 대처 |
|---|---|---|
| **최우선** | 바닐라 적 AI가 군집 실체/대체 hitbox를 적으로 인지하고 공격, 화살·투사체의 실제 타격 | 목표 버전/로더 선정 후 **서버 군집 proxy 1~소수**와 실제 충돌·피해 사건을 수직 슬라이스로 시험. 외부 몹 전체 지원 가정 X |

| **중요** | 상시 1인칭 시야 방해, 자신의 화살을 가로막고 팀원 피해 오폭 | 카메라 중심을 비우고 엄호군 시각/실체 위치 일치, 소유자·파티 관계/투사체 발사자 판정 |
| **중요** | 스킬 포인트/장비 등 다른 계수와 동시 곱으로 공격·내구 무한 폭주 | 일관된 계산 순서, 레벨1/25/100/500·군체0/절반/최대·5등급 장비 유무 기준 비교 |

**검증 단계 구분:** 현재는 코딩/로더 선정/구조·모델 작업/플레이테스트를 수행하지 않았다. 따라서 본 문서의 '한 마리씩 맞아 죽는 군체', '빠른 전술 설정', '완전한 비행', '멀티 안전'은 **구현 방향이지 검증 결과가 아님**.
