# GAME DESIGN — 이능 직업 서바이벌

Status: 논의 내용 정리 및 미확정 후보 기록. **여기에 없는 숫자와 기술 선택은 확정된 것이 아님.**

> **2026-11-05 진행 상태 최신 정리:** [**6직업 기획·미결정과 정본 통합 우선순위**](./DESIGN_CONSOLIDATION_AUDIT_2026-11-05.md)를 참조. **현재 상세 설계 대상은 정신 지배자·인형술사·기생술사·결계술사·계약술사·군체술사 여섯 직업**, 중력술사·공명술사 상세 기획은 보류이다. 많은 기존 수치/제작식·스킬/시각 가이드가 **미검증 초안**이므로 **게임 전체 기획이 끝났다고 판단하지 않는다**. 본 문서 일부 옛 '8직업 기획 후 UI 구현'·'다음 채팅에서 상세' 언급은 당시 기록이며 현재 구현 착수 순서를 지시하지 않는다. 현재는 기획 통합/공통 레벨·서바이벌 경제/여섯 직업의 같은 조건 플레이 동선 검토가 우선이고 코드/모델·빌드/JAR/게임플레이 테스트는 수행하지 않았다.

> **2026-11-05 외부 모드 1차 조사:** [외부 몬스터·보스·던전·난도 제어 및 1.21.1 NeoForge/Fabric·1.20.1 Forge·26.2 비교](./EXTERNAL_MOD_ECOSYSTEM_RESEARCH_2026-11-05.md) 참고. **1.21.1 NeoForge는 현재 확인된 보스 콘텐츠를 중심으로 유력한 후보일 뿐, 기술 스택/의존성은 아직 미확정**. Cataclysm·Mowzie's·Born in Chaos·Mutant Monsters·YUNG's·In Control! 등은 **실제 jar 테스트·모드 상호호환, 지배/기생/군체/결계·전투 피해 어댑터 테스트 전 후보**. 초반 생존과 중후반 강적의 보상·XP·제물/장비 연결을 기획하고 무차별 스폰/체력 증가를 피한다. 외부 원본 저작권/모델 직접 재사용과 일반 의존성은 별개.

> **2026-11-05 편의성/외부모드 범위 결정:** [멀티 플레이어 위치 바·동적 횃불 조명·JEI/바닐라 레시피북·외부 성장 시스템 제한](./QOL_MODS_AND_EXTERNAL_SCOPE_POLICY_2026-11-05.md) 참고. **인게임 경험치 바/상단에 멀티 플레이어 방향 표시, 손의 횃불 동적 조명, 모드 포함 조합법·사용처 검색**을 제공하는 모드를 후보로 둔다. **추가 RPG 레벨·직업·스킬트리·별도 성장 재화/새 게임 시스템은 기본 제외**, 사소한 장비·갑옷/인챈트 개선은 기존 진행과 충돌하지 않는 범위에서 허용. 1.21.1 NeoForge의 Locator Bar/PlayerLocatorPlus NeoForged(둘 중 하나), LambDynamicLights, JEI, 선택형 Crafting Tweaks+Balm 후보. 바닐라 책은 기본 닫기/버튼 숨김 선택을 제공하며 자체 모드 제작법은 JEI 호환 표시가 필요할 수 있다. 서버/클라 테스트 전 설치 확정 X.

> **2026-11-05 공통 진행 설계 v1:** [**생존·전투·성장·제작/보상·외부 모드 강적을 연결한 6직업 공통 플레이 루프**](./CORE_GAMEPLAY_GROWTH_REWARDS_DIFFICULTY_V1.md). 바닐라 채굴·건축/탐험과 이능을 함께 이용해 적·던전→기존 재료/XP·직업 고유 성장→레벨/패시브/매개체→다양한 강적/보스로 순환한다. **외부 모드가 별도의 RPG 성장축을 추가하는 것은 제외**하고, 계약술사 제물·기생술사 BD 같은 이 게임 직업 고유 자원은 유지. 공통 RPG XP와 바닐라 경험치/인챈트는 충돌하지 않도록 구분하되 구체 공식/보상량·레벨 곡선·분리 방식은 **미확정 제안**. 사용자 선택으로 JEI `Ctrl+O` UI 표시/숨김. **문서 검토만 완료, 실제 Minecraft 개발/테스트 수행하지 않음**.

> **2026-11-05 사용자 경험치 분리 확정:** 바닐라 경험치는 **인챈트·수선 및 원래 Minecraft 용도**, 게임 RPG 경험치는 **별도 직업 레벨·능력치·스킬 포인트 용도**로 **서로 환전·소비하지 않는다**. 직업 고유 성장(기생 BD/계약 제물/관계 등)도 기존 목적을 유지. [무제한 레벨·스킬 포인트 지급·경험치 곡선 3안·6직업 HP 초안 비교](./RPG_XP_LEVEL_SKILLPOINTS_BALANCE_V1.md) 기록. **레벨 공식/획득량/포인트 수/완료 뒤 반복 숙련 등은 미승인 비교안**이며 현재 수치가 출시 확정은 아님. 기존 RPG/바닐라 XP 분리 '제안·미정' 표기는 최신 이 확정 지시를 우선. 인챈트는 RPG 레벨을 줄이지 않으며, 같은 모드팩에서 JEI 아이템 창은 개인별 `Ctrl+O` 숨김을 허용.

> **2026-11-05 최신 1P/3P 비교:** 3P/레벨의 현재 프로젝트 사용자 확정 기록은 확인되지 않았고, 지난 1P 추천도 확정 아님. **유저는 1P/레벨을 허용하되 레벨업이 충분히 빨라야 한다는 조건**을 덧붙였다. [수치 비교 v1](./RPG_XP_LEVEL_SKILLPOINTS_BALANCE_V1.md)에서 1P면 패시브 270~300랭크 완성에 Lv271~301(기타 비용 제외), 3P면 Lv91~101임을 비교. 빠른 레벨링은 공통 자동 능력치도 빠르게 상승시키므로 공격·생존/외부 몬스터 난도와 함께 검토. **숫자와 시간 목표는 사용자 확정·플레이테스트 전**.

## 핵심 플레이

마인크래프트 생존 행동과 일반 RPG의 경험치·레벨·스킬 포인트·장비 성장 루프를 결합한다. **캐릭터 레벨 상한은 두지 않는다.** 레벨이 올라갈수록 필요한 경험치가 증가하더라도 성장 자체는 끝나지 않는다. 8개 직업은 동일한 일반 성장 UI 흐름을 공유하되, 레벨업으로 증가하는 능력치는 직업에 따라 다르고 스킬 활용 방식이 실질적으로 달라야 한다. 스킬 트리가 전부 해금되더라도 레벨업으로 능력치 성장이 계속되어야 한다.

## 공용 UI 구조 시안 (2026-11-04)

- [4화면 정적 구조 시안 HTML](./ui/concepts/STRUCTURAL_UI_V1.html): 직업 선택 / 스킬 트리 / 지배체 관리 / 전투 HUD를 전환해 보는 원본. **최종 UI 디자인 또는 Minecraft 구현이 아님**.
- [화면별 의도·검수 기준 및 Codex 인계 메모](./ui/concepts/README.md): 8직업 데이터 바인딩, 장악·결속·간섭 3계열(270랭크 후보), 단일 개체 관리, 바닐라 HUD 공존, 네트워크/서버 권한 경계 등을 정리.
- 핵심 게임/저장·AI 로직은 이 프로젝트에서 설계·개발하고, **최종 시각 UI/인터랙션 구현은 Codex에 위임**하는 역할 분리 방향. Codex가 핵심 게임 수치를 자체 계산하거나 기획에 없는 직업 능력을 추가하지 않도록 API 계약을 먼저 정한다.
- 이 시안은 다른 7직업의 상세 데이터·아이콘·스킬이 기획되기 전의 **정신 지배자 샘플**이므로, 나중에 전체 기획이 확정될 때 구조 변경 가능성을 열어둔다.

> **군체술사 3차 현재 방향:** [적에게 실제로 맞아 수량이 줄어드는 군체·자연 재증식·개체 질적 강화](./classes/SWARM_COMBAT_GROWTH_V3.md). 사용자가 수량을 스킬로 늘리는 것에 부정적이므로 `급속 증식` 액티브를 현재 추천에서 제외. **레벨로 최대 군체수 자동 증가**하고 **군단 전체 개체 공격/생존력**을 강화. 구체 스킬/계수는 미확정. 중력술사·공명술사 보류 계속.

> **4차 군체술사 방향:** 충분히 성장한 군체는 [공격대·엄호대 동시 분리](./classes/SWARM_SPLIT_FRONTLINE_V4.md)가 가능하며 엄호대가 적 화살·원거리 공격을 실제 가로막고 개체가 사망한다. 1인칭/3인칭 카메라·조준점 가림은 최소화. [공격·엄호·번식 270랭크 스킬 트리](./classes/SWARM_SKILL_TREE.md) 및 [군체 핵 5등급](./classes/SWARM_FOCUS.md)은 신규 미승인 수치·레시피 시안이다. 원격 표적/자연 증식/공통 슬롯 기능은 그대로. 중력술사·공명술사 상세 기획 보류 지속.

> **5차 군체술사 기획(2026-11-05):** [군체 탑승 비행·공격/엄호/비행 분담 및 레벨별 밸런스](./classes/SWARM_FLIGHT_AND_COMBAT_BALANCE_V5.md) 신규 상세안. 기존 실체 생물 군단이 플레이어를 떠받쳐 **정지 비행·상승·하강**, 비행 중에도 원격 공격·엄호 가능하지만 실제 N이 역할별로 나뉨. 적 화살/광역 피격으로 비행대가 죽으면 안전한 감속 하강 후보, 정면 시야 가림 금지. 마나·연료·별도 비행 게이지/개체수 즉시 증가 스킬을 요구하지 않는 방향. **비행 해금 Lv25, 속도, 16/48/80/128 수량 및 DPS/내구 수치는 미확정 시험안**. 다른 두 직업 상세 기획은 여전히 보류.

> **군체술사 6차 사용자 조작 요청:** [군체 관리 패널 단축키 + 전투 중 빠른 전술 설정](./classes/SWARM_COMMAND_PANEL_AND_QUICK_SETTINGS_V6.md). 패널에서 수량/분담/표적·성장 정보와 **직접 설정·이름 지정한 전술 목록**을 보고, 퀵 전술 휠에서도 **자신이 만든 전술로 즉시 변경하거나 비율을 직접 수정·저장**한다. **고정 '자동/공격 우선/균형/엄호 우선' 전술은 사용자 최신 지시로 폐기.** **현재 행동은 멈추지 않고**, 명령 서버 승인 후 적법한 실제 이동·피격 판정을 유지. G 키·탭/홀드 임계·정확한 비율·패널 그래픽은 시안. 비행 운반 군체 우선 확보, 한 개의 군체 총수 자원, 시야 보호·원격 표적/자연 증식 유지. 중력/공명 기획 보류.

> **군체술사 7차 통합 정본:** [플레이어 직접 만든 전술·실제 군체 분배·급습/소모·화살 엄호·비행·자연 증식의 사건 순서](./classes/SWARM_TACTICAL_COMBAT_INTEGRATION_V7.md). **고정 '자동/공격 우선/균형/엄호 우선' 전술은 폐기**. 플레이어가 공격:엄호를 0:100/100:0으로 자유 설정해도 **서버가 숨은 역할을 창설하지 않는다**. 비행에는 실제 최소 운반군을 예약하고 남은 수를 직접 설정 비율로 분담. 실제 이동·화살 피격과 HUD가 일치해야 하며, 기술 실현성/전투 수치는 미검증이며 **엄호 액티브 예외는 최신 8차에서 폐기**, 엄호는 플레이어 지정 비율에 따른 상시 전술이다. 중력·공명 기획 보류.

> **8차 최종 사용자 결정:** 군체술사의 **엄호는 스킬이 아니라 사용자 직접 이름·공격:엄호 비율을 설정하는 지속 전술**이다. `군집 엄호` 액티브·쿨타임·버프/지속시간 폐기. 액티브 공격은 **`군집 급습`과 `군체 소모`** 2종, 원격 지정/비행/자연 증식은 별도 기본 기능. [군체 정본](./classes/SWARM_CASTER.md)과 [전술 통합](./classes/SWARM_TACTICAL_COMBAT_INTEGRATION_V7.md). 사용자 전술 0% 방어는 숨은 엄호를 생성하지 않는다. 두 남은 직업 상세 보류 계속.

- [결계술사 형성·압축·경계 300랭크 패시브](./classes/BARRIER_SKILL_TREE.md): 각 계열 100랭크·3노드, 총 9노드·300랭크. **다중 전개 15/35랭크에서 동시 결계 +1/+1**(기본3→4→5) 후보. 압축·방어/격리·반경/유지 등 강화안은 미검증.

- 나머지 다섯 직업도 차례로 기획한 뒤 공용 UI·API 계약에 연결한다.

## 공용 소환·지배 아군 판정

- [서버 권위 아군 식별 및 인형 피아식별 계약](./ALLY_RELATIONS.md): 일반 엔티티 태그만으로는 소유자/팀을 판별하지 않는다. 소유자 UUID와 서버 팀/파티 관계를 비교하고, 인형은 같은 팀 플레이어/같은 팀 소환물과 **피해를 주고받지 않는다**. 바닐라 scoreboard 팀은 선택 가능한 관계 입력이며 그 자체만으로 모드 공격 전체가 차단되는 것은 아니다.
- 정신 지배체의 플레이어 공격 허용 ON/OFF는 기존 계약을 보존한다. **인형이 행위자 또는 피격 대상인 팀 관계**에 대해서만 인형의 아군 피해 방지가 우선한다. 구현은 서버에서 단일 판정 함수를 공유한다.

## 정신 지배 및 PvE/PvP 안전 계약

### 지배 가능성 / 난도

- 적대 몬스터와 보스뿐 아니라 **주민·철 골렘·가축/동물 등 비적대적 생명체**도 지배 가능성에 포함한다. 대상 유형 또는 보스 등급만으로 면역을 부여하지 않는다. 플레이어 직접 지배는 사용자 미결정이므로 확정하지 않는다.
- 난도는 적의 실제 능력과 저항, 현재 상태, 시전자의 성장도를 반영한다. 보스 성공은 매우 어렵지만 불가능으로 고정하지 않는다.
- 지배 시도에 정신력 비용이 있고 지배 상태를 유지하는 중에도 정신력이 소모된다.
- 고레벨에서는 약한 개체 유지 소모 0 또는 거의 0이 가능하다. 보스는 성장 후에도 의미 있는 부담을 줄 수 있다.
- 지배 실패, 지배 해제, 소유자 사망/로그아웃, 대상 소멸 및 외부 보스 스크립트와의 상호작용을 후속 설계한다.
- 특정 기간마다 자동 해제되는 보스 전용 절대 시간 제한은 사용자가 요구한 내용이 아니다. 강력함은 비용과 난도에서 표현한다.

### 지배 대상 공격 토글

- 각 지배 몬스터는 소유자 설정에 따른 별도의 `player_damage_allowed` 상태를 보유한다.
- 바라보고 개체별 토글. 소유자가 설정을 변경한다. 기본 ON/OFF 값은 플레이어별로 선택한다.
- ON: 자신과 타 플레이어가 지배한 대상을 직접 공격하거나 스킬로 공격할 수 있어 CC 이용 가능.
- OFF: 자신과 타 플레이어의 피해를 방지. 다른 적 몬스터와 환경 피해는 정상적이다.
- 투사체/광역/간접 피해, 지배 해제 직후 상태 복원, 대상 중복 등록, 멀티플레이 클라이언트 표시 및 서버 권위 판정은 구현 전 계약이 필요하다.

### 편의성

기본적으로 지배된 대상은 자동으로 따라오고 전투한다(주민 등 비전투형 대상은 역할에 맞는 행동이 필요하며 전투 능력을 억지로 부여하지 않는다). 일일이 유닛 편성, 명령 큐, 군단 관리 창을 조작하게 하지 않는다. 공격 허용 토글은 예외적으로 직접 조작 가능한 단순 기능이다.

### 스킬 방향 정정

- **정신 과부하:** 지배된 대상의 정신을 과부하시켜 일시적으로 강화한다. 적에게 피해를 주는 기술로 바꾸는 안은 **폐기**.
- **강제 장악:** 액티브 스킬 목록에서 제외한다. 정신 침투와 기능 중복을 만들지 않는다.
- **광역 정신 정지 CC:** 주변 일정 범위의 생명체를 잠시 멈추는 액티브를 추가한다. 적대·중립·우호 대상이 모두 포함되며 보스도 등급만으로 면역화하지 않는다. 지속시간과 저항/시전자 영향/다른 플레이어 포함 및 PvP 설정/외부 AI 상태 정합성은 아직 상세 검토가 필요하다.
- 주민·철 골렘 지배 시 거래, 직업, 마을 방어, 소환/기존 AI, 원래 상태 복원이 훼손되지 않도록 별도 검증해야 한다.
- **지배된 말**은 정신 장악에 성공한 뒤 버킹/길들이기 거부가 없고 안장 없이 탑승·조종 가능하도록 한다. 해제 후 원래 길들이기 상태를 복구한다. 이 규칙이 지배 시도 자체의 성공률 100%를 의미하지는 않는다.
- 개체 조작은 **동행/대기/해제** 같은 최소 명령을 제안한다. 한 번 지배한 종과 특별 개체의 달성 기록을 남기는 **지배 도감**은 관리 UI를 무겁게 만들지 않는 선택적 수집 요소이며 아직 확정되지 않았다.

## 군체술사

작은 개체의 빠른 증식과 비교적 빠른 소모가 특징이다. 초반 군단이 순식간에 무한 확대되어서도 안 되고, 개체 소모가 너무 빨라 집결 자체가 불가능해서도 안 된다. 후반에는 육성에 따라 군단 유지 능력을 체감해야 한다. 개체별 지휘는 넣지 않는다. 큰 군집의 실제 엔티티 수와 표현 방식은 성능 테스트 후 결정한다.

## 직업 장비 — 결정과 제안의 구분

**확정 방향**: 직업 장비는 직업 자체의 전투·생존 효율을 **체감 가능할 정도로 높이는 강화 장비**이다. 장착이 직업 능력 사용의 필수 자격 조건이 되어서는 안 된다. 바닐라 장비 사용을 막지 않는다.

**사용자 확정 방향**: [8직업 공통 매개체 장착 슬롯 1개](./CLASS_FOCUS_SLOT.md)를 주손/왼손과 분리하여 사용한다. 왼손은 방패·토템·횃불 용도로 유지하고 스킬 시전 시 장비를 손에 잠시 보여주는 연출 가능. **구체 GUI·슬롯 API 구현은 버전/로더 결정 이후**. 각 직업의 기존 등급·효과 변경 없음.

직업별 장비 콘셉트(명칭 임시):
- 정신 지배자: 정신 증폭 매개체
- 인형술사: 인형 제어 장치
- 기생술사: 공생 핵
- 결계술사: 결계 매개체
- 계약술사: 계약 증표
- 군체술사: 군체 핵
- 중력술사: 중력석
- 공명술사: 공명 결정

수치는 추후 스킬 트리와 함께 조정한다. 등급 이름이 좋아 보여도 등급 수와 장비 수를 억지로 늘리지 않는다.

## 장비 등급명 (확정)

일반·희귀·영웅·전설·신화 같은 범용 희귀도 명칭 대신 **A안 / 변칙형**을 정식 단계명으로 사용한다.

| 등급 단계 | 확정 명칭 |
|---|---|
| 1 | 규격 |
| 2 | 변조 |
| 3 | 변칙 |
| 4 | 이형 |
| 5 | 불가해 |

- 위 순서와 이름은 사용자 확정 사항이다. 과거 후보 B/C안은 채택하지 않는다.
- 각 단계의 정확한 아이템 옵션 폭, 희귀도, 획득 확률, 외형 색상/연출은 아직 설계 전이다.
- 등급명이 특이하더라도 직업 장비는 핵심 직업 능력의 효율을 명확히 높이는 강화 장비이며, 직업 사용을 위한 필수 키가 되어서는 안 된다.

## 직업 상세 설계 진행 방식

8개 직업을 한 번에 확정하지 않는다. **정신 지배자부터 하나씩** 스킬, 능력치 성장, 전투 흐름, 장비 효과를 설계·검토한 뒤 다음 직업으로 넘어간다. 대화에서 검토 중인 수치와 스킬은 사용자 확정 전까지 기획 후보로 취급한다.

다른 Minecraft 프로젝트의 설정/코드/보스 면역 정책을 이 게임의 확정 설정으로 옮기지 않는다.
