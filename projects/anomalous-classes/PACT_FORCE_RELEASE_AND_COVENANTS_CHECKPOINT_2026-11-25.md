## 이번 구현에서 변경한 실제 동작

1. **정식 해약 보존**: 기존 `/pact release <patron>` → 해약 비용 미리보기 → `/pact confirm` → 서버 원자 재료 확인/소비 → 해당 계약 종료 및 가호 재계산 유지. 하스텔 기존 전투채무가 남으면 정식 해약이 먼저 차단되는 규칙 유지.
2. **강행 파기 신규 동작**: `/pact force <patron>` → 원래 계약의 해약 비용·위험 고지 → `/pact confirm`. 안전한 서버 검증 후 **현재 재료 소비 없이 해당 계약을 실제 종료**하고, 이미 정본 카탈로그에 존재하는 `release_offering`을 같은 양·종류 그대로 미납으로 기록. 기존 계약의 권능/버프·종속 전투 상태는 즉시 해제. 임의 추가 수수료·시간제 이자·정기 유지비 없음.
3. **하스텔 미상환 채무**: 강행 파기 시 현재 `Bond.debt`를 금괴 1당 기존 전투 채무 1 단위로 환산하여, 해당 계약 해약 위약금에 합산·저장. 원래 `release_offering`의 금괴와 중복 항목 없이 합산; 금괴 수량 이외 기존 원료는 변경하지 않음.
4. **미납 비용 정산**: `/pact redeem <patron>` → 당시 기록된 미납 재료 재조회·확인 → `/pact confirm` → 원자 지급·해당 ID 미납 1회 해제. 자동 계약 재체결/기존 입문 제물 환급 없음. 미납 중에는 같은 존재에 대한 신규 체결·제단 체결이 서버에서 거절됨; **다른 존재와의 기존 계약·성장·동시 계약 허용 수는 그대로**.
5. **세이브 및 멀티 소유 분리**: `PactSavedData.Player.outstandingReleases`는 patronId별 정확한 고정 재료 목록이며 기존 데이터와 같은 세계 SavedData에 `unpaidReleaseBills`로 별도 저장. 세계 재시작·사망·직업 변경 후에도 미납 유지. 구세이브에 이 필드가 없으면 추가 부채를 만들지 않음. 서버 소유자 UUID별 분리.
6. **기획상 확인 가능한 금기**: 기존 이사엘–벨칸 1회 갈등·서약 회복, 네르아 실제 제단 핵 훼손·수중 연계 회복을 삭제/재설계하지 않음. `PactCombatService.onDeath`의 원래 이사엘 민간인/비적대 골렘 직접 살해 −6 관계 판정을 **칠익의 재판관(Sevenwing)에게도 적용**하며, 해당 동일 실사망 UUID를 최대 64개 서버 NBT로 기록해 같은 사건 이중 감점 방지. 적대 몬스터나 플레이어끼리의 전투에는 적용하지 않음. 둘 모두 서약 시 각 관계에 개별 적용. 칠익의 적법한 전투 권능을 통한 기존 `PactDeepeningService.record` 관계 회복 루프는 유지.
7. **기본 계약 엔진 유지**: 16계약·4위계·각자 2회 심화·3계약 이상 허용·추가 계약 신규 서명 제물 1/2/4/8배·중복 스탯 가호 최대100%+나머지50%·정기 유지비 없음·16제단·시련·원래 계약서·상태 알림을 변경하지 않음.

## 서버 명령

- `/pact`: 전체 계약 현황과 종료 뒤 미납 위약금 안내
- `/pact terms <patron>`: 기존 계약 조항·해약 제물과 미납 내역 열람
- `/pact release <patron>` + `/pact confirm`: 원래 정식 해약
- `/pact force <patron>` + `/pact confirm`: 즉시 강행 파기 후 위약금 미납 보존
- `/pact redeem <patron>` + `/pact confirm`: 미납 위약금 납부 및 재체결 허용
- `/pact settle` + `/pact confirm`: 현재 계약 중 하스텔 전투 채무 정산(기존)
- `/pact deepen <patron>`: 기존 단계별 심화(유지)

종료/납부/계약 서명은 전투 잠금·직업·서버 요청 만료·플레이어 UUID·현재 계약 수 및 세이브 revision 검증을 보존한다. `/pact confirm`은 미리보기와 별개의 명시적 최종 승인이며, 요청을 1번만 소비한다.
