# Frontier Settlement — canonical direction

The player should keep playing Minecraft, not a spreadsheet.

- One shared village per multiplayer world.
- Internal simulation may be deep; player micromanagement stays shallow.
- Resources remain physical items in settlement storage, with a cached HUD ledger.
- Building flow: choose building -> choose position/direction -> workers prepare and build.
- Roads/outposts become the spatial expansion layer instead of endlessly enlarging one flat town.
- Vanilla villager jobs/trading are not the settlement progression system; custom worker roles replace them.
- No player-authored functional-building registration in the planned scope.
- No early teleport network that invalidates roads/logistics.
- UI information architecture is based on proven references (Against the Storm, Manor Lords, MineColonies); do not invent arbitrary generic panels.
- World/combat/dungeon/item depth should remain compatible with selected external mods rather than being reimplemented here.

First vertical-slice order: shared state -> physical stockpile/HUD -> builder -> house/lumber construction -> short road -> first outpost.
