# 개척마을 프로젝트 정본 기획서 v0.2 — 저장소 복원본

> 구현 시작 전 재검수 반영본. 이 문서는 2026-08-22에 작성된 `개척마을_정본기획서_v0.2.docx`의 저장소용 복원본이다.
> `CANONICAL_PLAN.md`는 이 문서를 구현 단계에 맞게 구체화할 수 있지만, 이 문서의 범위를 현재 구현에 맞춰 축소하거나 누락해서는 안 된다.

## 0. 재검수 결론

결론: 이 문서를 정본으로 고정하면 바로 1차 구현을 시작해도 된다.

다만 이전 v0.1은 방향은 좋았지만, 기능이 계속 늘어나면 다시 복잡해질 위험이 있었다. 이번 v0.2에서는 아래 항목을 구현 규칙으로 추가 고정했다.

- 플레이어가 직접 관리하는 핵심 조작을 5종 이내로 제한한다.
- 첫 구현은 전체 시스템이 아니라 `공동 마을 + 건설 주민 1명 + 창고 + 주택 + 벌목소 + 도로 1개`의 수직 슬라이스로 시작한다.
- 자원은 실제 아이템을 유지하되 HUD에서는 소수의 범주형 숫자로만 보인다.
- 멀티에서는 서버가 마을 상태의 유일한 정본이며, 모든 플레이어가 같은 마을을 공유한다.
- 건설과 평탄화는 자동화하되 월드를 과도하게 파괴하지 않도록 허용 범위를 엄격히 둔다.
- 외부 모드와 UI/리소스는 `호환·참고·공개 라이선스 자산`으로 분리하여 우리 핵심 시스템과 느슨하게 연결한다.

## 1. 한 줄 정의와 핵심 재미

Minecraft 서바이벌을 하며 자원을 공동 마을에 모으고, 주민에게 건설·생산을 맡기고, 도로와 전초기지를 실제 월드 위에 확장하면서 생존자의 역할이 개척자와 영지 운영자로 바뀌는 협동 성장 모드.

## 2. 절대 원칙: 기능은 많아도 플레이는 단순하게

| 플레이어가 한다 | 게임이 알아서 한다 |
| --- | --- |
| 자원을 공동 창고에 넣는다 | 자원 분류·장부 갱신·필요 건설로 전달 |
| 건물 종류와 위치·방향을 정한다 | 부지 검사·평탄화·자재 운반·단계별 건설 |
| 전초기지 위치를 정한다 | 필요 직업 배치·생산·물류 |
| 도로 시작/끝과 필요 시 중간점만 찍는다 | 경로 계산·나무 제거·계단/소교량·시공 |
| 탐험·전투·희귀 자원 확보 | 기본 채집과 반복 생산 |

금지:

- 주민별 시간표
- 생산 비율
- 세금률
- 행복도 수십 종
- 직업별 세부 우선순위
- 수동 물류 경로
- 주민 한 명씩 찾아다니며 장비/직업을 관리하는 시스템

## 3. 멀티플레이 정본

- 한 월드의 기본 마을은 하나이며 모든 플레이어가 공동 소유한다.
- 마을 자원, 인구, 건설 대기열, 전초기지, 도로망, 발전 단계는 전부 공유한다.
- 서버가 상태를 authoritative하게 보관한다. 클라이언트는 표시와 요청만 담당한다.
- 동시에 같은 건물을 주문하거나 자원을 꺼내는 상황은 서버가 원자적으로 처리한다.
- 권한·길드·개인 마을·세금 분배 같은 시스템은 초기 범위에서 제외한다.

## 4. 시작 구조와 성장 단계

플레이어가 원하는 장소에서 개척 표식을 설치하면 소형 공동 창고와 건설 주민 1명으로 시작한다. 첫 주민은 건축뿐 아니라 초기 부지 정리까지 담당한다.

| 단계 | 규모 | 주요 해금 | 플레이 감각 |
| --- | --- | --- | --- |
| 개척 캠프 | 1~3명 | 창고·주택·벌목·소농장 | 플레이어가 주로 직접 채집 |
| 촌락 | 4~10명 | 채석·광산·대장간·경비 | 기초 자원 자동화 시작 |
| 마을 | 10~20명 | 도로·다리·시장·첫 전초기지 | 플레이어 역할이 탐험 중심으로 이동 |
| 개척 도시 | 20~40명 | 병영·고급 제작·여러 전초기지 | 장거리 물류와 특수 자원 |
| 영지 | 규모형 | 전문화 거점·후반 방어·고급 교역 | 여러 정착지가 하나의 네트워크로 동작 |

## 5. 자원·창고·HUD

자원은 가상 숫자가 아니라 실제 아이템으로 존재한다. 다만 플레이어는 상시 HUD에서 모든 아이템 스택을 보지 않고 마을이 이해하는 소수의 자원 범주만 본다.

- 기본 HUD: 목재 · 석재 · 금속 · 식량 · 인구. 필요 시에만 특수 자원 표시.
- 마을 창고에 들어오고 나가는 실제 아이템을 이벤트 기반으로 서버 장부에 반영한다.
- 매 틱 모든 상자를 스캔하지 않는다.
- 건설 비용은 가능한 한 태그/범주 기반으로 처리해 외부 모드 재료도 호환할 수 있게 한다.
- 플레이어가 직접 창고에서 아이템을 꺼낼 수 있으며 HUD 숫자도 즉시 감소한다.
- 일꾼이 획득한 자원은 실제 창고/거점 보관소에 저장한다.

## 6. 건물 설치와 지형 처리

기능 건물은 플레이어가 블록 하나씩 직접 짓지 않는다. 건물 메뉴에서 청사진을 고르고 실제 월드 위에서 위치와 방향만 정한다.

- 배치 시 완성 건물의 3D 미리보기, 출입구, 범위, 필요 자원, 설치 가능 여부를 표시한다.
- 작은 높이 차이: 건설 주민이 자동 평탄화·기초·옹벽·계단 처리.
- 중간 높이 차이: `지형 공사 포함`으로 표시 후 자동 시공.
- 큰 높이 차이 또는 위험 지형: 설치 거부하고 다른 위치를 선택하게 한다.
- 평탄화를 위해 산 하나를 통째로 삭제하는 식의 과도한 월드 수정은 금지한다.
- 후반에는 선택 영역 평탄화/절토/성토를 보조 기능으로 제공할 수 있다.

## 7. 건설 과정

`부지 정리 → 자재 운반 → 기초 → 골조 → 벽 → 지붕 → 내부 마감 → 완공`

건물은 즉시 생성되지 않으며 건설 주민이 실제 작업한다. 단, 실제 블록 하나마다 지나치게 긴 애니메이션을 강제하지 않고 보기 좋은 단위로 진행한다.

## 8. 주민 시스템

마을 주민은 바닐라 주민 직업/거래를 사실상 사용하지 않고 별도 AI를 사용한다. 기본 직업 배치는 자동이며 플레이어가 일일이 주민을 지정하지 않아도 된다.

- 초기 핵심 직업: 건설가, 벌목꾼, 농부, 광부, 채석공, 대장장이, 경비병.
- 중후반 보조 직업: 운송업자, 상인, 전문 제작자, 병사 정도로 제한한다.
- 로드된 지역에서는 실제 이동·작업·운반 모습을 보여준다.
- 언로드 지역에서는 저빈도 논리 시뮬레이션으로 전환한다.
- 식량은 주민별 세부 메뉴가 아니라 마을 전체 자원으로 취급한다.
- 주민 유입은 주택 여유·식량 안정·발전 조건으로 처리하며 가족/출산 시뮬레이션은 하지 않는다.

## 9. 전초기지와 도로

중앙 마을을 끝없이 넓히지 않고, 지형의 장점을 이용하는 전문 전초기지로 확장한다.

| 지형 | 대표 거점 |
| --- | --- |
| 산악 | 광산 |
| 숲 | 벌목 |
| 평야 | 농업 |
| 해안/강 | 어업·교역 |
| 위험 지역 | 군사 거점 |

- 전초기지는 본진과 연결되기 전에는 독립 재고를 가진다.
- 도로가 연결되면 수레/운송 주민이 생산물을 실제 또는 논리적으로 이동시킨다.
- 도로는 시작점·끝점·필요 시 중간점만 지정한다.
- 경로는 급경사와 건물을 피하고, 작은 계단·교량을 자동으로 포함한다.
- 초기에는 순간이동을 넣지 않아 도로와 거점의 의미를 보존한다.

## 10. 마을을 키우는 가치

마을 성장의 보상은 숫자 증가가 아니라 플레이어가 귀찮은 반복 생존 노동에서 해방되는 것이다.

- 기초 자원 자동 생산과 대량 저장
- 자동 건설과 토목
- 장비 제작·수리·고급 제작 지원
- 경비와 안전한 거점
- 도로와 전초기지
- 희귀 자원·교역·탐험 지원
- 후반 지역과 던전·보스 콘텐츠 접근

## 11. 외부 모드팩 연동 방향

우리 모드는 `마을 성장과 개척`에 집중한다. 바이옴·던전·몬스터·무기·편의 기능은 검증된 다른 모드를 함께 사용한다. 단, 외부 모드는 가능한 한 선택적 호환으로 두고 우리 모드 단독 실행도 유지한다.

| 후보 | 역할 | 우리 시스템과 연결 |

| Terralith | 바이옴/월드 밀도 | 전초기지 후보 지형을 다양화 |

## 12. UI 정본

UI는 감으로 새로 디자인하지 않는다. 각 화면마다 검증된 게임의 정보 구조를 먼저 고정하고, 우리 Minecraft 환경에 맞게 단순화한다.

| 화면 | 레퍼런스 | 가져올 핵심 |
| --- | --- | --- |
| 상시 자원 HUD | Against the Storm | 작은 아이콘 + 숫자, 최소 정보만 상시 노출 |
| 건물 배치 | Manor Lords + MineColonies | 월드가 많이 보이는 상태에서 위치/방향/범위 미리보기 |
| 도로 배치 | Manor Lords | 시작·끝·중간점 중심의 직접 경로 지정 |
| 건설 자재/진행 | MineColonies | 필요 자재와 공정만 간단히 표시 |
| 건물 상태 패널 | Against the Storm | 상태·직원·저장·업그레이드 정도만 |
| 알림 | Against the Storm 계열 | 작은 측면 알림, 중앙 팝업 최소화 |

## 13. UI/그래픽/건축 리소스 규칙

- 상용 게임 UI는 화면 구성·계층·조작 흐름의 레퍼런스로 사용한다. 독점 UI 텍스처를 그대로 프로젝트에 복사하는 것을 기본 방침으로 삼지 않는다.
- 실제 UI 스프라이트는 CC0 등 명확한 공개 라이선스 팩을 우선 사용하고 Minecraft 아이템 아이콘을 적극 재사용한다.
- 건물은 공개 schematic/구조물을 베이스로 가져와 동선·크기·지형 적응 규칙에 맞게 수정할 수 있다.
- 외부 모드 리소스·코드·schematic은 출처와 라이선스를 별도 목록으로 기록한다.
- 개인 플레이가 목적이어도 추후 GitHub에 소스/리소스를 올릴 가능성을 고려해 출처가 불명확한 파일을 정본 자산에 섞지 않는다.

## 14. 초기 건물 범위

초기 전체 목표는 15~20개 계열이지만, 첫 구현부터 전부 만들지 않는다. 동일 계열 건물의 업그레이드로 콘텐츠를 확장한다.

- 핵심: 마을 중심, 창고, 주택, 건설소
- 생산: 벌목소, 농장, 채석장, 광산, 대장간, 작업장
- 물류: 도로, 작은 다리, 전초기지 중심, 수레 정거장
- 방어: 경비초소, 감시탑, 병영
- 교역/후반: 시장, 고급 제작소

## 15. 첫 구현 수직 슬라이스

첫 빌드에서 반드시 완성할 범위:

- 멀티 공동 마을 데이터와 저장/동기화
- 개척 표식과 시작 캠프
- 건설 주민 1명
- 실제 공동 창고 + HUD 자원 장부
- 주택 1종
- 벌목소 1종
- 건물 3D 배치 미리보기
- 작은 지형 자동 정리
- 건설 주민의 자재 운반과 단계별 실제 건설
- 벌목 주민의 실제 생산 루프
- 짧은 테스트 도로 1개와 자동 시공

이 수직 슬라이스가 재미있고 안정적으로 돌아가기 전에는 광산·시장·병영·전초기지 대량 확장으로 넘어가지 않는다.

## 16. 구현 시작 전 최종 금지 목록

- 사용자 제작 건물을 기능 건물로 등록하는 시스템
- 플레이어별 개별 마을
- 국가 정치·세금·복잡한 경제
- 주민 가족/출산 시뮬레이션
- 복잡한 연구 트리
- 수십 종류의 주민 욕구와 행복도
- 건물마다 반복적인 수동 주민 배치
- 도로 블록 수백 개 직접 설치
- 건설 현장으로 자재 직접 배달 강요
- 초반 순간이동망
- UI를 레퍼런스 없이 임의 디자인

## 17. 첫 빌드 합격 기준

- 두 명이 동시에 접속해도 같은 자원·건설 상태를 본다.
- 한 플레이어가 창고에 원목을 넣으면 다른 플레이어 HUD에 즉시 반영된다.
- 플레이어가 주택/벌목소 위치만 정하면 건설 주민이 필요한 지형과 자재를 처리한다.
- 작은 언덕에서도 건물이 정상적으로 완공되며 월드가 과도하게 파괴되지 않는다.
- 벌목 주민이 실제로 작업하고 생산물이 실제 창고에 들어간다.
- 건설/생산을 위해 메뉴를 여러 단계 순회할 필요가 없다.
- 플레이어가 30분 이상 마을 메뉴만 보고 있지 않고 Minecraft 탐험·채집·전투를 계속한다.
- UI가 Minecraft 기본 HUD와 충돌하지 않고, 레퍼런스 화면의 정보 계층을 유지한다.
- 새 기능 하나를 추가할 때 기존 단순 조작 원칙이 깨지지 않는다.

## 18. 정본 변경 규칙

향후 아이디어가 생기더라도 `재밌어 보인다`는 이유만으로 바로 추가하지 않는다. 다음 질문 중 하나라도 실패하면 기본 기능으로 넣지 않는다.

- 마을을 키우는 가치가 실제로 증가하는가?
- 플레이어가 새 메뉴나 반복 관리를 배워야 하는가?
- 기존 시스템으로 같은 재미를 낼 수 없는가?
- 멀티에서 함께 하는 재미를 해치지 않는가?
- Minecraft 서바이벌을 방해하지 않는가?
- 외부 모드와 충돌하거나 특정 모드에 과도하게 종속되지 않는가?

이 v0.2를 구현 정본으로 사용한다.
