# 00 — PRODUCTION PRINCIPLES

## 목적
기획과 구현 사이에서 임의 결정이 발생하지 않게 하고, 개발 속도 때문에 품질 게이트가 사라지는 것을 막는다.

## 우선순위
1. 정본 일치
2. 플레이 가능한 코어
3. 재현 가능한 테스트
4. 게임성 검증
5. 시각 품질
6. 콘텐츠 확장

## 설계 변경 등급
- **CANON**: 파티 크기, 별 체계, 핵심 전투 루프처럼 제품 정체성을 바꿈. `CANON.md` 수정 필요.
- **SYSTEM**: 공식, 상태 지속시간, 데이터 계약. 관련 문서+테스트 수정 필요.
- **TUNING**: 수치만 조정. 데이터와 밸런스 로그 수정.
- **PRESENTATION**: 정보 구조/미술/연출. UI/Asset Gate 통과 필요.

## 구현 전 체크
- 입력/출력/소유권이 명확한가?
- 서버/클라이언트 책임이 정해졌는가?
- 실패 케이스가 정의됐는가?
- 저장이 필요한가?
- 데이터 reload 시 참조 무결성을 검사하는가?
- 테스트가 가능한가?

## 기능 완료 체크
- Happy path와 invalid path 테스트.
- 월드 이탈, 사망, disconnect, dimension change, reload cleanup 고려.
- 전투가 끝난 후 바닐라 AI/충돌/무적/카메라 상태가 복구됨.
- 저장 데이터 version을 가짐.
- debug command로 재현 가능.

## 시각 기능 완료 체크
공용 `QUALITY_STANDARD.md`를 만족하지 않으면 기능적으로 작동해도 production 완료가 아니다.
