# 01 — GAME LOOP & WORLD

## 1. 메인 루프
`Hub 준비 → 월드 탐험/생활 → Encounter 선택 → 턴제 전투 → 집중 보상 → 캐릭터/장비/생활 성장 → 새 지역/던전/보스 개방`

루프의 모든 단계는 다음 단계에 실제 자원을 공급해야 한다. 의미 없는 별도 미니게임을 만들지 않는다.

## 2. 월드 구조
미술 스타일이 결정되기 전에는 기능 ID를 사용한다.
- `HUB_01`: 파티 편성, 성장, 제작, 상점, 퀘스트.
- `REGION_01+`: 탐험/채집/일반 Encounter.
- `DUNGEON_*`: 제한된 동선, 특별 자원, 엘리트/보스.
- `STORY_GATE_*`: 진행 조건.
- `FAST_TRAVEL_*`: 발견 후 활성화.

월드는 고정 저작형을 기본으로 하며 플레이어가 어디서 무엇을 얻는지 학습할 수 있어야 한다.

## 3. Encounter 표현
- 전투 가능 대상은 월드에서 사전에 인지 가능해야 한다.
- 접근/상호작용 시 최소한 난이도, 적 계열 힌트, 보상 카테고리, 반복 가능 여부를 알 수 있다.
- 스토리/매복 조우는 예외지만 의도적으로 사용한다.
- 단순 자연 스폰 바닐라 몹의 모든 공격을 전투 시작 신호로 사용하지 않는다.

## 4. 생활 활동의 전투 연결
| 활동 | 주요 산출 | 전투 연결 |
|---|---|---|
| 채광 | 광물/희귀 소재 | 장비 제작·강화 |
| 농사 | 식재료 | 전투 전 음식/버프/회복 준비 |
| 낚시 | 식재료/특수 소재/수집품 | 소모품·특수 제작 |
| 제작 | 장비/지원 아이템 | 빌드 다양화 |
| 탐험 | 상자/Encounter/퀘스트/이동지점 | 성장 경로 개방 |

활동이 다른 활동보다 압도적으로 효율적이면 루프가 붕괴하므로 시간당 기대가치를 측정한다.

## 5. 전투장
M0~M4에서는 별도 debug arena를 허용한다. production 월드의 전투 공간 연출은 Asset Gate 이후 확정한다. 전투 참가 Entity는 전투 중 외부 몹/환경 피해와 섞이지 않게 battle ownership을 가진다.

## 6. 보상 원칙
턴제 전투가 바닐라 전투보다 길기 때문에 동일 몹 1체 기준 드롭을 그대로 적용하지 않는다. 보상은 Encounter 단위로 설계한다.
- 일반 Encounter 목표 체감 시간: 초기 튜닝 30~75초.
- 엘리트: 60~150초.
- 보스: 별도 기믹에 따라 더 길 수 있음.
- 동일 플레이 시간에서 단순 바닐라 사냥보다 의미 있는 성장 보상을 제공해야 한다.
정확한 배율은 플레이테스트로 조정하고 `12_BALANCE_PLAYTEST_PROTOCOL.md`에서 측정한다.

## 7. 월드 상태 저장
- 발견한 이동지점.
- 스토리/퀘스트/던전 최초 클리어.
- 일회성 상자/보스.
- 반복 Encounter 쿨다운/리셋 정책.
개인 진행과 월드 공용 진행을 데이터 구조에서 분리한다.
