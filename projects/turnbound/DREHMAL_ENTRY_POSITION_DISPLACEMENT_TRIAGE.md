## 현상과 확인된 사실

공식 맵 복사본의 **CI 전용 실험 좌표** `(26458.5,223,-285.5)`에 가상 프로토콜 플레이어를 이동시키면, 일부 서버 틱 뒤 정확히 `(26520.5,177,-84.5)`로 이동했다. X/Z 수평 이동은 **210.345블록**, 수직 차이는 **-46**. 이 지점은 가상 플레이어가 월드에 처음 접속한 위치 `(26519.5,177,-82.5)`로부터 수평 약 **2.236블록** 떨어진 곳이다. 1.20.1 서버 측 동기화/맵 트리거/충돌/리스폰 중 무엇이 실제 원인인지는 **아직 확정되지 않았다**. 최초 이동은 현상 발생의 확인용이며 **TURNBOUND START 또는 체크포인트로 승인된 좌표가 아니다**.

### 원인 추정의 경계

- **배제되는 단정:** 원작 명령 블록을 비활성화하면 이 현상이 해결된다는 주장. 실제로 OFF에서도 발생했다.
- **배제되는 단정:** 테스트 봇이 일반 위치 패킷을 보내지 않아서 *그 이유만으로* 모든 맵에서 되돌아간다는 주장. 평지 월드에서는 두 방식 모두 유지됐고, 공식 맵에서는 두 방식 모두 돌아갔다.
- **그럴듯하지만 미확인:** 시험용 위치에서 플레이어 발/머리 블록 충돌로 서버가 보정했는지. 기존 시험은 해당 좌표의 **발 아래 한 블록이 `minecraft:air`**라는 점만 확인했을 뿐, 해당 발·머리 영역 및 충돌 형태를 직접 검사하지 않았다. RCON으로 강제 이동한 것이 실제 플레이어의 안전한 착륙을 보장하지 않는다.
- **그럴듯하지만 미확인:** 원작 업적/위치/차원 관련 보상 콜백이나 command block 이외의 world tick 트리거. 기존 7단계는 자동 `load/tick` 3개, 시작 체인 57개, Terminus 함수 명령 62개, 지정된 보상 등을 차단했지만 **다른 업적·서버 동작은 여전히 남는다**.
- **그럴듯하지만 미확인:** 원작 spawn/저장 좌표·vanilla/server 위치 동기화 시점의 오류. 이동 이후 좌표가 최초 접속 위치와 가까워 이 가설과 일치하지만 직접 원인 증거는 아직 없다.
- 새 [#42798205522](https://github.com/q93503128-a11y/minecraft-java-mod-builds/actions/runs/42798205522)의 CI 전용 진척도 파일 diff에는 1,169개의 새로운 `done=true` 항목(그중 1,159개는 vanilla recipe 및 10개 비제작법 root)이 기록되었다. 그러나 **첫 로그인 이후 파일 최초 생성/저장 타이밍을 독립 판별하지 않았기 때문에 실제 좌표 이동으로 그 순간 1,169건의 업적이 새로 달성됐다고 결론 내릴 수 없다.** 따라서 어떤 root 업적이 텔레포트 원인인지는 미확정이다.

## 안전 범위 / 검증 상태

- 기존 7단계 가역 복사본 SHA 및 시작 명령 블록 57개 공란 상태를 각 시험 시작과 종료에 검사했다.
- 소스 원본 지도는 수정하지 않았고 별도 사본만 서버에 올렸다. CI의 테스트 데이터 외에는 TURNBOUND에 원작 함수·게임 아이템·모델/텍스처를 이식하지 않았다.
- **VERIFIED:** 공식 지도 원본 해시 보존, 독립 복사본 서버 부팅/두 프로토콜 플레이어 접속/위치 시계열, command block ON/OFF 비교, 일반 위치 패킷 대조, 별도 flat world 대조.
- **NOT VERIFIED:** 위치 이동의 구체적 원인, 실제 맵 안전 START·체크포인트, 문/포탈/레버/Terminus 실제 사용, 원작 전체 스토리·전투·보상 분리, 그래픽 클라이언트 화면, 실제 4인 게임 플레이.
- CI 비교는 **원인 추론용 가설 분리**이며 분리 완료·플레이 승인 증거가 아니다.

## 우선 후속 작업 (맵 분리만)

1. 원본 SHA로 검사한 임시 복사본에서 CI 목표 좌표의 **발 아래/발·머리/상부 블록과 충돌 공간**, 안전한 지형 높이 및 목표 지점 주변 세부 월드 경계 비교. 같은 월드의 다른 안전한 테스트 지점도 고정해 비교하면 좌표 특이성을 구분할 수 있다. 여기서 나온 위치를 실제 START로 자동 승인하지 않는다.
2. 같은 서버에서 **이동 직전·직후 death/respawn, 게임모드, teleport correction packet, 원작 advancement 추가 데이터와 실제 실행 경로**를 독립 관측한다. 모든 권한은 서버에서; 업적 파일에 표시된 대규모 recipe 목록을 곧바로 원작 이벤트로 오인하지 않는다.
3. 현상이 서버 보정인지 원작 업적/스크립트인지 특정된 이후에만 원작 불필요 기능의 **단일 가역 분리**를 설계한다. 문·포탈·장치 유지 기능을 추측으로 삭제하지 않는다.
4. Av'Sal / Foundry / Godmachine / Terminus의 실제 시설 위치·버튼/레버 작동 검증, 남은 original callback 172개 등 선별, 4인/실제 Minecraft 클라이언트 체크를 완료하기 전에는 지도 분리 완료 선언 금지.

**이번 단계 변경:** 프로덕션 Fabric 소스/정식 JAR 변경 **0건**. 추가된 코드는 `tools/` 아래 테스트·감사 코드 및 GitHub Actions 전용 워크플로이며, 정식 게임용 좌표/경로 설정은 변경하지 않았다.
