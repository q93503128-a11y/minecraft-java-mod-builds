# Drehmal 원작 게임모드 명령 29개 — 복사본 가역 분리

## 대상
- 공식 v2.2.2f 명령 블록 분석의 직접 `gamemode` 명령 **29개**. 오버월드 26개, `minecraft:space` 차원 3개, 지역 파일 7개.
- 기존 Terminus 함수 호출 블록 62개와는 다른 명령이다. TURNBOUND 플레이어 상태는 서버가 통제해야 하며, 원작 명령 블록이 임의로 생존/모험/관전 등 모드를 바꾸지 않도록 오프라인 복사본에서 이 경로를 분리한다.
- 사용자가 승인한 원작 게임 기능 제거 범위에 해당하며 **Drehmal 코드를 TURNBOUND로 재사용하지 않는다.**

## 보존/검증 경계
- 원본 월드와 활성 TURNBOUND 월드는 절대로 수정하지 않는다.
- 실제 원본 명령 블록의 위치·NBT 명령 SHA-256·차원·지역 및 공식 분석 전체 보고서 SHA-256을 검증한다.
- **명령 블록은 삭제하지 않으며** 그 블록의 `Command` 문자열만 비운다. 이 작업으로 게임모드 변경만 차단하는 것이 목표지만, 조건부 명령 블록 체인의 성공/실패 전파가 달라질 가능성은 *실제 월드에서 아직 검증되지 않았음*.
- 모든 7개 지역 원본 바이트를 사본 안에 백업하고, 수정 지역 해시를 기록한 후 독립 검증, 복원 시 원본 파일 SHA 정확히 확인한다.
- 기존 `prepare_drehmal_isolated_copy.py`의 `--include-gamemode` 옵션으로 기존 **4개 분리 경계에 다섯 번째 분리 경계**를 추가한다. 새 실행 순서는 무기 업적 → 자동 진입점 → Terminus 함수 블록 → 직접 게임모드 블록 → 저장 예약 이벤트. 복원 순서는 역순.
- 이미 검증된 기존 4종 모드는 기본값으로 유지하여 기존 실행 절차를 깨지 않는다.
- 사본을 먼저 `inspect`한 다음 `prepare`, `verify`, `restore`한다. 공식 월드 및 가공된 월드 자체는 GitHub/아티팩트에 업로드하지 않는다.

## 남은 작업
원작 문·퍼즐·포탈의 명령 블록 체인 연결, 남은 업적 보상과 직접 명령, 점수판/저장 데이터의 런타임 참조, 실제 1.20.1/Fabric 클라이언트·서버·멀티플레이 검증이 남아 있다. **완료된 맵 분리 및 플레이 가능한 설치물은 아니다.**
