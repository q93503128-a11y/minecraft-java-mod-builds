# TURNBOUND — 필드 적 서버 권한 탐지·접촉 전투 경계

## 현행 기술 범위 (2026-11-10)

브랜치: `turnbound-content-rebuild`, 프로젝트: `projects/turnbound/`. Minecraft Java 1.20.1, Fabric 0.16.14, Java 17.

**이미 승인된 플레이 규칙:** 필드 적이 플레이어를 감지한 뒤 ! 경고 → 짧은 반응 → 추격 → 물리 접촉으로 **발견한 실제 월드 지형에서** 4인 파티 턴제 전투를 시작한다. 단순히 적 근처에 지나간다고 즉시 전투 화면을 띄우지 않는다. 적을 피하거나 추격을 떼는 선택권을 제공한다. 평화로운 생물을 고의 공격하면 전투로 전환하는 별도 경로는 승인된 장기 범위이나 이 변경에 포함되지 않는다.

## 이번에 구현된 부분

- `src/fabric/java/.../combat/FieldEncounterClaims.java`: 서버만 소유하는 경고 → 추격 → 접촉 → 선점 상태기계, 거리/시야/대상 변화 검증, 접촉 대상 원자적 선점, 재접촉 방지 상태, 등록 개수 상한과 해제. Loader 독립 클래스와 JUnit 회귀 검사. **감지·접촉 범위, 추격 속도, 경고 지속, 해제시간은 실제 몬스터 카탈로그에서 제공하도록 설계했으며 게임 수치를 임의로 확정하지 않았다.**
- `src/fabric/java/.../TurnboundFieldEncounterService.java`: **다른 시스템이 서버 측에서 명시적으로 등록한 살아 있는 `MobEntity`만** 추적한다. 등록되지 않은 바닐라·Drehmal 몹을 스캔/전투로 자동 변환하지 않는다. 서버가 대상 세계, 생존, 관전/크리에이티브, 기존 전투 참가 여부, 시야/거리와 단일 접촉을 검증한다.
- 서버 승인 적의 경고 시 짧은 기본 경고 파티클을 호출하고, 추격 상태에서 해당 적의 navigation을 유도한다. **모델/GeckoLib 애니메이션, 전용 ! VFX/사운드, AI 경로·시각 연출은 미완**으로 게임에서 최종 디자인을 검증하기 전까지 본 기능을 완성품으로 분류하지 않는다.
- `TrustedBattleFactory`가 신뢰된 몬스터/파티 작성 카탈로그로부터 `BattleState` 및 `UUID → 아군 전투 참가자 소유권`을 제공할 때에만 기존 `TurnboundBattleBridge.open`을 호출한다. **클라이언트 패킷으로 적·스탯·보상을 직접 만들 수 없다.**
- `TurnboundBattleBridge.inBattle`로 이미 전투 중인 플레이어를 다시 선점하지 않고, `close` 시 서버 소유 적의 선점과 추격을 해제한다. 전투 결과·체크포인트 패배 복귀는 기존 서버 정본과 공용 사용한다. 이 변경은 골드/보석·경험치/드롭·보스를 임의 구현하지 않는다.

## 여전히 완료되지 않은 게임성

1. TURNBOUND 월드의 실제 몬스터 목록/스탯·시각 자산과 적의 스폰 위치/밀도는 아직 승인되지 않았다. **현재 정식 모드가 월드에 적을 자체 생성/등록하여 실제 플레이 가능한 필드 전투를 시작하는 것은 아니다.**
2. 고의로 공격한 평화로운 동물의 전투 전환, 지형이 좁은 장소의 전투 화면·카메라, 전투 참가 모델/기본 공격 애니메이션, 승리 보상, 필드 전투 뒤 다시 적을 만나는 사용자 경험은 별도 구현 필요.
3. Drehmal 원작 구조·시설/정품 리소스는 그대로 보호. 원작 맵의 원본 함수나 데이터팩을 게임 로직에 복사하지 않았고, 공식 제작자 자산을 저장소/아티팩트에 업로드하지 않았다.
4. **실제 플레이테스트와 4인 멀티 테스트 미실시**. 합의되지 않은 전투 알림 UI·스폰 타이밍·재화 획득 수치는 확정하지 않는다.
